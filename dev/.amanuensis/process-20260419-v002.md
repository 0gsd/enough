# Process Documentation — enough v0.0.2

## Session: 2026-04-19 (starts ~17:30 local, continues from 20260417 session)

### Task
Three features requested for v0.0.2:

1. Inline editor in the preview pane — click edit, textarea, save/cancel.
2. Skill on/off toggles that don't require moving folders in/out of
   `.rness/skills/`.
3. A Requests/Sub-Requests/Tasks tracking system seeded by a default
   policy in `.rness/policies/requests.md`.

User framed all three as "paradigms being enforced" but noted #1 and #2
are also infrastructure. I agreed — and added that #3 is half infra
(folders, sidebar, mark-done endpoint) and half paradigm (the policy
text the agent reads on every turn).

### Methodology
Same pattern as v0.01: phase-by-phase build with a push at each phase,
integration test before declaring a phase done, amanuensis checkpoint
at session end.

### Design decisions up front (before writing code)
Two questions asked of user and answered:

- Date format: changed from user's original `MM_DD_YYYY-HH-MM` to
  `YYYY-MM-DD_HH-MM` for filename-sortability. (DR-023)
- Mark-done action: UI button only, not an agent shell-tool call.
  Preserves "the move IS the confirmation act" semantics. (DR-024)

### Idle Thoughts (to test in practice, not build yet)
- Agents may forget to update an active request file across turns.
  Lightweight nudge options: (a) an ambient indicator in the chat header
  "active request: X"; (b) inject the current request file's content into
  the system prompt automatically when exactly one active request exists.
  Both speculative; let's see if it's actually a problem.
- Edit-mode has no conflict detection. If the agent writes while the user
  is in edit mode, the user's save will clobber the agent's write. Probably
  rare in practice; (b) above would make it rarer still.
- `.rness/skills/.disabled` is invisible in the file tree (dotfile
  filter). Users may not realize the UI writes state there unless they read
  docs. Fine for v0.02, flag for later.
