こんにちは、enough を作った Graham です。このドキュメントは — いま読んでいるこの部分をのぞいて、という意味ですが — 主にエージェントたちが書き、手入れをしています。私もときどき、まず間違いなく Graham らしさをひとつまみ振りかけていくでしょうが、面白いものを書きたいという自分の欲に、行き届いたドキュメントの邪魔をさせない、というのが趣旨です。

# enough ヘルプセンター

> enough でできることのすべてを、ひとつの場所に。enough **0.3.5** に対して書かれていて、composure ラウンドを含みます — いまやすべてのプロジェクトの床になったキャンバスで、会話はその隣のパネルに移りました（セクション 4 と 5）。**リードバイザー**、これはロールの新しい呼び名で、Ed という名の主任リードバイザーが率います（セクション 16）。**議事会**は、何人かのリードバイザーがひとつのことについて順番に、書きながら考えるのを、あなたが見ているところです（セクション 17）。そして新しいスキルが 2 つ、`readvisory` と `scaffold`（セクション 18）。このラウンドより前に作ったプロジェクトは、次に開いたときに `rness/roles/` フォルダが `rness/readvisors/` に改名され、オンオフの設定はそのまま引き継がれます（セクション 8）。以前のラウンドからのものも、ここにあります：ホーム画面（これまでに始めたすべてのプロジェクトをひとつの一覧に、入り口と出口つきで — セクション 2）、convert ラウンド（PDF、Word ドキュメント、電子書籍、スライド、ワークブックが、編集できる markdown のツインとして開き、書き出しと同期と画像ビューアがつく — セクション 7）、skills ラウンド（analyzer の新しい監査モード、`anything-finder` スキル、そして enough が同梱していないスキルを、通す前にかならず読む初回監査）、2026 年 8 月ラウンド（実現できるかを確かめながら入れられる 7 つのローカルモデルと、**enough.app** — 署名・公証済みのデスクトップアプリケーション）、2026 年 7 月のインターフェイスラウンド（モードスタック、フォルダごとのヘルプバブル、girraph→merirmaid のミラー）、そして 0.3.0 の設定ラウンド（プロジェクトごとの ui とテキストの拡大率、そして 6 言語で読めるインターフェイスとヘルプ — セクション 10）。このドキュメントと目の前のアプリが食い違っていたら、正しいのはアプリのほうで、このドキュメントにバグがあります — 修正のご連絡は [enough.support](https://enough.support) へどうぞ。

enough は、あなた自身のマシンで動く、個人のための言語システムです。フォルダをひとつ指し示し、話しかければ、計画し、書き、見直し、調べ、翻訳するのを手伝ってくれます。モデルは既定でローカル。あなたのファイルはあなたのものです。そして、enough がすることのほとんどは、あなたが開いて読んで変えられる、平文の markdown ファイルで定義されています。

読みながら、ひとつだけ頭の隅に置いておいてください。**このマニュアルに載っている組み込みの機能は、enough にできることのほんの一部です。** 箱に入っているパラダイム、リードバイザー、スキルは出発点の一式 — 3 つのカスタマイズの仕組みの、動く実例であって、その限界ではありません。行き着く先は、あなたが自分のものを書くこと、あるいは主任リードバイザーと一緒に書くことです：エッセイの計画の立て方に合わせたパラダイム、いちばん手厳しい読者のように反論してくるリードバイザー、あなたの文体を写し取ったスキル。その方法はセクション 3 にあります。このドキュメントでいちばん大事なセクションであり、これから何度もそこへ送り返すことになります。

## 1. インストール、ショートカット、このドキュメント

### 1.1 必要なもの

- Apple Silicon の Mac。（enough は macOS で作られ、テストされています。Linux 対応は予定にあり、Windows も可能です。）
- 少なくともモデル 1 つ分のディスク容量 — いちばん小さいもので約 5 GB です。
- アカウントも、API キーも、サブスクリプションも不要。あとからクラウドのモデル枠（セクション 14.2）を選ばないかぎり、すべてが手元で動きます。

### 1.2 インストール

扉は 2 つ、着く家は同じです。

**アプリ — 短い道。** リリースページから `enough` の DMG をダウンロードして開き、**enough** を Applications にドラッグして起動します。macOS は「インターネットから入手したアプリ」だと言ってきますが — 署名も公証も済んでいるので、これは戦って突破する警告ではなく、**開く**ボタンのある人当たりのよい青いダイアログが一度出るだけです。あとは初回ガイドが引き受けます：自分の Python 環境を作り、モデルの一覧を、*このマシン*に何が入るかの正直な判定つきで見せ（セクション 14.1）、任意のエクストラのうちすでに持っているものを並べ、作業したいフォルダを選ぶホーム画面へ渡してくれます（セクション 2）。待ち時間のほとんどはモデルのダウンロードです。Terminal も、Homebrew も、git も要りません。

アプリは自前の推論エンジンと Python を抱えています。任意のエクストラ — 音声入力、ウェブページの取得、文法チェック、翻訳 — はいまも別のプログラムで、ガイドの Extras ページが、それぞれ何なのか、無いと何が使えなくなるのか、どう手に入れるのかを説明します。どれも必須ではなく、勝手に入るものもありません。ひとつだけ、別プログラムではないエクストラがあります：**PDF の読み込み**は、enough の中からいつでもインストールできます（セクション 7.8）。

**ターミナル — 長い道、そのぶん手綱が多い。** リポジトリをクローンして、クローンの中の `install-enough.command` をダブルクリックします：

```bash
git clone https://github.com/0gsd/enough.git ~/Downloads/enough-seed
open ~/Downloads/enough-seed
```

初めてダブルクリックしたとき、macOS の Gatekeeper が「開発元が未確認」と渋ることがあります — その用心は `.command` ファイルに向けられたもので、アプリのようには署名されていないからです。ファイルを右クリックして**開く**を一度選べば、macOS はそれ以降、信頼を覚えています。

ランチャーは `bootstrap.sh` を走らせます。10 段階の対話式インストーラで、各段階の前に何をするかを説明して尋ねてきます。Ctrl-C はいつ押しても安全です。やり直しも安全 — 先に状態を確かめて、途中から続けます。段階はおおよそこうです：

1. お使いのプラットフォームを確認。
2. Homebrew があるか確かめ、無ければ入れるのを手伝う。
3. enough が頼っている補助プログラムを入れる：`llama.cpp`（ローカルモデルの推論）、`whisper-cpp`（音声入力）、`tor`（匿名でのウェブ取得）、`harper`（ローカルの文法チェック。analyzer スキルが使います）。ドキュメントの変換器 — 取得したウェブページや Word ファイルを markdown にする pandoc と、PDF を書き出す typst — はもうこの一覧にありません：どのプラットフォームでも、段階 5 で入る enough 自身の Python 環境に同梱されています。Homebrew の pandoc をお持ちなら、enough はそちらを使います。
4. 全体のインストール先 `~/enough/` を用意。
5. Python 環境を（`uv` で）準備。
6. モデルの重みをダウンロード。対応しているモデルはひとつずつ提示され、それぞれサイズと、お使いのマシンのメモリと空き容量に照らした実現可能性の判定がつきます — ✓ は余裕、~ はぎりぎり、✗ はよそを当たったほうがよい、という意味です。いくつ選んでも構いません。すべてはセクション 14.1 で説明しますし、見送ったものはあとからワンクリックで入れられます。
7. 音声入力（whisper）のモデルを配置。
8. オフライン翻訳のモデルを配置。`translator` スキルが使います。
9. `enough` コマンドを PATH に置く。
10. 完了。次にすることの一覧が印字されます。

あとで更新するには：`~/enough/` の `update-enough.command` を実行するか、チャット欄に `/update-enough` と打ちます。新しい defaults が出たときは enough がインターフェイスで知らせ、そのコマンドを指し示すので、こちらから見に行く必要はありません。モデルの重みだけを更新するには `update-weights.command` を使います。

### 1.3 起動

**アプリから：** ダブルクリックすると、**ホーム画面**に着きます — これまでに enough プロジェクトにしたフォルダがすべてひとつの一覧になり、もう 1 つ足すための場所もあります。ひとつ選べば開きます。それがセクション 2 で、このセクションより先に読む価値があります。

**enough** メニューには設定がひとつだけ、**Reopen Last Project on Launch**（起動時に前のプロジェクトを開く）があります。既定はオフ。オンにすると、アプリはホームを飛ばして、前にいた場所へまっすぐ戻ります。ウィンドウはひとつ、プロジェクトも一度にひとつ — そして **File → Close Project**（⌘W）を使えば、終了せずにいつでもホームへ降りて、別の場所へ移れます（セクション 2.5）。

素のフォルダピッカーもまだ中にありますが、おそらく出会うことはありません：ホーム画面そのものが立ち上がれないとき — 中途半端な更新、壊れたインストール — のための逃げ道で、悪い日にも仕事へ入る道が残るようにしてあります。

**ターミナルから：** enough はプロジェクトフォルダごとに動きます。好きなフォルダでターミナルを開き、こう打ちます：

```bash
enough
```

そして `http://127.0.0.1:3456` を開きます（enough が代わりに開いてくれます）。フォルダが違えば、プロジェクトも、リードバイザーの記憶も別です。ひとつだけ起動できないフォルダが `~/enough/` そのもので、CLI はこれを断ります。そこはインストール先であって、プロジェクトではないからです。

ホーム画面も、どこからでも呼べます：

```bash
enough --home
```

同じ画面、同じ一覧が、アプリのウィンドウではなくブラウザに出ます。そこからプロジェクトを開けば、起動に使ったターミナルがそのプロジェクトのターミナルになります。

コマンドを打ちたくないなら、`~/enough/shortcuts/` にランチャーが 2 つ入っています：

- **`enough-on.command`** — プロジェクトフォルダにコピーして（`cp ~/enough/shortcuts/enough-on.command ~/some-project/`）、Finder でダブルクリックします。そのフォルダで enough が動く Terminal ウィンドウが開き、⌘W か Ctrl-C で止まります。
- **`setup-quick-action.sh`** — 一度だけ実行すると（`bash ~/enough/shortcuts/setup-quick-action.sh`）、Finder のクイックアクションが手に入ります：どのフォルダでも右クリック → クイックアクション → **Launch in enough**。メニュー項目が出てこないときは、システム設定 → キーボード → キーボードショートカット → サービス → ファイルとフォルダ で有効にしてください。

### 1.4 このドキュメントと、その他のドキュメント

このファイルは長文のマニュアルです。ほかにこういうものもあります：

- **手元のヘルプ** — インターフェイスのあちこちにある `(?)` バブル。それぞれが、くっついている当のものを説明します：*what*、*how*、*ideas* の一覧つき。セクション 10.6 をどうぞ。
- **チートシート** — キーボードショートカットと markdown の記法が、UI ウィンドウからワンクリックで。セクション 10.5 をどうぞ。
- **[enough.support](https://enough.support)** — コミュニティのフォーラム：インストールの相談、進め方の見せ合い、そしてこのマニュアルがずっと勧めているカスタマイズを、喜んで一緒に作ってくれる人たち。

そしてそのすべて — このマニュアル、バブル、まわりのインターフェイス — が 6 言語で読めます：英語、フランス語、スペイン語、ドイツ語、中国語、日本語。ドロップダウンと細かい話はセクション 10.4 に。

## 2. ホーム画面

プロジェクトに入る前にいるのが**ホーム**です：これまでに enough プロジェクトにしたフォルダをすべて並べた 1 枚の画面と、もう 1 つ足すためのタイル。このアプリケーションでいちばん静かな画面になるよう、わざとそうしてあります。チャットも、サイドバーも、モデルも、リードバイザーもありません — まだ何も動いておらず、何も考えられていません。あるのはあなたのプロジェクトと、テーマとこのマニュアルのための、上部バーの ⚙ UI ボタンだけです。

ここに来るのは：

- 初回起動のとき、初回ガイドが終わった直後。
- そのあとの起動のたび。ただし **Reopen Last Project on Launch** がオンなら別です（セクション 1.3）。
- プロジェクトを閉じたとき（セクション 2.5）。
- ターミナルから、いつでも、`enough --home` で。

ホームを*見ない*ただひとつの方法が、あのトグルです。**Reopen Last Project on Launch** をオンにすると、enough は前にいたプロジェクトへまっすぐ戻り、ホームは間に入りません。オフにすれば、起動はいつもホームから始まります。設定はそれだけ。ほかに調整するものはありません。

### 2.1 グリッド、リスト、そして ¶ W C

表示は 2 つ。画面右上のボタン 2 つで切り替わり、enough はどちらが好みかを覚えています。

**アイコン**は眺めるための表示です：フォルダの絵、プロジェクトの名前、その下に平たい日本語の 1 行 — *3 日前に編集*、1 週間より古ければ実際の日付。

**リスト**は見比べるための表示です。列は 6 つ：

| 列 | 何を表すか |
|---|---|
| 名前 | プロジェクトの表示名（プロジェクトのタイトルバーで設定したもの、なければフォルダ名） |
| ¶ | 段落数 |
| W | 語数 |
| C | 文字数 |
| 最終更新 | それらの数に含まれるファイルへの、いちばん新しい変更 |
| 作成 | そのフォルダが enough プロジェクトになった日 |

真ん中の 3 列は、ドキュメントを開いているあいだ enough が上部バーに出しているのと同じ 3 つの数字を、プロジェクト全体で足し上げたものです — ¶ は段落（空行で区切られたブロック）、W は語、C は空白と改行を含む文字。*どの*ファイルが数えられるかの決まりは、この数字に意味を持たせている一文なので、書いておく値打ちがあります：プロジェクト自身のファイルツリーに出てくる markdown ファイルはすべて、**変換されたドキュメントのツインも含めて**数えます（ここで編集している `.docx` は、あなたの書いたものです）。そして `rness/` の中身は**数えません**（リードバイザーの足場は、あなたの本ではありません）。ですから W 列の数字は、まず間違いなく、あなたがどれだけ書いたかです。

列見出しをクリックすればその列で並べ替え、同じものをもう一度クリックすれば逆順になります。報告することが何もないプロジェクト — 一度も開かれず、数えられてもいないもの — は、どちらの向きでも最下段に沈みます。いちばん古いふりをするより、そのほうが正直だからです。既定の並びは、最近編集した順です。

いまフォルダがそこに無いプロジェクト — 外付けドライブを抜いた、Finder で移動した — は灰色で描かれ、覚えているパスがツールチップに出ます。一覧から**落とされることはなく**、最後に見たときの数字もそのまま保ちます。引き出しの中のドライブにあるプロジェクトは、失われたプロジェクトではありません。

### 2.2 プロジェクトをクリックする：地図

シングルクリックではプロジェクトは開きません。かわりに**地図**を描きます：そのフォルダの目に見える中身を、読み取り専用の merirmaid 図（セクション 20）にしたもので、上の小さな情報ノードにパス、ファイル数、¶ と W の合計、作成日・最終起動日・最終編集日が入ります。cacheawl がキャッシュボックスに描くのと同じ種類の絵を（セクション 12.1）、プロジェクトに向けたものです。

この地図は、それらしい名前のフォルダが 4 つあって、章が入っているのはどれかを知りたい、あの瞬間のためのものです。見て、それから決める。

決まったら、ツールバーの**プロジェクトを開く**ボタンで開きます。Esc か右上のリボンでグリッドに戻ります。そして、どれを開きたいかもう分かっているなら、タイルや行を**ダブルクリック**すれば寄り道なしで開きます。

開く様子はどちらでも同じです：enough がホーム画面を畳んでプロジェクトを立ち上げるあいだ、ローダーが 1、2 秒あらわれ、そのあとは、最初からそのフォルダで起動したのと変わらない discussion 表示（セクション 4）にいます。

### 2.3 フォルダを足す

グリッドのいちばん最後のタイル — プラスの付いたもの — が、フォルダをプロジェクトにする方法です。

クリックすると macOS 自身のフォルダ選択画面が開きます。メモでも下書きでもドキュメントでも、好きなフォルダを選んでください。enough はそこに `rness/` を足し（セクション 8）、ホーム画面に登録して、開きます。ダイアログが出ているあいだ、タイルは*フォルダ選択を待っています…*と言っているので、じっくり探して構いません。

断られるフォルダが 2 種類あります。enough は、ぼんやり失敗するかわりに、どちらでなぜかを伝えます：

- **`~/enough` そのもの、およびその中身。** そこはインストール先であって、プロジェクトではありません。（`enough` コマンドも、同じ理由で同じフォルダを断ります。）
- **クラウド同期フォルダの中身すべて** — Google Drive、Dropbox、iCloud Drive。これは神経質さではありません。プロジェクトの `rness/` は、全体の defaults へ戻るシンボリックリンクで組まれていて、同期クライアントはシンボリックリンクを日常的に書き換えたり壊したりします。結果として、全体の設定を静かに追わなくなったプロジェクトが、あなたが気づかないほうのマシンにできあがります。プロジェクトはローカルディスクに置いて、仕上がったものを同期してください。

すでにホーム画面にあるフォルダはエラーではありません — enough はただ開きます。

フォルダ選択画面がそもそも出せないとき（Mac でないマシン、拒否するサンドボックス）は、モーダルがパスを打ち込む素のテキスト欄を出し、その上に理由を書きます。そこから先はまったく同じです。

### 2.4 プロジェクトを隠す

ホームはすべてを、いつまでも並べます。実験を 1 年も続ければ、それは長くなります。というわけで：**タイルや行を option+クリックすると隠せます。**

隠すというのは enough 自身の一覧に付けたメモであって、それ以外の何でもありません。尋ねるときにもそう書いてあります：ディスク上のフォルダには触れず、`rness/` にも触れず、その中の一語も変わりません。ホーム画面に「このプロジェクトを削除」はありませんし、それはわざとです — プロジェクトを削除するとは、あなたの書いたもので一杯のフォルダを削除するということで、それは Finder の仕事です。自分が何をしているか、目で見える場所の。

表示ボタンの隣の**非表示**チップが、隠したものを呼び戻します。いくつあるかも書いてあります。隠されたプロジェクトは灰色で、行に*非表示*と出ます。option+クリックで戻せます（確認はありません — 即座で、即座に取り消せるからです）。アプリでは **View → Show Hidden Projects** から同じスイッチを動かせます。

### 2.5 プロジェクトを閉じて、また戻る

扉は 2 つ、部屋は同じです。

**アプリで：** **File → Close Project**、または **⌘W**。プロジェクトのバックエンドが行儀よく終了し、1 秒ほどでホーム画面がその場に現れます。

**どこでも、アプリでもブラウザでも：** ⚙ UI ウィンドウ（セクション 10）の上にある**プロジェクトを閉じる → ホーム**ボタン。先に尋ねてきます。閉じることはセッションの終わりだからです — 目の前の会話は、終了したときと同じように終わります — そのあとは、⌘W とまったく同じ場所に着きます。

どちらもあなたのフォルダには触れません。ファイルも、`rness/` も、リクエストファイルも、セッションログも、置いてきたところにそのままあります。終わるのは、動いていた会話だけです。

新しくなった ⌘W について、enough を長く使ってきた人が知っておくとよいことがひとつ：**⌘W はもうウィンドウを閉じません。** enough はウィンドウがひとつのアプリケーションで、そのウィンドウを閉じれば終了してしまいます。だから ⌘Q と赤いボタンですでに足りていて、⌘W にはもっとよい仕事があったのです。

そして、これと再開設定のあいだの相互作用がひとつ。書いておかないと、きっちり一度は驚かせるので：**プロジェクトを閉じても、enough はそれを忘れません。** **Reopen Last Project on Launch** がオンのときに、プロジェクトを閉じ、しばらくホームにいて、それから終了すると — 次の起動で開くのはホームではなく、そのプロジェクトです。トグルは「どこから始めるか」を決める設定で、Close Project は「いま自分がどこにいるか」を決めるボタンです。これからはホームで始めたい、というときは、トグルをオフにしてください。

### 2.6 ホームが覚えていること

小さなものが 3 つ。どれもマシン全体のもので、プロジェクトからプロジェクトへ、そしてホームへ、あなたについてきます。どのプロジェクトフォルダにも保存されません：

- **テーマとフォント**（セクション 10.1）。ホームは最後に選んだ装いをまといますし、ホーム画面*で*切り替えたテーマが、プロジェクトを開いたときのテーマになります。これは以前、人をいらだたせていたところです：起動の画面と仕事の画面は、いまはいつでも同じことを言います。
- **アイコンかリストか**（セクション 2.1）。
- **隠したプロジェクトを出しているかどうか**（セクション 2.4）。

プロジェクトについてのそれ以外は、すべてそのプロジェクトのフォルダの中、あなたが読める場所にあります。

## 3. 仕事のやり方を、根っこからカスタマイズする

ひとつだけ読むなら、ここを読んでください。

たいていのソフトウェアは機能を手渡します。enough が手渡すのは仕組みです。主任リードバイザーの人格、方法、持ち技は、あなたのディスクにある markdown ファイルから、メッセージ 1 通ごとに新しく組み立てられます：

- **`AGENT.md`** — 主任リードバイザーが誰で、どう動くか（セクション 5.3）
- **`MOTIVATION.md`** — なぜ：価値観、優先順位、「終わった」がどんな感じか
- **ポリシー** — 何を読み、書き、取ってきてよいかの動かせない規則（セクション 5.4）
- **有効なパラダイム** — いま効いている思考の枠組み（セクション 15）
- **有効なスキル** — 手を伸ばせる能力（セクション 18）
- **有効なリードバイザー** — 声に折り込まれる、あるいは議事会に席を取るもうひとつの判断（セクション 16）
- **プロジェクトプロファイル** — このプロジェクトについて学ばれたこと（セクション 8.1）

これらを、アプリでもお好みのテキストエディタでも編集すれば、次のメッセージから効きます。ビルドも、再起動も、プラグイン API も要りません。markdown ファイルが書けるなら、あなたはリードバイザーをプログラムし直せます。

### 3.1 全体のもの、プロジェクト専用のもの

カスタマイズできるものはすべて、ひとつの型に従います：**既定は `~/enough/defaults/` にあり、プロジェクトはそこへリンクし、どのプロジェクトもそのリンクを切ることができる。**

`~/enough/defaults/` のファイルを編集すれば、まだリンクしているすべてのプロジェクトに変更が届きます。プロジェクトの中でリンクされたファイルを開き、**カスタマイズ**をクリックすると、リンクはプロジェクト専用のコピーになり、それ以降そのプロジェクトは自分の道を行き、ほかは全体の既定に付いていきます。どちらなのかは、ファイルツリーがひと目で教えてくれます：リンクされたファイルは*斜体で淡く*、ローカルのコピーはふつうに描かれます。

`~/enough/defaults/` に置かれた新しいスキルやパラダイムは、次の起動ですべてのプロジェクトに現れます。リードバイザーには、書き込みのできる 2 つめの住まいが `~/enough/readvisors/` に用意されています（セクション 16）。スキルとリードバイザーはオフの状態で来るので、知らないうちに何かが変わることはありません。欲しくなったときに、プロジェクトごとに有効にしてください。enough が同梱していないスキル — ダウンロードしたもの、友人が送ってくれたもの、セッションの最中にあなたのために書かれたもの — は、通す前にかならず読まれます。セクション 18.8 がその話です。

### 3.2 3 種類の部品

| | パラダイム | スキル | リードバイザー |
|---|---|---|---|
| 何なのか | 思考の枠組み — 仕事にどう向かうか | 焦点の定まった能力 — 語彙、レシピ、手順 | もうひとつの判断 — 自前の AGENT.md と MOTIVATION.md を持つ |
| 同時にいくつ | 常にちょうど 1 つ | オンにした数だけ | オンにした数だけ |
| 置き場所 | `rness/paradigms/<name>.md` | `rness/skills/<name>/SKILL.md` | `rness/readvisors/<name>/` |
| 同梱の例 | default、text-planning、translation、workflow-design | analyzer、anything-finder、girraph-merirmaid、memoir-dialectic、readvisory、scaffold、translator | block-breaker、open-skeptic |

### 3.3 自分のものを作る

これらのファイルは手で書けます — 先頭に小さな YAML ブロックの付いた markdown です — が、手で書く必要はありません。同梱の **workflow-design パラダイム**（セクション 15.4）は、主任リードバイザーがあなたと一緒に作れるように存在します。「こういうスキルを作って」「こういうパラダイムを作って」と言えば、workflow-design に切り替わり、確かめるべきことを尋ね（範囲は？　名前は？　どんなときに動く？　付随するファイルは？）、部品をきちんと書き上げます。将来のターンにいつそれへ手を伸ばすべきかを伝える `description:` のフロントマターも込みで。リードバイザーには専用の入口があります — `readvisory` スキル（セクション 18.5）で、仕様書ではなく人に話を聞きます。

実際に作られているもの：

- 仕事の性質ごとの**パラダイム** — 調査、下書き、推敲 — と、いつ切り替えるかの明示的な規則。
- ニュースレターの声、引用の書式、学位論文の用語法を写し取った**スキル**。
- ソクラテス式に問い返すラバーダックや、疑い深い査読者、あるいは自分がいちばん趣味を信頼している友人を、一度きちんと聞き取って手もとに残した**リードバイザー**。

このマニュアルの残りは、組み込みのものを説明します。そのひとつひとつを、あなたがコピーし、分岐させ、改良してよい実例として読んでください。

## 4. Composure — 積み重ねの土台

プロジェクトを開くと、まず **composure** に降り立ちます：ウィンドウいっぱいのキャンバスと、その隣のパネルに収まった会話（セクション 5）です。ここが 1 階です。出たり入ったりするモードではありません — ほかのモードはすべてこの上に積み重なり、いずれ閉じてここへ戻ってきます。そして composure 自体を閉じる方法はありません。閉じたら、下には何もないからです。（セクション 2 の*ホーム画面*はまったく別のもので、あちらはプロジェクトを開く前にいる場所、こちらは開いたあとにいる場所です。）

composure は `.comp` ファイルです：文章の入った箱と手描きのインクが、果てのない机の上に置かれ、その机を動かしたり、寄ったり引いたりしながら見ていきます。箱のことを**モジュール**と呼びます。保存ボタンはありません — 書いたそばから書き出されます — そしてファイル自体はふつうの HTML なので、`.comp` は enough がまったく入っていないマシンのブラウザでも、読めるただのページとして開きます。これは副産物ではありません。作ったプログラムの中でしか読めないドキュメントは、誰かに貸してあるドキュメントです。

まわりにあるもの：

- **ツールバー**。キャンバスの上端を横切ります：composure のタイトル（打ち込んで、外をクリックすれば名前が変わります）、閲覧／編集の切り替え、ツール、**モジュールを追加**、取り消しとやり直し、ズームのまとまり、検索、コメントの切り替え、そして **composure の一覧**メニュー — form から新しく…、開く…、form として保存…。
- **サイドバー**。プロジェクトのファイルツリーと、操作の区画：有効な**パラダイム**、**スキル**と**リードバイザー**の切り替え、そしてあなたの**リクエスト**です。ファイルやフォルダを option クリックすればコンテキストメニューが出ます（新規ファイル、新規フォルダ、パスをコピー、名前をコピー）。⌘\ でサイドバー全体を隠したり出したりします。
- **上部バー**。モデルウィンドウ、ブローカー、UI ウィンドウ、wikisink（🚰）、cacheawl のボタン。いま積み重なって開いているモードの目印（セクション 13）。そしていちばん右に、リードバイザーパネルの切り替えです。

### 4.1 動きまわる

**机を動かす**には、2 本指のスクロール、space を押しながらのドラッグ、あるいはマウスの中ボタン。**拡大・縮小**は、ピンチ、ポインタを中心にした ⌘ スクロール、⌘+ / ⌘− / ⌘0、あるいは**すべてを画面に収める** — 持っているものが全部入るところまで、ちょうど引いてくれます。ツールバーの倍率表示はボタンです：クリックすれば 100% に戻ります。

勝手に拡大・縮小するものが 2 つあります。どちらも、よかれと思ってやっています。

**パネルの段。** 横のパネルを隠すと、キャンバスは広くなるだけでなく、*大きく*なります：ページの文字は、サイドバーとリードバイザーパネルの両方が開いていればおよそ 12 ポイント、どちらか一方を隠せばおよそ 14、両方隠せばおよそ 16 で読めます。切り替わりは 5 分の 1 秒かけて動き、打っている最中ならカーソルを、そうでなければ画面の真ん中を軸にするので、見ている場所を見失いません。10 回のうち 9 回はこれが正解で、残りの 1 回は自分で倍率を決めれば、そのドキュメントにはもう口を出さなくなります。

**ページに合わせる。** ページのかたちをした composure — blank、journal、council — は、幅がゆとりのある余白ごとちょうど収まる倍率で、真ん中に置かれます。自分で倍率を変えるまでは、そのままです。ウィンドウを広げても紙が大きくなるのではなく、紙のまわりの机が広く見えます。合わせているのは幅だけです：ページはたいていのウィンドウより背が高いので、下のほうはいつも、机をひと動かしした先にあります。

**面。** じゅうぶん引くと、それぞれのモジュールは**面**にたたまれます：箱に入るかぎり大きなタイトルと、形だけになった本文です。ですから 60 枚のカードは、60 個の灰色の四角ではなく 60 本のタイトルとして読めますし、読める大きさで組んだボードは、ひと目で見てもやはりボードです。モジュールにタイトルを付ければ、その面が何と言うかはあなたが決められます。一方インクは、ほかのすべてが縮むよりゆっくり細くなるので、引いて眺めたスケッチも、ちゃんとスケッチに見えます。

### 4.2 四つのツール

閲覧／編集の切り替えは、enough のほかの場所とまったく同じです：読むための目、変えるための鉛筆。ツールは編集の面にしか存在せず、それぞれに文字が割り当ててあります。

- **ポインタ（V）**は選びます。モジュールをクリックし、ドラッグして動かし、ハンドルをドラッグして大きさを変え、何もない机の上をなぞって囲めば複数まとめて掴めます。shift クリックで 1 つ足したり外したり。矢印キーで少し動かし、shift を押していれば大きく動きます。delete で消えます — 中に文章があるときは先に確認が出ますし、⌘Z で戻せます。テキストモジュールをダブルクリックすれば、その中のテキストツールに入ります。
- **テキスト（T）**はテキストモジュールの中にカーソルを置きます。箱を作ることはできませんし、何もない机をクリックしても何も起きません — それはモジュール追加ボタンの仕事です。ページの中では、太字と斜体、見出しの階層、箇条書き、チェックリスト、引用、コード、リンク、そして 4 色のハイライトが使えます。しかも、あなたがふだん打っている markdown のままで：`# `、`- `、`1. `、`[] `、`> `、そして囲みブロックは、打った端から本物になります。貼り付けたものは、まず素の構造まで削ぎ落とされます。
- **鉛筆（P）**は描きます。ただ描いてください。指を離した時点で、線はなめらかに整えられます。ドラッグしながら **shift** を押さえていれば、先端に矢じりの付いたまっすぐな線になります — *これ、それからあれ* と言いたいときの書き方です。
- **消しゴム（E）**は消します。どれだけ拡大・縮小しても、画面の上では同じ大きさのままの円です。線の上を通せば円の下にあった部分が消え、両端は別々の線として残ります。⌘Z を押せば、線はひと続きに戻ります。

インクは机の上、モジュールの*下*に横たわっています。ですから 1 本のメモが 3 枚のカードをまたげますし、矢印が 2 枚をつなげます。ポインタで線の近くをクリックすれば拾い上げられ、インスペクタが 5 色のインク — インク、赤、青、緑、黄 — と削除を出します。

### 4.3 モジュール：六つの種類

**テキスト**モジュールは文章そのもので、中に好きなだけページを持てます。残りの 5 つは何かを指し、読んでいるあいだはその下読みを見せ、クリックすれば本物を開きます：

- **このプロジェクトのファイル** — 冒頭の数行が見え、クリックすればツリーでクリックしたときとまったく同じように開きます（変換されたドキュメントも含めて）。`.comp` を指させれば、クリックで足もとのキャンバスが入れ替わります — ボードが掘り下げていけるものになるのは、これのおかげです。
- **wikisink の記事** — 冒頭の段落が見え、クリックすればその場所で wikisink の読み手が開きます（セクション 11）。まだアーカイブのないマシンでは、カードがそう言いつつ記事名は覚えておき、アーカイブが入った時点で自分で中身を埋めます。
- **ウェブへのリンク** — タイトルとホスト名。クリックすると、アプリのほかの外部リンクと同じように、あなたのブラウザで開きます。
- **キャッシュしたウェブページ** — 最後に取ってきた時点のページの文章と、その日付、そして**更新**ボタン。更新はほかのウェブ読み取りとまったく同じくブローカーを通るので、取得の切り替え、許可リスト、Tor 経由の設定がすべて効きます — そしてブローカーが断った場合、カードはその断り文句をブローカー自身の言葉で見せます。どのスイッチを見に行けばいいか、分かるようにです。
- **画像** — 箱に収まる大きさに合わせた絵です。クリックすれば画像ビューアが開きます（セクション 7.9）。

**モジュールを追加**を押すと、6 つの短い一覧が出ます。新しいモジュールの置き場所と大きさは enough が決めてくれます — いま見ていたものの近くに置き、選んだ状態にします。

### 4.4 インスペクタ

編集の面で何かを選ぶと、その横に — けっして上に重ならずに — 小さなパネルが現れ、当てはまるものを一通り並べます：

- **背景の色見本が 10 色**：紙、黄、ピンク、青、緑、オレンジ、ライラック、グレー。それに、暗いカードになる**インク**と、そもそもカードにならない**透明**。後ろの 2 つは構造のためのものです：見出しの行には暗いカードを、メモに見えてほしくないラベルには透明を。
- **文字の大きさ**。小さく、大きく。そのモジュールにだけ効きます。
- **ページ**：足す、減らす。ページが 2 枚以上あるモジュールにはページ送りのボタンと `n / N` の表示が付き、1 ページに収まりきらなくなった文章は、黙って伸びつづけるかわりに**新しいページに続ける →**を出します。
- **重なり**：前面へ、背面へ。
- **その種類ごとの欄**（あるものだけ） — 打ちながらプロジェクトのツリーを検索するファイル選択、wikisink の検索欄、アドレスの欄、更新の方針。
- **このモジュールにコメント**、そして**削除**。

モジュールを複数選ぶと、インスペクタは何個選ばれているかを言い、その状態でも意味のあるものだけを出します。

### 4.5 form と、自分の form を保存する

**form** は composure のひな型です。5 つ同梱されています：

- **blank** — ページのかたちをした紙が 1 枚。編集の面で開き、カーソルはもう中で点滅しています。
- **cards** — テキストカードを格子に並べたボード。全体が収まるところまで引いた状態で開きます。
- **scaffold** — 場面を列ごとに並べたボードで、上には前提を書く帯、下には結びを並べる行が渡してあります。`scaffold` スキル（セクション 18.6）が、メモの山を構造に変えるときに埋めるのがこれです。
- **journal** — 日付入りの記録です。1 ページに 1 モジュール、1 つの記録。ジャーナルを開くと*今日*のページにカーソルが入った状態で始まり、そのページはあなたが何か打ち込むまでメモリの中にしかありません。ですから、開いてみて気が変わっても、あとには何も残りません。記録は書きながら勝手に保存されます。綴じないまま離れても、ジャーナルはその書きかけの下書きから開き直します。**この記録を綴じる**を押すと日付が刻まれ、そこから先はずっと読むだけのものになり — enough はあとから変えることを断りますし、カーソルも入りません — 次のための新しいページへ進みます。綴じた記録を遡って眺めるのは安全です：書き込まなかったページをめくっても、何ひとつ保存されません。綴じた文章にもコメントは付けられます。むしろ、綴じるのはそのためです。
- **council** — リードバイザーたちが、ひとつのことについて順番に考える部屋です。セクション 17 で扱います。

composure の一覧メニューにある **form として保存…** は、いま見ている composure をあなた自身の form として取っておきます。置き場所は `rness/composure-forms/` で、それ以降このプロジェクトの一覧に並びます。同梱の form と同じ名前を付けたときは、あなたのものが勝ちます。

### 4.6 検索、コメント、そして取り消し

**検索**は、すべてのモジュール、すべてのページの素の文章を読みます — ちょうど 1 つだけ選ばれているときは、そのモジュールだけを読みます。enter と shift+enter で見つかった箇所を順にたどり、欄の横に件数が出ます。見つかった箇所は*場所*であって、ハイライトではありません：キャンバスがそこへすっと寄り、別のページにあればそのページをめくり、その言葉の上でひととき光ります。どこにあるかを示すために、あなたの文章に手が入ることはありません。esc で検索語が消えます。

**コメント**は wikisink のもの（セクション 11.2）と同じ仕組みで、同じカードの上で働きます。モジュールの中の文章を選んでコメントすることも、インスペクタや option クリックのメニューからモジュール全体にコメントすることもできます。ツールバーのコメントボタンでパネルが開きます。返信、解決、再開、該当箇所へ移動。あとから書き換えて消えてしまった文章に付いていたコメントは、そのモジュールに留め直されます。モジュールごと消したときは、コメントはパネルの中で**親なし**とそう書かれたまま残り、黙って捨てられることはありません。コメントは `.comp` の中ではなく、その隣の隠しファイルに住んでいます。ですから composure 自体はきれいなままですし、綴じたジャーナルのページや議事会の発言のような、そもそも編集できないものにも付けられます。

**取り消し**は ⌘Z、やり直しは ⇧⌘Z で、開いている composure ごとに 100 手まで遡れます。文章のページの中では、ブラウザ自身の取り消しが引き継ぎます — そこではそちらが正解だからです。

### 4.7 composure はどこにあるか、起動時に何が開くか

新しい composure は `rness/io/composure/` に置かれ、タイトルと日付から名前が付きます。ふつうのファイルです：コピーしても、git に入れても、enough を聞いたこともない人にメールで送っても構いません。

中に何かが書かれるまで、何も書き出されません。開いただけで触らなかった composure は、ファイルを 1 つも残しません — 空のものすら残しません。保存するものができたら、ツールバーの保存表示が知らせつづけます：*保存中…*、それから*保存しました*。サーバーに一時的に届かないときは*保存できません — 再試行中*です。黙って嘘をつくかわりの、正直な言い方です。

どの composure に降り立つかは、あなたが決められます。**プロジェクト**ウィンドウ — プロジェクトの名前、説明、フォルダが並んでいるあれです — に**起動時に開くもの**の行があり、答えは 4 つ：*新しい白紙のページ*、*最後に使った composure*、*特定の composure…*、*form から新しく作る…*。指しておいたものがその後に名前を変えられていたり消えていたりしたら、enough は白紙のページを開き、そのことを一行で伝えます。入口であなたに向かって失敗してみせたりはしません。

そしてファイルツリーの `.comp` は、どれもクリックひとつで開きます。いましていることの上に積み重なるのではなく、キャンバスが映しているもの*そのもの*が入れ替わります。1 階は、いつでもひとつしかないからです。

### 4.8 積み重ねの下を覗く

上部バーにあるモードの積み重なりの目印（セクション 13）は、composure を表す消えない四角で終わっています。閉じるためのリボンは付いていません。閉じるものがないからです。

モードを積み重ねた状態でこれをクリックすると、そのすべてが隠れ、下のキャンバスが見えます。隠れたモードの状態はそっくりそのまま — スクロールの位置も、保存していない編集も、入れ子の girraph をどこまで降りたかも残ります。もう一度クリックするか、ほかの目印をクリックすれば、すぐ戻ってきます。覗いているあいだの esc は、まず積み重なりを戻し、それから 1 枚外します。

確かめたいものがボードの上にあって、そのために 3 枚のモードを畳みたくはない — そういうときのためのものです。

### 4.9 リードバイザーが composure にできること

読むこと、form から作ること、モジュールを足したり見た目を変えたり並べ替えたりすること、ページを書くこと、composure を form として保存すること、そして — `scaffold` スキル（セクション 18.6）を使えば — 構成案ひとつを、ひと手でボードに組み上げることまでできます。これらはすべて、ブローカーの **composure ツール**の切り替え（セクション 9）が関門になります。あなた自身がキャンバスを触るぶんには、いつでも関門はありません。あなた自身の wikisink や cacheawl の閲覧に関門がないのと同じです。

できないのは、`.comp` をファイルとして書くことです。ふつうのファイル書き込みの入口は 2 つともこの拡張子を頭から断ります。ですからリードバイザーの加えるどの変更も、あなたが使うのと同じ小さな操作の集まりを、ひとつずつ、同じ入口から、記録に残る形で通っていきます。つまり、混乱したモデルがドキュメントを壊すことはありません — できるいちばん悪いことは、要らないカードを 1 枚足すことで、⌘Z はすぐそこにあります。

あなたが composure を見ているあいだにリードバイザーがモジュールを変えると、そのモジュールはひととき光って、その場で読み込み直されます。ただひとつ、あなたが打ち込んでいる最中のモジュールだけは、足もとで書き換えられることがありません。

## 5. リードバイザーパネル

会話は右側の列に住んでいます。いま手を動かしているものの*かわり*ではなく、その*隣*にいます。いちばん上にはあなたの**主任リードバイザー**の名前 — 名前を変えるまでは **Ed** です（セクション 16） — が出て、その横に、有効にしてある他のリードバイザーが並びます。ふだんの会話では、その全員の視点を汲みつつ、ひとつの声として答えます。めいめいが別々に話すのは議事会（セクション 17）です。

メッセージを打って ⌘Enter、または送信ボタンを押します。返事はその場で流れてきますし、リードバイザーが話しているあいだに enough は動けます — ファイルを読み書きし、シェルコマンドを走らせ、ページを取ってきます。ツールの呼び出しは、起きたそばから記録に現れます。**マイクボタン**は口述のためのものです：音声は whisper.cpp がこのマシンの中で文字に起こすので、あなたの声がマシンを出ることはありません。録っているあいだ、ボタンは脈打ちます。もう一度クリックすれば止まります。

### 5.1 ドック、全画面、閉じる

状態は 3 つ、切り替えは上部バーのいちばん右にひとつです。

**ドック**が既定で、ふだん暮らすのはここです。キャンバスの隣 — あるいは、その上に積み重ねたどのモードの隣 — に立つ、本物の列です。ですから、読んでいるものを閉じてから訊く、ということが要りません。それには狭すぎるウィンドウでは、つまりドックに入れると舞台が 480 ピクセルほどより狭くなってしまう場合、パネルは舞台をさらに押しやるかわりに、その右端の上に浮かびます。

**全画面**はパネルにウィンドウ全体を渡し、会話を読みやすい幅の列で真ん中に置きます。これは昔返りです：かつての Discussion 表示で、答えが長く、腰を据えて向き合いたいときのためのものです。

**閉じる**は、幅ゼロの列です。パネルを閉じているあいだに返事が終わると、上部バーのボタンに点が付きます — *見ていないあいだに何か届きました*であって、*いい答えが出ました*ではありません。パネルを開けば点は消えます。

⌘/ で開いたり閉じたり。⇧⌘/ でウィンドウ全体を渡し、⌘/ で戻します。⌘K はいつでもメッセージ欄にカーソルを移し、閉じていれば途中でパネルを開きます。esc は全画面のパネルをドックに戻します — ただし、カーソルがメッセージ欄にあるあいだ esc は効きません。パネルを開くとカーソルはそこに入るので、先に外をクリックしてください。**esc がドックのパネルを閉じることはありません。**これはわざとです：誰もがうっかり押してしまう、まさにそのキーだからです。

開いているか閉じているかはプロジェクトごとに、そのプロジェクト自身のファイルに覚えられ、ウィンドウが最初に描かれる前に適用されます。ですから起動時に画面が跳ねることはありません。全画面は設定ではなく仕草なので、覚えられることはありません。

**例外がひとつ、議事会です。** 議事会がキャンバスに出ているあいだ（セクション 17）、パネルは閉じたまま保たれ、切り替えは押せなくなり、理由がツールチップに出ます：議事会とチャットは 1 つのモデルを分け合っていて、そのモデルは 1 つしかないからです。議事会を離れれば、パネルはあなたが置いていたとおりに戻ります — あなたの好みは上書きされず、覚えられています。

### 5.2 選択したところを送る

パネルから見えるところならどこでも、文章を選べば — read/edit のドキュメント、wikisink の記事、composure のモジュール — メッセージ欄の上にチップが現れ、どこから来たかを名指しし、冒頭を引いて見せます。送れば、その一節はメッセージと一緒に、囲みと、チップに出ていたとおりの見出しを付けて渡ります。チップの × で外せます。

説明するより、添えるほうが勝ります。言葉はそのまま渡り、リードバイザーはそれがどこから来たかを、探しに行かずに教えてもらえます。そして、それ*以外*は何も添えられません：パネルの後ろで開いたままのモードが、送るメッセージすべてに黙って自分を刷り込む、ということはありません。あなたが選んだものが、渡るものです。

### 5.3 AGENT.md と MOTIVATION.md

どのプロジェクトも、この 2 つのファイルを `rness/` に自分のコピーとして持っています。あなたの主任リードバイザーの正体の根であり、両方が毎ターン読み込まれます。

**`AGENT.md`** は*どう*のほう：作業の指示です。口調、歯止め、作法、いつも守ってほしいこと。「文章は小文字のままで」「`archive/` の中のファイルには絶対に触らないこと」「1 行を超えるシェルコマンドを走らせる前に尋ねること」。

**`MOTIVATION.md`** は*なぜ*のほう：目の前の作業を越えた価値観と優先順位です。このプロジェクトは何のためで、誰のためか、どのトレードオフが大事か（速さより正しさ？　網羅より簡潔さ？）、そして「終わった」がどんな感じか。

サイドバーでどちらかのファイルをクリックすれば読めます。**カスタマイズ**を押せばプロジェクト専用のコピーに分岐しますし、好きなエディタで編集しても構いません。変更は次のメッセージから効きます。ほかのリードバイザーも、同じ 2 つのファイルを使います（セクション 16）— 主任がほかと違う種類のものだ、ということではありません。指名がないときに話すのがその人だ、というだけです。

### 5.4 policies フォルダと許可リスト

`rness/policies/` には、リードバイザーの動かせない規則が入っています。人格ではなく、法です。既定では 4 つのポリシーが同梱されています：

- **`allowlists.md`** — 手の届く範囲の規則。一覧は 3 つ：
  1. *読み取りを許すパスの接頭辞：* プロジェクトの外でリードバイザーが読んでよい絶対パス（既定は `~/enough/`）。
  2. *読み書きを許すパスの接頭辞：* プロジェクトの外で書き込みもしてよいパス。この一覧は**空**で出荷されます：箱から出したままなら、リードバイザーが書くのはあなたのプロジェクトの中だけで、あなたが自分でパスを足すまでそのままです。
  3. *インターネットのドメイン：* 直接取りに行くホスト（既定には `gutenberg.org`、`en.wikipedia.org`、`en.wikisource.org`、`archive.org`、`standardebooks.org`、そして Kiwix のダウンロードホストが入っています）。一覧に無いドメインは、遮断されるのではなく、ローカルの Tor プロキシ経由に回されます。ちょっとした調べ物で、どこかのサーバーのログにあなたのアドレスを残さずに済むように。ブローカーの切り替えでこの逃げ道を切れば、一覧外の取得はそのまま失敗します。
- **`context-management.md`** — 埋まっていくコンテキストウィンドウをどう感じ取り、状態を失わずに行儀よくリセットするか（セクション 8.3）。
- **`requests.md`** — 長く続く仕事を、いつ、どうリクエストファイルとして追いかけるか（セクション 8.3）。
- **`profile-maintenance.md`** — プロジェクトプロファイルに書くべきもの、書かないもの（セクション 8.1）。

ポリシーもほかと同じく defaults からシンボリックリンクされているので、許可リストを全体で締めることも、もっと緩い（あるいは厳しい）範囲が要る 1 つのプロジェクトのためだけにカスタマイズすることもできます。実際にいちばんよくあるカスタマイズが `allowlists.md` の編集です：信頼しているドキュメントのサイトを足し、リードバイザーに書かせたい共有フォルダを足して、あとは一日を進めてください。

## 6. read/edit モード

ツリーのファイルをクリックすると、ひとつにまとまった read/edit モード（読み／編集）で開きます。ひとつのモードに*面*が 2 つ：見直すための**読む面**（目）と、文章を変えるための**編集の面**（鉛筆）です。

### 6.1 全画面とミニ、そしてすべてのあいだの行き来

read/edit の大きさは 2 通り。**ミニ**はチャットの隣のサイドパネルです：話しながら、資料を肘のあたりに置いておけます。（ミニパネルにはレビューのツールバーをあえて置いていません — 読むことと軽い編集のためのもので、書き込みのためではないからです。）**全画面**は画面いっぱいを取ります。長いドキュメントや、腰を据えた編集のために。

大きさはパネルの枠のミニ↔全画面ボタンで、面はその隣の面切り替えボタンで変えます。編集の面では ⌘S で保存します。いま見ているものが変換されたドキュメントのツインなら、枠には元ファイルの名前も出て、変更を書き戻すための**書き出し**ボタンが付きます（セクション 7.5）。そしてすべてに未保存の見張りが付いています：保存していない編集があるとき、enough はそれを捨てさせる前にかならず尋ねます — 別のファイルへ移るとき、モードを閉じるとき、別のドキュメントへ跳ぶとき。うっかりのクリックで 1 時間分の仕事を失うことはありません。

ドキュメントを開いているあいだ、上部バーに 3 つの数が出て、あなたの打鍵に付いてきます：**¶** 段落、**W** 語、**C** 文字。（ホーム画面のリスト表示は、同じ 3 つの合計をプロジェクト全体について見せます — セクション 2.1。）

ほかの全画面モードと同じく、read/edit も右上の印の場所に自分のアイコンを出し、閉じるための小さな赤い × のリボンを下げています（セクション 13）。

### 6.2 ハイライト

どの markdown ドキュメントでも、読む面で文章を選べば、4 色 — **黄、緑、青、ピンク** — のどれかで塗れます。ツールバーからでも、選択の上に出るポップアップからでも。同じツールバーが軽い書式も出します：太字、斜体、下線（⌘B / ⌘I / ⌘U）。

ハイライトは消えませんし、本文の外側に暮らします：ドキュメントごとに隠しの伴走ファイル（`.<filename>.highlights.json`）ができるので、あなたの文章にマークアップが割り込むことはなく、ドキュメント自体はきれいなままです。ハイライトされた行には、余白に色の帯が付きます。ハイライトはセッションをまたいで残り、色が重なれば重なったまま積まれます。

ここからが、仕事のやり方を変えるところです：リードバイザーにもハイライトが見えます。`read_highlights` ツールはドキュメントの中のハイライトを色ごとに並べ、`navigate_to_highlight` はそのひとつへ表示を飛ばします。これでハイライトは、ひとつの通信路になります。書き直してほしい 4 つの段落を黄色に、気に入っている 2 つを緑に塗って、「黄色のところを書き直して。緑のところの調子は残して」と言えばいい。あなたが色を口にしたとき、リードバイザーはそれがあなたのハイライトのことだと分かっています。

### 6.3 対応しているファイル形式

- **markdown（`.md`）** は、読む面では整形されて、編集の面ではソースとして出ます。markdown は enough の母語です — このシステム自身が書くもののほとんどが markdown です。
- **平文テキスト**と、テキストらしいものはすべて、read/edit でテキストとして開きます。
- **`.girraph`** ファイルは、かわりに girraph モードで開きます（セクション 19）。
- **`.merirmaid`** ファイルは、かわりに merirmaid モードで開きます（セクション 20）。
- **保存した Wikipedia の記事**（`wiki/` フォルダの中の `article.html`）は、wikisink の読み手で完全なまま開きます（セクション 11.2）。
- **Word ドキュメント、PDF、電子書籍、スライド、ワークブック**は、編集できる markdown の**ツイン**として開きます — ツリーでは 1 行、クリックは 1 回、そして枠には変更を書き戻すための**書き出し**ボタン。それがセクション 7 で、話はそこにすべてあります。
- **画像**（`.png`、`.jpg`、`.gif`、`.webp`、`.bmp`、`.svg`）は素のビューアで開きます（セクション 7.9）。ドキュメント*の中*の画像は、markdown のほかの絵と同じように読む面で描かれます。

enough はいまもテキストのシステムですし、これからもそうです：描くのは markdown であって、ページのレイアウトではありません。それ以外のものに対してすることは、変換です — 中で仕事ができる程度には損なわず、何が生き残らなかったかを言う程度には正直に。

## 7. PDF、Word ドキュメント、その他のファイルを扱う

enough は PDF を描画しませんし、Word ドキュメントのレイアウトもしませんし、表計算も描きません。そのふりもしません。かわりにすることは、もっと静かで、ここでするような仕事にはもっと役に立ちます：ドキュメントを、実際に読めて、編集できて、ハイライトできて、リードバイザーに渡せる markdown に変換し、その markdown を元ファイルにつなぎ止めておく — だから、あなたの変更は帰れるのです。

これのどこにも、別のモードや別のアプリはありません。ファイルをクリックする。開く。それだけです。

### 7.1 ツイン

`memo.docx` を開くと、enough はその隣に `memo.docx.md` を書きます。この 2 つめのファイルが**ツイン**：ドキュメントの素の markdown コピーで、あなたのプロジェクトフォルダに座り、ほかと同じように編集できます。これを作っても、元ファイルには決して手が入りません。

ファイルツリーに見えるのは 1 行のまま — `memo.docx` です。ツインと、ドキュメントから取り出された画像のフォルダ（`memo.docx.assets/`）と、何を何から変換したかを記録した小さな隠しファイルは、すべてその 1 行に畳み込まれます。だからあなたのプロジェクトは、Finder で見たときの姿のままでいられます。行をクリックすればツインが read/edit モード（セクション 6）で開き、そのモードが与えるものはすべて使えます：2 つの面、⌘S、未保存の見張り — そして全画面にすればハイライトも。

知っておくとよい帰結が 2 つ。名前がぶつかることはありません：あなたが書いた `memo.md` と `memo.docx.md` は別のファイルで、enough が取り違えることはありません。そして Finder で `memo.docx` を消しても、何も壊れません — ツインは静かに、ツリーの中のふつうの markdown ファイルになります。もともとそれ以上のものではなかったのです。

リードバイザーにも、あなたと同じものが見えています。`report.pdf` を読んでと頼めばツインが渡され（まだ無ければ先に 1 つ作られます）、何かを変えてと頼めばツインを編集します。あなた自身の編集が行くのと、まったく同じ場所です。

### 7.2 enough がこの形で開けるもの

この一覧は、誰かが更新を思い出さなければならない文章ではなく、アプリ自身から来ます — enough の外でこれを読んでいるなら、アプリでヘルプセンターを開けば（セクション 10）中身の入ったものが見られます：

{{convert-formats}}

### 7.3 ツリーの中のバッジ

変換できるドキュメントはどれも、行の右端に小さなバッジを付けています。バッジの仕事はきっかりひとつ：2 つの半身がまだ一致しているかどうかを伝えることです。

- **静か** — 変換済みで、両側が一致。することはありません。
- **点灯、あなたの色** — あなたがツインを編集しました。その変更は markdown にあって、まだ元ファイルにはありません。用意ができたら書き出してください（セクション 7.5）。
- **点灯、リードバイザーの色** — 変換されたあと、元ファイルが enough の外で変わりました。誰かが Word で編集した、新しいコピーが上に落ちてきた、共有ドライブから降りてきた。
- **点灯、エラーの色** — 上の 2 つが両方。enough があなたに尋ねる唯一の場面で、実際に尋ねます（セクション 7.7）。
- **中抜き** — 変換できるが、まだ変換していない。クリックすれば変換されます。
- **中抜きで、クリックするとエクストラの説明が出る** — まだそれを読めないインストールでの PDF、スライド、ワークブック（セクション 7.8）。

バッジにカーソルを置けば、同じことが一文で出ます。バッジをクリックしたときの動きは、ファイル名をクリックしたときとまったく同じです。

### 7.4 初めて開くとき

ドキュメントの*種類*ごとに、初めて開くときだけ、これから何が起きるかを短いモーダルが説明します — ツインとは何か、どこに置かれるか、元ファイルはそのままだということ。ボタンは OK ひとつ。ファイルごとではなく種類ごとに一度なので、2 つめの Word ドキュメントはただ開きます。

オフィス文書の変換は速く、ふつうのものなら 1 秒もかかりません。走っているあいだ、隅に小さなトーストが出て、時間のかかるものには**キャンセル**ボタンが付きます。PDF はもっと時間がかかり、正直な進捗バーが付きます（セクション 7.8）。

### 7.5 変更を書き出して戻す

開いたツインは、その枠に**書き出し**ボタンを持っています。モーダルはひとつ、決めることは 3 つ：

**どの形式か。** 元ファイル自身の形式があらかじめ選ばれていて、ほかの書き出し先も並びます — Word ドキュメントは PDF にも、EPUB にも、単体で完結する HTML ページにもできます。その形式にできないことは、理由つきで灰色になります。黙って消えることはありません。

**コピーか、元ファイルか。** 既定は元ファイルの隣に書かれる**日付入りのコピー** — `memo-2026-08-19-1042.docx` — で、確定する前に正確なファイル名がモーダルに出ます。何も危険はありません：新しいファイルが 1 つできて、古いほうは無傷です。2 つめの選択肢は元ファイルをその場で上書きするもので、書き出し先が元ファイル自身の形式のときにだけ出ます。これを選ぶと、enough はあとから**取り消し**を差し出します：新しいファイルを残すか、古いバイト列を 1 バイトも違わず戻すか。

**これから同期を保つかどうか** — セクション 7.6 へ。

この旅で何が生き延びるかについて、ひとこと。`.docx` や `.odt` を上書きするときは元ファイルをスタイルの手本として使うので、ページサイズ、フォント、ランニングヘッダーやフッターは、あなたの文章と一緒に帰ってきます — markdown では表しようがなく、そうでなければ失われていたものです。markdown が本当に運べないものは帰りません：変更履歴とコメント（取り込むときに反映して落とします）、テキストボックス、フィールド、画像の精密なサイズ指定。この非対称さこそが、日付入りコピーが既定である理由であり、enough が自分の判断で元ファイルを書き換えない理由です。

### 7.6 元ファイルを同期しつづける

書き出しのモーダルで**元ファイルを同期しつづける**にチェックを入れると、ツインを保存するたび、元ファイルも静かに書き直されます。enough で編集していれば、同僚に求められたときの `.docx` はいつでも最新です。ファイルごとの設定で、チェックを入れたその瞬間から効き、保存が向こう側まで届くたびに小さな確認が出ます。

これは書き戻せる形式にだけ出ます — Word、OpenDocument、リッチテキスト、EPUB。セクション 7.2 の「同期できるか」の列が正です。PDF は参加できず、その理由ははっきり言う値打ちがあります：enough は markdown から PDF を*書け*ますが、そのとき組版を一から作り直します。同期される PDF は、保存のたびに、丹念にレイアウトされた元ファイルを、言葉だけを素で組み直したものに置き換えてしまう。それは同期ではなく取り壊しなので、差し出さないのです。

### 7.7 両側が変わったとき

元ファイルは、あなたを置いて先へ進むことがあります。あなたはここでツインを編集し、誰かが Word で `.docx` を編集する。いま、真実が 2 つあります。

enough は気づきます。大事な瞬間 — ツリーが描かれるとき、ドキュメントを開くとき、保存するとき、書き出すとき — のたびに、変換時に記録した内容と元ファイルを比べます。単に*触られた*だけのファイル（コピーされた、バックアップされた、開いて閉じられた）は数えません：この確認はタイムスタンプではなく中身を読みます。

本当に両側が変わっていたとき、平たい言葉で 3 つの選択肢を出すモーダルが現れます：

- **ツインを残す。** 何も書きません。バッジは「あなたが変えた」に戻り、判断はあとに回ります。
- **元ファイルに書き出す。** あなたの markdown が勝ち、元ファイルは書き直され、いつものように取り消しが差し出されます。
- **元ファイルから変換し直す。** 元ファイルが勝ち、新しいツインが書かれます — そして古いツインは、削除されるのではなく、その隣に取り消し用のファイルとして退避されます。

このモーダルのどの選択肢も、取り返しのつかないものを壊しません。この機能全体が、その設計の決まりの上に立っています。

### 7.8 PDF、スライド、ワークブックを読む：PDF エクストラ

PDF を読むのは、Word ファイルを読むより難しい問題です。`.docx` はまだ、見出しとは何かを知っています。PDF が知っているのはインクがどこに落ちたかだけで、そこから表や 2 段組やスキャンを取り出すには、本物のドキュメントモデルが要ります。そのモデルは大きいので、基本のインストールには入っていません — かわりに、ワンクリックのところに置いてあります：**⚙ UI ウィンドウ → extras → PDF エクストラをインストール**。

かかるものを、正直に：

- ダウンロードで約 **250 MB**、インストール後のディスクで約 **1 GB**。
- 加えて**モデルの重み約 0.7 GB**。一度だけ取ってきて、`~/enough/weights/docling/` に置かれます。
- 時間は数分、ほとんどはダウンロード。インストーラはログをウィンドウに流すので眺めていられますし、エンジンは動いたまま切り替わります — 再起動は要りません。

手に入るもの：**PDF**（スキャンされたものも含みます。文字は OCR でピクセルから読み出されます）、**PowerPoint のスライド**（各スライドが見出し付きのセクションになります）、そして **Excel のワークブック**（各シートが markdown の表になります）。

速さは、当て推量ではなく実測で、Apple silicon にて：デジタルの PDF で 1 ページあたり約 **0.9 秒**、加えて変換ごとに 1 回だけ約 **10 秒**のモデル読み込み。ですから 1 ページの PDF で約 10 秒、100 ページの本で 1 分半ほど、スライドやワークブックなら数秒です。長い変換は進捗を出し、途中で止められます。止めても何も残りません — 書きかけのツインも、迷子のフォルダも。

あとで首をかしげずに済む話が 2 つ。ひとつめ：**PDF を書き出すのに、これは何ひとつ要りません。** どのツインも、エクストラの有無にかかわらず、どのインストールでも PDF に書き出せます。それをする組版器が enough に同梱されているからです。エクストラは*読む*ためのものです。ふたつめ：入れたはずのマシンで「エクストラが必要です」と出たら、どちらの文言が出たかを読んでください — パッケージとモデルの重みは別々のダウンロードで、途中で切れた接続は、前者だけあって後者が無い状態を残すことがあります。もう一度インストールを走らせれば仕事は仕上がり、すでに持っているものを取り直すことはありません。

更新してもエクストラは残ります。`update-enough.command`（と `/update-enough`）は、あなたが何を入れたかを覚えていて、同期のたびにそれを取り直します。日常の更新が、PDF の読み込みを黙って取り上げることはありません。

### 7.9 画像と、元ファイルを見ること

画像をクリックすると素のビューアで開きます：既定は幅に合わせ、クリックすれば実寸に切り替わってスクロールでき、透明なところの後ろには市松模様、ヘッダーには名前、ピクセル寸法、ファイルサイズ。読み取り専用です。enough は画像エディタではありませんし、そちらへの野心もありません。

ドキュメント*の中*の絵は話が別で、ちゃんと渡ってきます：Word ファイルの中の写真は `memo.docx.assets/` に取り出され、ツインの読む面で、markdown のほかの画像とまったく同じように描かれます。

そしてツインでは足りないとき、PDF の枠には**元ファイルを見る**があります：実際の PDF をパネルに開くので、ツインを本物のページと突き合わせられます。閉じれば、離れたところからツインに戻ります。

### 7.10 変換で失うもの、2 文で

自分で見つけてもらうより、声に出して名指しておく値打ちのある限界が 2 つ。ワークブックのシートは、**シート名の見出しなしで**表が続けて並ぶ形で届きます — リーダーがそれを出さないので、enough はラベルをでっちあげるより空白を残すほうを選びます。そして PDF から取り出された絵には、毎回「Image」という代替テキストが付きます：ファイルの中に、もっとよい名前をあげられるキャプションが無いのです。

それを越えたところに、変わらない約束があります：**あなたの元ファイルは、あなたが頼まないかぎり変更されません。** 変換がすることは、その隣に新しいファイルを書くことだけです。元ファイルに触れる道は書き出しの上書きただひとつで、それには意識したクリックが要り、そして取り消しが残ります。

## 8. プロジェクトフォルダと `rness/`

プロジェクトとはフォルダです。どんなフォルダでも構いません。enough がそこに足すものはきっかりひとつ、`rness/` — このプロジェクトのために外に出された頭です。ここであなたのリードバイザーたちが何者であるか、何を知っているか、何を覚えているかは、すべてそのフォルダの中にふつうのファイルとして置かれます。全部読めますし、全部編集できますし、その習慣があるなら git に入れても構いません。

構成はこうです：

```
your-project/
  rness/
    AGENT.md            who your chief readvisor is    (5.3)
    MOTIVATION.md       why they work                  (5.3)
    active-paradigm     which paradigm is in force     (15)
    paradigms/          available reasoning frameworks (15)
    skills/             available skills               (18)
    readvisors/         the readvisors you can turn on (16)
    policies/           the hard rules                 (5.4)
    composure-forms/    composure forms you saved      (4.5)
    knowledge/          project memory                 (8.1)
      councils/         exported council transcripts   (17)
    io/                 input/output workspace          (8.2)
      composure/        where new composures land       (4.7)
    requests/           long-running work tracking      (8.3)
  ...your actual files...
```

このうち 2 つは、必要になってはじめて現れます：`composure-forms/` は composure を form として最初に保存したとき、`knowledge/councils/` は議事会が最初に結論を出したときです。何の説明もしてくれない空のフォルダは、結局あとで人に訊くことになるフォルダですから。

**このプロジェクトが 0.3.5 より前のものなら**、`rness/readvisors/` ではなく `rness/roles/` フォルダを持っています。enough は次にそのプロジェクトを開いたときに、ひと動きでこれを改名し、プロジェクト専用のリードバイザーも、オンオフの設定も、そっくりそのまま引き継ぎます。それができないときも — 読み取り専用のディスク、ほかの何かが掴んでいるフォルダ — 壊れるものはありません：すべて古い名前のまま動きつづけ、改名は次の起動でまた試されます。

シンボリックリンクの項目（ツリーでは斜体）は全体の既定に付いていきます。どれでもカスタマイズすれば、ローカルのコピーに分岐します（セクション 3.1）。どんな手段で置かれたファイルでも — Finder、別のエディタ、リードバイザー — 次のターンには全員に等しく見えています。

変換されたドキュメント（セクション 7）も、ここにファイルを足します。いつでも元ファイルの隣、いつでもその名前にちなんで：`memo.docx` にはツイン `memo.docx.md`、絵は `memo.docx.assets/`、そして何を何からいつ変換したかを記録する隠しの `.memo.docx.convert.json`。ツリーはこの 3 つを元ファイルの行に畳み込みますが、ディスク上ではふつうのファイルです — 2 つまとめて別のマシンにコピーしても、git に入れても、ツインを消して元ファイルをまたクリックして新しいものを作らせても構いません。隠しのマニフェストは enough の帳簿です。放っておけば正確なままですし、消せば enough は単に、そのドキュメントを一度も変換していないものとして扱います。

### 8.1 knowledge フォルダ

`rness/knowledge/` は、プロジェクトごとの記憶です。

**`project-profile.md`** は、このフォルダでいちばん役に立つファイルです。中身は毎ターン、リードバイザーのシステムプロンプトに流し込まれます：ここに書かれていることは、探しに行かなくてもリードバイザーの作業記憶に入っています。リードバイザーは働きながらこれを手入れします — 観察したあなたの好み、よく出てくるファイルや人、採用した作法、開いたままの糸口 — そしてあなたも直接編集できます。毎回のセッションで繰り返すかわりに、いつもの好みはプロファイルに一度書いてください。profile-maintenance ポリシーがこのファイルを引き締めます：漠然としたラベルではなく具体的な観察を、書庫ではなく蒸留を。

**`session-logs/`** には、各セッションのやりとりを日付ごとにまとめた markdown のログと、ブローカーの日誌（セクション 9）が入っています。追記だけの履歴です。先週の火曜に何があったかを組み立て直したいときに、眺めるなり grep するなりしてください。

その 2 つを別にすれば、このフォルダはあなたのものです。`glossary/` のサブフォルダ、学んだことのファイル、背景メモ — ここに置いたものは何でも、リードバイザーが参照できます。

### 8.2 io フォルダ

`rness/io/` は、通り抜けるための作業場です：

- **`input/`** — リードバイザーに処理してほしいファイルを置きます。取ってきたウェブページも、markdown に変換されキャッシュされて自動的にここへ降りるので、一度取ったページは永遠に足場になります。
- **`output/`** — 生成物が降りる場所。目を通し、よいものは残し、あとは片づけてください。
- **`cloud-cache/`** — クラウドのモデル枠を使っているなら、クラウドとのやりとりはすべてここに記録されます（セクション 14.2）。クラウドでの仕事も、ローカルに、grep できる紙の跡を残します。

### 8.3 リクエスト：長い仕事はどう生き延びるか

これは駆け足の案内にはあまり出てきませんが、複数のセッションにまたがる仕事を可能にしている仕組みなので、2 分の値打ちがあります。

1、2 ターンでは終わらないことを頼むと、リードバイザーは `rness/requests/` に**リクエストファイル**を開きます：目的、進捗のチェックポイント、道すがらの判断を記した markdown です。こちらから頼む必要はありません。仕事のかたちを見て取るのは、リードバイザーの仕事です。

このファイルが大事なのは、コンテキストウィンドウが埋まるからです。enough は会話の圧力を見ていて — context-management ポリシーに従い — あふれる前に、リードバイザーが状態を、動いているリクエストファイルにチェックポイントとして書きます。オーケストレータの設定によって、enough はそのあと自動でリセットする（メモリ上の会話を消し、チェックポイントから新しく再開する）か、バナーを出して止まり、あなたの用意ができたときにリセットさせます。どちらにせよ、本当の記憶は会話ではなくファイルシステムです：新しいセッションはリクエストファイルの継続ブロックを読んで、物事が立っていたところから続けます。

終わったリクエストは `rness/requests/done/` に移ります — 開いているリクエストで**完了にする**を押すか、リードバイザーに言ってください。done フォルダはリードバイザーからは書き込めないようになっていて、二人が実際に世に出したものの、正直な日誌も兼ねています。

## 9. ブローカーウィンドウ

ブローカーは enough の信頼の錨です。あなたのリードバイザーが行うツールの呼び出しはすべて — ファイルの読み、書き、シェルコマンド、ウェブの取得 — ここを通ります。🔀 のブローカーウィンドウは、それを眺め、調整する場所です。

切り替えは 13 個、いくつかの組に分かれています：

| 切り替え | 何を制御するか |
|---|---|
| trace log | ブローカーが日誌を書くかどうか、そもそも |
| local models only | クラウド枠（OPRO-API）をモデル選択に出すかどうか |
| read_file / write_file / shell brokered | ツールごとのトレース記録。1 つずつで計 3 つ（許可リストは、これに関係なく*常に*効きます） |
| fetch_url enabled | リードバイザーのウェブ取得ツールがそもそも動くかどうか |
| Tor for off-list fetches | 許可リスト外のドメイン：Tor 経由にする（オン）か、断る（オフ）か |
| cache & convert fetches | 取ってきたページを markdown に変換し、`rness/io/input/` にキャッシュするか |
| wikisink tools | あなたのリードバイザーの 4 つの wiki ツールが動くかどうか（あなた自身の 🚰 での閲覧は決して止められません） |
| wikisink live updates | 更新の実行が Wikipedia に接触してよいかどうか（オフ = ローカルの状態だけからレポート） |
| cacheawl tools | あなたのリードバイザーのキャッシュボックスツールが動くかどうか（あなた自身の cacheawl モードは決して止められません） |
| composure tools | あなたのリードバイザーが composure を読み書きしてよいかどうか（あなた自身のキャンバスは決して止められません — セクション 4.9） |
| forge new readvisors | `readvisory` スキルが、仕上がったリードバイザーをあなたのために導入してよいかどうか（セクション 18.5）。オフにすると、聞き取りも下書きもそのまま行われ、最後に置く一歩だけがあなたの手に残ります |

このウィンドウのヘッダーには、enough の中で唯一「誰かの呼び名」を変えるボタンも載っています：**主任リードバイザーの名前を変える**です。小さな欄が開き、1 文字から 24 文字までを受け取り、次に主任が言うことの署名は、もう新しい名前になっています。テーマと同じく、マシン全体の設定です — 主任はひとり、名前はひとつ、どこでも同じ。履歴は残りません：署名はいつでも、いまの名前です。記録を遡って書き換わる改名は、部屋に二人の別人がいたかのように読めてしまうからです。

既定はすべてオンです：既定の姿勢は、リードバイザーにプロジェクトを任せ、紙の跡で誠実さを保つというもの。その跡 — **トレース日誌** — は `rness/knowledge/session-logs/<date>-broker.md` に降ります：ブローカーを通った呼び出しごとに、時刻、ツール、判断、引数、結果。そして切り替えや許可リストが何かを止めたとき、リードバイザーには「何がなぜ止められたか」を書いた明快な拒否メッセージが届くので、黙って失敗するかわりに、あなたに伝えられます。

この表にある設計の原則に気づいてください：リードバイザーのツールを閉じる切り替えは、決して*あなたの*インターフェイスを閉じません。cacheawl tools を切っても、あなたが cacheawl モードから締め出されることはありません。誰かがあなたに代わって保管庫に手を伸ばすことがなくなる、というだけです。

## 10. UI ウィンドウとヘルプ

⚙ の UI ボタンは、表示の設定と参照資料を開きます。そのウィンドウの右上、× の隣に小さな**ヘルプ**ボタンがあります：このマニュアルを読み取り専用で、アプリの中に、ほかと同じ全画面モードとして開きます（セクション 13）。

出口はいまタイトルバーに乗っています：**プロジェクトを閉じる → ホーム**が、ヘルプボタンの隣に。このセッションを終えてホーム画面に戻ります（セクション 2.5）。実行の前に尋ねますし、何を*しない*かも書いてあります — ディスク上のフォルダには触れません。アプリでならたぶん ⌘W に手が伸びるでしょう。このボタンは同じもので、ブラウザで enough を動かしているときは*唯一の*ものです。（閉じるプロジェクトが無いホーム画面には、これはありません。）

ここにはもうひとつ、enough の中からインストールできる唯一のものもあります：**PDF の読み込み**のための **extras** の行です（セクション 7.8）。行にはいまの状態が出ます — 未インストール、インストール中、インストール済み、あるいはインストール済みだが未完了 — そしてインストールボタンは走りながらログをすべてウィンドウに流すので、長いダウンロードは、待ち構えるものではなく眺めるものになります。終われば PDF が開くようになります。再起動は要りません。

### 10.1 テーマ

enough には 4 つ同梱されています：**Enough Default**（深い青紫のダーク）、**Pastel**（淡い紙。Terminal の「Man Page」配色の精神で）、**Wireframe**、**Darknest**。切り替えは即座で、インターフェイスのアイコンはすべて、明るい版と暗い版をその場で導き直します。

テーマは焼き付けられていません。`~/enough/config/ui.json` に、名前の付いた色の値の塊として置かれ、それぞれが CSS のカスタムプロパティとして当てられます。既存の塊をコピーして名前を変え、色を変えて読み込み直せば、あなたのテーマがドロップダウンに入ります。ファイル先頭の `_doc` の塊が、各キーを説明しています。

### 10.2 フォント

同じ型です。同梱の 4 組 — SF Mono、システムのサンセリフ、Georgia のセリフ、Courier — と、同じ `ui.json` へのあなた自身の追加を歓迎します。大きさについては、下のダイヤル 2 つを（セクション 10.3）。そしてブラウザのタブでなら、昔ながらのブラウザのズーム（⌘+ / ⌘−）も、その上から問題なく効きます。

### 10.3 大きさ — ui scale と text scale

ここでの答えはずっとブラウザのズームでした。ブラウザに包まれていないデスクトップアプリが現れるまでは。そこで enough は自前のものを育て、ついでにもう一歩よくすることにしました：ひとつではなくふたつのダイヤルを、テーマの下の行に。

**ui scale** は*すべて*の大きさを変えます — アイコン、ラベル、サイドバー、チャット、まさにこのウィンドウ — 0.1 倍刻みで。**text scale** は目の前のドキュメントだけを変えます：read/edit のページ、wikisink の記事、ファイルのプレビュー、リファレンスモードのこのマニュアル。ふたつは掛け合わさり、互いの邪魔をしません：0.9 倍のインターフェイスに 1.5 倍の文字は、原稿を読むのにまったく理にかなった構えですし、その逆は、午後の視界から原稿を追いやるのにまったく理にかなった構えです。どちらかの数字をクリックすれば、そのダイヤルだけが 1.0 倍に戻り、もう一方はそのままです。

どちらも**プロジェクトフォルダごとに**覚えられます — 部屋の向こうから読む原稿と、机で開くメモは、それぞれ自分の大きさを持ち、どちらも相手を引きずりません。ホーム画面は素の大きさのままなので、そこにダイヤルは出ません。

限界はあなたの画面に合わせて呼吸します：いまどきのディスプレイでおよそ 0.5 倍から 2 倍。小さなウィンドウでは締まり（インターフェイスがインターフェイスでいられるだけの余地を、いつでも残すために）、とても大きくとても密な画面では緩みます（2046 年の 8K の壁なら 3 倍まで）。ひと刻みで線を越えるとき、ボタンは身をよじり、数字は赤く脈打ち、何も変わりません — それが、エラーメッセージのすべてです。

### 10.4 言語

インターフェイスは 6 つの言語を話します：英語、フランス語、スペイン語、ドイツ語、中国語、日本語。同じ行の **ui language** ドロップダウンが、目に見えているものすべて — ラベル、ツールチップ、`(?)` バブル、このマニュアル — をその場で切り替えます。再起動は要りません。選択はマシン全体のもので、テーマと同じように `ui.json` に乗るので、ホームもすべてのプロジェクトも同じ言語で揃います。

これがあえて*触らない*もの：あなたのファイル、あなたのチャット、あなたのリードバイザー。リードバイザーとは好きな言語で話してください — ローカルのモデルはこの 6 言語のどれでも心地よく振る舞います — が、enough は自分の足場（スキル、パラダイム、プロンプト、プロジェクトファイル）を英語のままにします。モデルがいちばん確かに読むのがその言語だからです。生成されるものの一部も英語のままです — *あなたの*マシンに入っているものから生で引かれる一覧、たとえばバブルの中のスキルや、ファイル形式の表。そして、新しい英語のラベルに翻訳が追いつけていないところでは、空白ではなく英語が出ます：見た目は劣りますが、壊れてはいません。見つけたら、それはバグです — [enough.support](https://enough.support) が歓迎します。

### 10.5 チートシート

UI ウィンドウの中に、参照が 2 列。

**キーボードショートカット：**

| キー | 動作 |
|---|---|
| esc | いちばん上のモードを閉じる |
| ⌘ \ | サイドバーの表示／非表示 |
| ⌘ / | リードバイザーパネルの表示／非表示 |
| ⇧ ⌘ / | リードバイザーパネルにウィンドウ全体を渡す |
| ⌘ K | チャット入力にフォーカス |
| ⌘ Enter | メッセージを送信 |
| shift Enter | 送信ではなく改行 |
| ⌘ B / I / U | 選択範囲を太字／斜体／下線（読む面） |
| ⌘ S | 保存（編集の面） |
| ⌥ クリック | ファイルツリーのコンテキストメニュー |

（Mac 以外のキーボードでは：⌘ は Ctrl、⌥ は Alt。）

これらはインターフェイス自身が扱うショートカットなので、アプリでもブラウザのタブでも同じように効きます。アプリはメニューバーから、自分のものを 2 つ足します：**⌘W** はプロジェクトを閉じてホーム画面に戻り（セクション 2.5）— もうウィンドウは閉じません — **⌘Q** は、これまでどおり終了します。

**markdown のチートシート：** 見出し、リスト、リンク、コード、引用 — markdown にまだ慣れきっていない人のための、ひととおりの早見表です。慣れておく値打ちはあります。enough はどこでもそれを母語として話すので。

### 10.6 手元のヘルプ（IHH）

インターフェイスのあちこちに散らばる `(?)` バブルが、組み込みのヘルプです：概念 1 つにバブル 1 つ — スキル、リードバイザー、リードバイザーパネル、パラダイムの選択、composure とそのモジュールとツール、ジャーナル、rness、io、knowledge、cacheawl、wikisink、モードの仕組み、変換されたドキュメント、等々 — それぞれに **what**、**how**、**ideas** の一覧が付いています。スキル、リードバイザー、パラダイムのバブルは、*あなたの*プロジェクトに実際に入っているものを並べますし、変換されたドキュメントのバブルは、アプリ自身の形式レジストリからファイル形式の表を引いてきます — すべて生成されたてなので、ヘルプが現実とずれることがありません。（このマニュアルのセクション 7.2 に出る表も、同じ出どころです。）

バブルは、UI ウィンドウの「ヘルプ (?) バブル」チェックボックスで、プロジェクトフォルダごとに制御します。新しいフォルダでは既定でオン、設定はフォルダごとに残ります — だから、毎日の相棒になった歴戦のプロジェクトは静かにしていられて、生まれたての実験は補助輪を付けたままでいられます。

ヘルプさえカスタマイズできます。中身は markdown ファイル 1 つ（`enough/static/help-docs.md`）にあり、それを編集すればバブルが変わります。

## 11. Wikisink

wikisink（🚰）は、英語版 Wikipedia のオフラインコピーをあなたのマシンに置きます：アプリの中で読めて、全文検索でき、リードバイザーも読めて、注釈を付けられて、変更レポートつきで好きなときに更新できます。セットアップが済めば、インターネットはまったく要りません。

### 11.1 セットアップ

🚰 を初めてクリックすると、ウィザードが 3 つのことを尋ねます。

1. **サイズ。** アーカイブは Kiwix のビルドで、断りがなければテキストのみです：

   | 版 | 中身 | おおよそのサイズ |
   |---|---|---|
   | 上位 100 万記事 *(既定)* | いちばん読まれている 100 万件 | 約 16 GB |
   | 英語版 Wikipedia のすべて | 全記事 | 約 49 GB |
   | 上位 5 万 | いちばん読まれている 5 万件 | 約 2.1 GB |
   | 上位 5 万 mini | 上位およそ 5 万件、導入部だけ | 約 320 MB |
   | Simple English | Simple Wikipedia のすべて | 約 950 MB |

2. **置き場所。** 既定は `~/enough/wikisink`。どのフォルダでも、外付けドライブでも構いません。アーカイブのサイズに加えて 5% ほどの余裕を残しておいてください。
3. **確認。** ダウンロードは中断から再開でき、終了しても生き延びます — 同じウィンドウから一時停止、再開、中止ができ、そのあいだも enough のほかの部分は動き続けます。

アーカイブは `.zim` ファイル 1 つで、その場のまま読まれます。展開されることはなく、ファイルマネージャーを散らかすこともありません。**複数のインストール**を登録することもできて — たとえば外付けドライブに全体、内蔵ディスクに小さいもの — ⚙ のインストール一覧で切り替えられます。ドライブを外しても何も壊れません：そのインストールが「届きません」と出るだけで、ドライブが戻れば戻りますし、あなたのコメントと上書き設定は、どのアーカイブとも独立に暮らしています。

入れてしまえば、🚰 が読み手を開きます：戻ると進む、検索欄での見出し候補の即時表示（Enter でアーカイブ全体の全文検索）、🎲 のランダム記事のサイコロ、そして今読んでいるものがアーカイブのスナップショットなのか（`ZIM <date>`）、更新の実行で得た新しいコピーなのか（`live <date>`、つまり「最新」）、保護されたコピーなのか（`preserved`、つまり「保護」）を教える出どころのバッジ。内部リンクはアプリの中に留まり、外部リンクはブラウザで開きます。一節を選べば、リードバイザーパネルのメッセージ欄の上にチップとして現れ、次のメッセージと一緒に渡る用意が整います（セクション 5.2）。

**新しいスナップショットのピル。** Kiwix はこれらのアーカイブを定期的に作り直しますし、あなたがそれを探しに行く必要はありません。*あなたの*版に新しいビルドが出ると、読み手のツールバーに小さなピルが現れます — `newer snapshot: <date> · <size>`。押してサイズを確かめれば、その場での入れ替えが走ります：同じ保存先フォルダに、先にダウンロードして、終わってから初めて差し替え、古いファイルはそのあとで消されます。その前ではありません。あなたのコメント、保存、🛡 の上書き設定はそのまま渡ります。どれもアーカイブの中には暮らしていないからです。ピルはダウンロード中は進捗の表示になり、それから消えます。enough がこれを確かめるのは 1 日に多くて 1 回、読み手が描画している最中には決してせず、オフラインのときは黙っています — オフライン Wikipedia の機能にとって、それがふつうの状態だからです。同じ入れ替えは遠回りの道、⚙ のインストール一覧からもできますし、リードバイザーの wikisink の実行もそれを報告します（セクション 11.3）— けれどボタンを押すのは、いつでもあなたです。

### 11.2 記事を保存し、鍵をかける

**保存。** 保存ボタンは行き先を 2 つ出します：このプロジェクトの `wiki/` フォルダか、すべてのプロジェクトで共有される、マシン全体の wiki キャッシュボックス（`~/enough/cacheawl/wiki/`）。どちらでも、保存 1 件はフォルダ 1 つ — `article.html`（アーカイブが持っていたままの、1 バイトも違わない記事）と、題名、出典 URL、取得日、CC BY-SA のライセンス行を載せた `_manifest.md`。保存された記事はどれも自分を説明できます。つまり、その文章がいつかあなたの発表するものに入っても、必要な帰属表示はもう隣に座っているということです。ツリーで保存された `article.html` をクリックすれば、アーカイブに手が届かないときでも、読み手で完全なまま開きます — インフォボックスも表も。保存をやめるには、ツリーでそのフォルダにカーソルを置き、現れる 🗑 をクリックしてください。

保存は*あなたの*ためのものです：オフラインのさらにオフラインのコピー、発表のための帰属表示。リードバイザーに保存は要りません — ツールが、アーカイブの中のどの記事でも、きれいなテキストとしてその場で読めます。

**コメント。** 文章を選んで 💬 を押すか、ツールバーの 💬 で段落単位のメモを付けます。スレッドは 🗨 のパネルに暮らします：返信、解決、再開、その場所へ跳ぶ。コメントは保存ファイルではなく*記事*に付き、記事の更新もゆるやかに劣化しながら生き延びます。まだ残っている文章には**そのまま留まり**ます。編集で消えた文章は、段落に**貼り直され**ます。段落ごと消えたときは、パネルの中で**宙に浮いた**まま残ります — 印は付きますが、自動で消えることはありません。

**鍵（削除の上書き設定）。** ライブの Wikipedia が、あなたの頼りにしていた記事を消してしまうことがあります。典型例は、品質ではなく「特筆性」を理由に切られたニッチな話題です。🛡 ボタンは、手元のコピーを永久に保ちます — それ以降は `preserved`（保護）のバッジ付きで供され、今後の更新からは外れ、検索にはかかり続けます。更新の実行のレポートは、検出した削除に実際に点数を付けるので（特筆性めいた理由は「疑わしい」、著作権侵害は「まっとう」）、どの削除に目を向ける値打ちがあるか分かります。そして上書きは、意図してあなただけのものにしてあります：リードバイザーは 🛡 を勧めることはできても、押すことは決してできません。

### 11.3 wikisink の更新と、変更レポート

「wikisink」は動詞でもあります。保存した記事、コメントした記事はすべて*監視中*で、リードバイザーに「wikisink を走らせて」と頼めば（あるいはリードバイザーが自分の `wikisink` ツールを呼べば）、監視中の一式をライブの Wikipedia と突き合わせ、報告してきます。1 回の実行は：

1. 変わっていた監視記事を、ローカルのオーバーレイに取り込んで更新します（バッジが `live` に変わります）。
2. **編集の急増**に印を付けます — 監視記事が急に 1 日に何十回も編集されているとき、加えて Wikipedia 全体での急増候補も。
3. 日次の**上位 1000 の閲覧数**を前回と比べます：上がったもの、下がったもの、新顔、脱落、そして監視記事の閲覧の傾向。
4. 監視中または最近見た記事の**削除**を確かめ、疑わしさに点数を付けます（セクション 11.2）。
5. **新しい基盤スナップショット**が出ていれば、それを書き添えます。数 GB の基盤アーカイブを入れ替えるかどうかは、いつでもあなたの判断です — 読み手のツールバーのピルを押すか（セクション 11.1）、⚙ のインストール一覧を使ってください。これを入れ替えるリードバイザー用のツールはありません。

レポートは markdown としてチャットに届き、上限のない完全版は wikisink の状態フォルダの下に残ります。実行は Wikipedia に対して礼儀正しく — まとめて、正直な User-Agent で — 中断されても再開でき、`report-only` の実行なら更新の段階を飛ばします。すべてを支配するのはブローカーの切り替え 2 つ：ひとつはリードバイザーの wiki ツールをまるごと閉じ、もうひとつは実行を完全にオフラインへ強制します。

## 12. Cacheawl

cacheawl は、マシン全体で共通のテキスト保管庫です：ずっと持っておきたくて、どのプロジェクトからも手を伸ばしたいものの場所。`~/enough/cacheawl/` にあり、どのプロジェクトのファイルツリーにも現れず、あなたのすべての enough で共有されます。（以前の enough を使っていたなら、古い `infoworld/` の書庫は 0.1.6 の初回起動で cacheawl に溶け込みました — `personal/`、`public/`、`wiki/` が、最初の 3 つのキャッシュボックスになったのです。失われたものはありません。）

### 12.1 キャッシュボックスと、その merirmaid の図

**キャッシュボックス**は保管庫の最上位フォルダで、2 つの型があります。**素のボックス**は、あなたが自分で整理する、ずっと持っておきたいテキストのためのもの：参照メモの `personal` ボックス、発表した文章の `press` ボックス、あなたに合う構成なら何でも。**キャッシュ複製**は、あるソース — ローカルのフォルダ、web サイト、Wikipedia の記事群 — から*取り込まれた*ボックスで、どこから来たかを覚えています。

どのボックスも **merirmaid の図**を持っています：`_cachebox.merirmaid` は、ボックスの構造を映した生きた図で、中身が変わるたびに作り直されます。ダブルクリックすれば、ボックスのかたちがひと目で分かります。この図は*ミラー*で、設計として読み取り専用です。現実を映しているからで、図を変えたければボックスを変えてください。安上がりな突き合わせの処理が、enough の背中越しに Finder からファイルを落としたときでも、ミラーを正直に保ちます。

上部バーから **cacheawl モード**を開くと 2 ペイン表示になります。片側にプロジェクト、もう片側に保管庫。ドラッグでファイルをコピー、shift ドラッグで移動、shift クリックでコンテキストメニュー、そしてダブルクリックでどのファイルもその自然なモードで開きます — girraph、merirmaid、read/edit、wiki の読み手 — 保管庫からまっすぐに。

### 12.2 キャッシュボックスと、ローカルや web のドキュメントを捕まえること

cacheawl モードの**取り込みバー**（あるいは、ふつうに会話で頼むこと）が、外の材料をボックスへ捕まえます：

- **ローカルのパス** — メモやドキュメントのフォルダを、保管庫に複製します。
- **web サイト** — ドキュメントや参照のサイトを、選んだ深さまで（上限はおよそ 500 ページ）クロールして、ローカルの markdown として保ちます。web の取り込みは、あなたの取得の切り替えと許可リストに従います。Tor 経由も含めて。
- **Wikipedia** — ある話題の記事を（上限はおよそ 200 件）wikisink のアーカイブから引き出して、プロジェクトに縛られない永続的なテキストにします。

取り込みは裏側で走ります。ボックスはすぐに「取り込み中」の状態で現れて、様子を眺められますし、失敗した取り込みは、終わったふりをせずに失敗したと言います。リードバイザーのキャッシュボックスツール（一覧、作成、取り込み）はブローカーの cacheawl の切り替えで制御されます。あなた自身の cacheawl モードの利用は、決して制御されません。

なぜそうするのか。プロジェクトフォルダは作業場で、cacheawl は書庫だからです。あるフレームワークのドキュメントを一度取り込んでおけば、これから先のどのプロジェクトも、オフラインでそこに足場を置けます。長く効く参照メモをボックスに置いておけば、これから話すどのリードバイザーもそこに手が届きます。成果物を仕上げてボックスへ移せば、それを生んだプロジェクトより長生きします。

## 13. 複数のモードを重ねる

enough の全画面モード — read/edit、girraph、merirmaid、wikisink、cacheawl — は、互いを置き換えません。紙を重ねるように**積み重なり**ます。cacheawl を開き、ボックスの中から girraph を開き、その上にメモのファイルを開く：3 段の深さで、ひとつずつ閉じれば、その下のものが置いてきたままの姿で現れます。同じスクロール位置、同じ潜り方、同じ未保存の編集で。

上部バーは、開いているモード 1 つにつき四角い印を 1 つ出します。新しいものが左です。それぞれに、そのモードだけを閉じる小さな赤い × のリボンが付いていて、埋もれたものにも効きます。埋もれたモードの印をクリックすれば、ほかを乱さずにそれだけを最前面に上げられます。最後のひとつが閉じれば、composure に戻っています — 空になったスタックです（セクション 4）。

**土台の四角。** 印の並びの右端には、いつでもそこにあり、リボンを持たないものが 1 つ座っています：composure です。閉じるものがありません。床だからです。これをクリックするのが、セクション 4.8 の**覗く**仕草です — 積み重なったモードがすべて隠れ、キャンバスが見え、もう一度クリックすれば（あるいはほかの印をクリックすれば）、何ひとつ変わらないまま全部が戻ってきます。

**リードバイザーパネルは、そもそもスタックの中にいません。** スタックの隣に立つ列です（セクション 5）。ですからドックに入ったパネルと 3 段のモードは、互いの邪魔をせずに共存しますし、ドックにあるパネルを esc が閉じることはありません。

**esc の順番。** esc は*いちばん内側のものから抜ける*という意味で、いちばん内側のものは、いつもモードとはかぎりません：

1. 開いているモーダル。自分で esc を処理します。
2. 確認のオーバーレイ。
3. いま打ち込んでいる最中のテキスト欄 — ここで esc はわざと効きません。うっかり押しても、書きかけのメッセージが捨てられないようにです（検索欄だけは例外で、まず検索語を消し、それから手を放します）。
4. 開いている composure のメニュー。
5. 全画面のリードバイザーパネル。ドックに戻ります。
6. 覗いている状態。積み重なったモードを戻します。
7. そしてようやく、いちばん上のモード。

知っておくと便利なことが 2 つ：

- ミニの read/edit パネルは、全画面モードの*上*に浮きます。だから、たとえば下で girraph モードの仕事をしながら、肘のあたりにドキュメントを置いておけます。
- スタックのどこかにすでにあるモードを開いても、複製はされません。前に開いたものへ狙いを付け直し、それを上げます。

## 14. モデルウィンドウ

上部バーのモデルバッジが、モデルウィンドウを開きます：いまどの頭があなたに答えているのか、ほかに何が使えるのか、そして — 望むなら — クラウドの枠。

### 14.1 ローカルモデル：概観と使い分けの勧め

対応するローカルモデルは 7 つ — そしてこのウィンドウは、いまやそれらをインストールする場所でもあります。まだ持っていない行には、ダウンロードのサイズと、*このマシン*のメモリと空き容量に照らして計算された実現可能性の判定が出ます：✓ は余裕、~ はぎりぎり、✗ は勧められません。ダウンロードは進捗バー付きで走り、終了しても生き延び（止まったところから再開します）、すでに受け取った分を失わずに中止できます。インストール済みのモデルはクリックで切り替わり、いま動いているもの以外は、ディスクを取り戻したくなったときにその行から削除できます。

| 愛称 | モデル | ディスク | 最小 RAM | 備考 |
|---|---|---|---|---|
| **G40-04** | Gemma 4 4B (E4B) | 約 5.4 GB | 8 GB | いちばん小さい。どこにでも入る。既定 |
| **Q35-09** | Qwen3.5-9B | 約 5.9 GB | 10 GB | 均衡のとれた中型。MTP による投機的デコード |
| **G40-12** | Gemma 4 12B (QAT) | 約 7.0 GB | 12 GB | 量子化を織り込んで学習済み。16 GB の甘い場所 |
| **G40-26** | Gemma 4 26B MoE (4B active) | 約 15.6 GB | 20 GB | 大型の質を、中型の速さで |
| **Q36-27** | Qwen3.6-27B dense | 約 17.1 GB | 22 GB | 場数を踏んだ重量級。MTP つき。息が長い |
| **Q38-04** | Qwen3.8 27B (4-bit) | 約 19 GB + draft 1.7 | 24 GB | 最新の Qwen。自分の投機を自分で下書きする |
| **Q38-16** | Qwen3.8 27B (16-bit) | 約 54 GB + draft 3.2 | 64 GB | 完全精度。いちばん大きな Mac のために |

名前のちょっとした落とし穴をひとつ、つまずかないように：Q38 の 2 つでは、ダッシュのあとの数字は**量子化のビット幅**であって、パラメータ数ではありません — Q38-04 と Q38-16 は、4 ビットと 16 ビットの精度で動く、*同じ* 270 億パラメータのモデルです。（G40-04 は、古い流儀の名前なので、本当に 40 億パラメータのモデルです。）ウィンドウのラベルがそこを書き下しているので、愛称のほうが説明する必要はありません。

目安。8〜16 GB のマシンなら G40-04 で暮らし、余裕ができたら G40-12 を次の一歩に — 量子化を織り込んだ学習のおかげで、そのサイズにしては珍しくきれいな出力をします。32 GB なら G40-12 か Q35-09 が心地よい常用機で、難しい統合の仕事には G40-26 か Q38-04 を。64 GB 以上なら Q38-04 か Q36-27 を既定にして、もう考えないでください。Q38-16 はそれ自体がひとつの分類です：本気の統合メモリと約 57 GB の空き容量を持つマシンのための、完全精度の重量級 — Mac Studio があって天井が見たいなら、これが天井です。コンテキストウィンドウは RAM に合わせて自動で伸び縮みし（モデルごとに RAM 階層別の妥当な既定が付いていて、設定で上書きできます）、Qwen のビルドは追加の速さを無料でくれる Multi-Token Prediction を積んでいます：Q35/Q36 はモデルファイルに内蔵、Q38 の 2 つは小さな相棒の「draft」ファイル経由で、これは一緒に自動でダウンロードされます。

ターミナルからインストールした人へ、もうひとつ。モデルはどの llama.cpp でも*ダウンロード*できますが、*動かせる*のは十分に新しいビルドだけです。お使いのものが新しいモデルに対して古すぎるときは、ウィンドウがそう言い、直し方（`brew upgrade llama.cpp`）を教えます。アプリでインストールした人が、この注意書きを見ることはありません — アプリは自前の推論エンジンを積んでいます。

モデルを切り替えると、ローカルの推論サーバーが再起動し、メモリ上の会話が消えます。ファイルもログもリクエストの状態も残ります。切り替えで失うのはチャットのスクロールバックであって、仕事ではありません。

### 14.2 OpenRouter への対応（OPRO-API の枠）

enough はローカル優先であって、ローカル専用ではありません。5 つめのモデル枠、**OPRO-API** は、OpenRouter を通してクラウドのモデルへつながります。既定はオフ、有効にするにはあえて手間がかかるようにしてあり、取引の中身については正直です：あなたのプロンプトと出力はマシンを出ます。その代わりに、最前線のモデルの力と、ときには、同じ力のローカルモデルが要求するハードウェアと電気より安い費用が手に入ります。

有効にするには：ブローカーで **local models only** をオフにし、モデルウィンドウで OPRO-API をクリックします。3 画面のウィザードが案内します — 明示的な確認のチェックボックスが 3 つ（アカウントを持っていること、課金を理解していること、プライバシー上の取引を理解していること）、それから API キー、そして生きた疎通確認。キーは macOS のキーチェーンに保管されます。どのファイルにも書かれることはなく、リードバイザーには読む手立てがなく、ブローカーはそれを取りに行こうとするように見えるだけのシェルコマンドさえ断ります。確認が済めば、OPRO-API はほかのモデルと同じように選べるようになり、その設定パネルから再テスト、キーの更新、キーの削除、そして好きな OpenRouter のモデル id を選べます。

クラウドの利用に説明責任を持たせているものが 2 つ：

- **すべてがローカルにキャッシュされます。** クラウドとのやりとりはすべて、トークン数と索引つきで `rness/io/cloud-cache/` に書かれます — あなたのローカルのリードバイザーが、あとから読めるローカルの紙の跡です。
- **`cloud_pipeline`** は、大きな仕事をクラウド枠へまとめて流させます — 最大 200 段階、段階ごとのキャッシュ、任意で段階ごとの要約、そして最後の取りまとめ — 結果は会話にあふれさせるかわりに、ディスクへ書かれます。「12 章分の要約をぜんぶ下書きするクラウドパイプラインを」と頼めば、重い持ち上げは会話の外で、すべて記録されながら行われます。

## 15. パラダイム

パラダイムはリードバイザーの思考の枠組み — 仕事がどう進むかについての、交戦規定です。有効なのは常にちょうど 1 つ（サイドバーの上部に出ます。● をクリックで切り替え）で、有効なパラダイムの全文が毎ターン、システムプロンプトに乗ります。リードバイザーは他のパラダイムの 1 行の目録も見ているので、あなたの依頼がよそでもっとうまく扱えそうなときは、切り替えを提案 — あるいは実行 — できます。リードバイザーからの切り替えは、何も奇をてらったものではありません：そのパラダイムの名前を `rness/active-paradigm` に書き、そうしたとあなたに伝えるだけです。

### 15.1 default

自由なかたちの会話、声はひとつ。たいていの仕事のためのパラダイムであり、別のパラダイムのほうが合う瞬間を見張っている案内役でもあります。いつも守る作法もここが抱えています — たとえば「黄色のところ」があなたのハイライトを指すと知っていること。

### 15.2 text-planning

文章の前にある、長い助走路のために：小説、エッセイ集、ノンフィクションの本、あるいは宣言を、「何か書きたい気がする」から使える計画にまで持っていきます。リードバイザーはプロジェクトのルートに、あなたと一緒に計画のドキュメントを 1 つ作ります — 辛抱強く、繰り返し、必要なだけのセッションをかけて — そして頼まれれば、セクションごとの*足場*を作ります：構造の手引き（拍、見出し、声の覚え書き、語数の目安）で、それをあなた自身が文章にふくらませます。このパラダイムを定めている決まりは：**あなたの文章は決して書かない。** 足場に入るのは構造だけです。あなたの声はあなたの声のまま。（`analyzer` または `memoir-dialectic` スキルと一緒に働きます。回想録は memoir-dialectic に渡されます。あちらがそのために作られたものだからです。）

### 15.3 translation

オフラインの翻訳を、一等市民の能力として宣言します。`translator` スキル（セクション 18.7）と組みます：依頼が人間の言語のあいだで文章を動かすものだと、リードバイザーはここへ切り替え、スキルがオフなら、何を逃しているかを教えます — そしてあなたがオンにするまで言い続けます。スキルをオンにすれば、アカウントも、レート制限も、ネットワークへの依存もない、約 419 言語のローカル翻訳者が手に入ります。

### 15.4 workflow-design

enough そのものについてのパラダイムで、仕事の中で働くのではなく、仕事のやり方を作ったり変えたりしているときに有効になります：新しいスキル、新しいリードバイザー、新しいパラダイム、AGENT.md や MOTIVATION.md への編集。ここでのリードバイザーは、設計における思慮深い共同作業者としてふるまいます — 作る前に確かめる問い（範囲は？　名前は？　どんなときに動く？）、最初の思いつきがもっと鋭くなりそうなときの代案、そして作るたびに追いかけるリクエストファイル。仕事のやり方の変更は、それを生んだ会話より長く生きるからです。セクション 3 を本当のものにしているのが、このパラダイムです。

## 16. リードバイザー

**リードバイザー**は、手もとに置いておける判断です：自分の `AGENT.md` と `MOTIVATION.md` を持ち — あなたの主任リードバイザーを定めているのと同じ 2 つのファイルです — 問題をある一通りに読む、その読み方に絞られています。サイドバーの**リードバイザー**の区画で、プロジェクトごとにオン／オフします。

リードバイザーパネルのいちばん上にいるのが、あなたの**主任リードバイザー**で、箱から出したままの名前は **Ed** です。その名前はあなたが変えられます — ブローカーウィンドウのヘッダーにある**主任リードバイザーの名前を変える**です（セクション 9）。主任がほかと違う種類のものだ、ということではありません。誰を指名するでもなく訊いたときに答えるのが、その人だというだけです。

**何人いても、声はひとつ。** 3 人オンにしても、答えが 3 つ返ってくるわけではありません。ふだんの会話では、その人たちの視点、専門、用心が、主任の言うことに折り込まれます — ひとつの声、ただし何人かでできた声です。ある視点がその話を引っぱっているときは、たいていどれなのかを教えてもらえます。それぞれの名前で、順番に、別々に話してほしいのなら、それが**議事会**です（セクション 17）。

**出どころは 3 つ**で、サイドバーの行がどれなのかを言います：

- **shipped** — 下に挙げる 2 つ。ほかの同梱部品と同じように、enough 自身の既定へのリンクとして来ます。
- **global** — `~/enough/readvisors/` に入っているもの。あなたのもので、このマシンのすべてのプロジェクトから見えます。勝手に作られることはありません。何かがそこにリードバイザーを置いた、その最初のときに現れます。（書き込めるのはこちらです。デスクトップ版の中にある defaults フォルダは封じられています。）
- **project** — このプロジェクトの `rness/readvisors/` にある本物のフォルダで、このプロジェクトだけのものです。

同じ名前の global と shipped のリードバイザーは、プロジェクト専用のものに負けます。そのプロジェクト自身のコピーがいつでも勝ちます — 「カスタマイズ」に意味があるのは、そのおかげです。

**取り除く。** 同梱でない行には × が付いています。ファイルを消すので、先に確認します：プロジェクトのリードバイザーならそのフォルダが消え、global のものなら `~/enough/readvisors/` から、そしてこのプロジェクトの一覧から消えます。enough が同梱したものは、この方法では取り除けません — 消したところで、更新がまた置き直すものしかそこにはないからです。そして取り除かれた名前は、プロジェクトのオフ一覧からも消されます。あとから同じ名前のリードバイザーが来たときに、わけもなくオフになっていることのないようにです。

### 16.1 block-breaker

書けなくなることの専門家で、実在の書き手が「どうやって行き詰まりを溶かすか」に答えたものから蒸留されました — まさに `readvisory` スキル（セクション 18.5）がすることで、その出来上がりがどんなものかの実例が、これです。処方の前に診断します — アイデアが尽きた、度胸が尽きた、構造が尽きた、許しが尽きた、はそれぞれ別の問題です — そのうえで制約、反復による発想（「10 通り出してから削る」）、奇妙な捉え直し、そして望まれれば実際の次の一文へ手を伸ばします。徹底して敗北主義に与しません。その核にある信念：自ら望んで書いている人にとって、行き詰まりはいつでも解けます。規則は誰かがこしらえたものであり、治し方もこしらえられるからです。

### 16.2 open-skeptic

「啓発可能な悲観論者」です：AI が強いところには心から熱を上げ、売り込みが過ぎるところには職業的に疑いをかけます。これから仕事のやり方を作ろうというときに呼び出して、失敗の筋道を早いうちに名指ししてもらってください。人間の経験を AI に再現させることに、人の目を通さない誤差の連鎖に、そして流暢な自信が専門性の仕事を代行することに、押し返します — その一方で、集める機械として、知識の義肢として、稽古の相手としての AI には声援を送ります。証拠があれば意見を更新します：うまくいっている仕事のやり方を見せれば、そう言います。あっさりと。

### 16.3 自分のリードバイザーを立てる

例は 2 つ、かたちはひとつ。どのリードバイザーも、同じ見出しを持つ同じ 2 枚の markdown ファイルでできています：`AGENT.md` は、サイドバーに出る表示名で始まり、それからこの人がどう考えるかを述べます。`MOTIVATION.md` は、何を大事にし、何から守り、どこで間違えるかを言います。このかたちが確かめられるのは導入のときで、読み込みのときではありません。ですから、何年も前に手で書いたリードバイザーも、当時のまま動きます。

2 つのファイルは自分で書けます。用意されている道は **`readvisory` スキル**（セクション 18.5）で、実在の人の判断から 1 人を組み上げます。質問をすることによってです — あなた自身にその場で、あるいは、助言を手もとに置いておきたい誰かに、送った質問票で。リードバイザーは、足りていない読み方を足すいちばん安上がりな方法です：ソクラテス式のラバーダック、コンプライアンスの査読者、想定読者、そして自分では見えなかったものをいつも捕まえてくれた、あの編集者。

## 17. 議事会

**議事会**は、あなたのリードバイザーたちが、ひとつのことについて順番に、書きながら、それぞれの名前で考える composure です。そのようすを、あなたは見ています。これはセクション 16 のもう半分です：ふだんはひとつの声にたたまれている同じリードバイザーたちが、たたまれずに開かれ、記録に残る形で意見を違えます。

ふつうの composure なので、セクション 4 の内容はすべてそのまま当てはまります。**議題**が上に置かれ、その下に発言が 1 枚ずつカードとして降りてきます。カードの見出しは、誰が言ったかと、何回目の発言か。色は話し手ごとに分かれます — 主任は紙、あなたは青、それぞれのリードバイザーはその議事会のあいだ自分の色、結論はインクです。列は伸びるにつれて自分で整い直します。あなたがどれだけあちこち動かしたあとでもです。

発言は議事会のもので、あなたのものではありません。動かすことも、見た目を変えることも、コメントを付けることもできますし、引いて全体を面の列として読むこともできます — けれど書き換えることはできません。どのリードバイザーにもできません。編集できる記録は、記録ではなく提案です。議題のほうはふつうのモジュールのままで、編集できます。

### 17.1 立ち上げる

**council** の form から新しく作ると、議題のための 4 つの欄が並んだ組み立てカードが出ます：

- **入力** — 決めようとしていることそのもの。問いをひとつ、できるかぎり鋭く。
- **進め方** — どう回してほしいか。「2 ラウンド回して、それから決めてください。」
- **制約** — 触ってほしくないこと。「本文は書き換えないでください。」
- **ほしい出力** — 17.3 をご覧ください。

次に、部屋にいる顔ぶれです。チェックリストには、あなたの主任リードバイザー、このプロジェクトで有効にしてあるリードバイザー全員、そして**あなた**が並びます。要らない人のチェックを外してください。上限は 12 人。同じ名前の参加者が 2 人いてはいけません。発言は名前で誰のものかを示すので、Nadia が 2 人いるのは議事会ではなく、取り違えだからです。**最大ラウンド数**は既定で 3、1 から 20 まで選べます。

**招集する**で始まります。

### 17.2 動かす

操作は 6 つ。どれも、書いてあるとおりのことをします。

- **次の発言** — 次の番の人から、発言をひとつ。
- **1 ラウンド回す** — 順番がひと回りするまで発言を進めます。招集した直後に押せば全員、あと 1 人ぶん残っている状態で押せば 1 人です。
- **最後まで回す** — 決めた上限のラウンド数に届くまで、裏側で回しつづけ、進み具合を知らせます。
- **一時停止** — いま書かれている発言が終わったところで止まります。書きかけの発言が捨てられるほうが、段落がひとつ余分に増えるより、ずっといやな驚きだからです。
- **議題** — 組み立てカードに戻ります。全員が何をもとにしているかを読み直したり、結論を出す前に出力を変えたりするためです。
- **結論を出す** — 最後の発言です。17.3 で扱います。

発言はその場で流れてきます。列のいちばん下に、話し手の名前と発言番号を載せたカードが現れ、言葉が届くにつれて埋まっていき、発言が終わるとほんもののモジュールに落ち着きます。順番は、主任とリードバイザーたちを一覧に並んでいる順に回ります。ぐるりと回り、一周したところで 1 ラウンドが閉じます。

**いつでも、あなたから何か言えます。** 議事会のいちばん下の入力欄があなた自身の発言を受け取り、ほかの誰とも同じようにカードとして入ります。色は青です。誰も話していなければすぐに載りますし、発言が流れている最中なら次の枠を取り、そのときまで待機中として見えます。どちらにしても、これは*ひとこと挟む*ことであって、順番の組み替えではありません。番だったリードバイザーは、やはり次に話します。

**そのあいだ、リードバイザーパネルは閉じたままです。**切り替えは押せなくなり、理由がツールチップに出ます（セクション 5.1）。議事会とチャットは 1 つのモデルを分け合っていて、そのモデルは 1 つしかありません。チャットの発言は、議事会の後ろに並ぶか、議事会と取り合うかのどちらかになってしまいます。逆も同じです：主任がチャットで答えている最中に議事会の操作を押すと、黙って待つかわりに、そう書かれた一文が返ってきます。

### 17.3 結ぶ：答え、ドキュメント、記録

**結論を出す**は最後の発言をひとつ回し、そこであなたの主任リードバイザーが、話がどこに落ち着いたかを述べます — 決め手になった論をきちんと名指し、解けなかった対立をならさずにそう書き、まだ開いたままのことを言います。その発言もほかと同じように確定し、色はインクです。

そのあと何が起きるかは、組み立てのときに選んだ**ほしい出力**しだいです：

- **答え** — それ以上は何もしません。最後のカードが出力であり、それは議事会のあるキャンバスの上にあります。
- **ドキュメント** — 結論は、あなたが指定したプロジェクト内のパスに markdown ファイルとして書かれます。ほかのファイル書き込みとまったく同じ入口を通り、同じ許可リストと同じ取り消しが効きますし、既にあるファイルを上書きすることは、確認を見てあなたが「はい」と言うまでありません。そのうえで、結論の下にそのファイルを指すモジュールが足されます。生まれた議事会からクリックひとつで、ドキュメントに行けるようにです。
- **composure** — 0.4.0 で入る予定です。いま選んでおくと、結論を出すは発言をひとつ使う前に断り、別のものを選んでくださいと言います。

どちらにしても、全体は素の markdown として `rness/knowledge/councils/<date>-<title>.md` にも書き出されます：議題、部屋にいたのは誰で、それぞれ何のためにいたのか、ラウンド数、そして順番どおりのすべての発言です。前の書き出しを上書きすることはありません。一度開かれた議事会は、grep でき、引用でき、人に手渡せるものです — composure がとっくにどこかへ動かされた何か月もあとでも。

結論の出た議事会は、それで終わりです。操作は消え、そこから先に見えるのは、記録のパスと出力です。

### 17.4 何がかかるか、正直に

**遅いですし、遅くていいのです。** 発言のひとつひとつが、モデルのまるごと 1 ターンです — その参加者が議題とそれまでの発言をすべて読み、そして書きます。4 人で 3 ラウンドなら 12 ターン、しかも 1 つのローカルモデルの上で、順番にです。これを速くする裏技はありません。そして議事会を招集する値打ちがあるのは、その考えごとに 12 ターンの値打ちがあるとき、まさにそのときです。

**ウィンドウは等しく分けられます。** 話す参加者はみな、モデルのコンテキストウィンドウを同じだけ受け取ります — 2 人なら半分ずつ、4 人なら 4 分の 1 ずつ。その持ち分に、その参加者自身の人となりと、入るかぎりの議事会の中身とを収めなければなりません。いっぱいに近づくと、enough は古い発言から順に一行ずつにたたみ、誰が何を言ったかの一行の記憶に変えます：*この議事会のこれまで：Ed（発言 1）：…*。議題がたたまれることはありませんし、いま誰かが答えようとしている当の発言もたたまれません — 返事をする相手が見えない参加者には、言うことがないからです。

このたたみ方は機械的です — 最初の一文を取るだけで、モデルに要約を頼んだりはしません。自分を要約するために生成を使う議事会は、同じウィンドウに二度払うことになるからです。発言のたびに、何かたたんだかどうかが報告されます。早いうちから何度もたたみはじめたときの正直な対処は、議事会を小さくすることではなく、モデルウィンドウ（セクション 14.1）でコンテキストウィンドウを大きくするか、それだけの余裕のあるモデルにすることです。

## 18. スキル

スキルは、焦点の定まった能力の包みです：`SKILL.md`（と、任意の参照ドキュメントやスクリプト）の入ったフォルダが、手順や語彙や規律をリードバイザーに教えます。スキルはサイドバーからプロジェクトごとにオン／オフします。オフは本当にオフ — プロンプトにまったく入りません — そして新しいスキルはオフの状態で来るので、知らないうちに何かが変わることはありません。enough が同梱していないスキルは、そもそも有効にできるようになる前に読まれます（セクション 18.8）。全部オフにするのも、れっきとしたやり方です：素の会話、足場なし。モデルがあなたを驚かせるための余白は、そのほうが広いこともあります。

### 18.1 analyzer

ひとつのスキルに、分析のモードが 4 つ。

**Summarize** は、どんな文章についても 1 ページの、公平な要約を作ります：何を言っているか、誰に向けたものか、書き手の動機と偏り、調子、鍵になる引用。

**Proofread** は軽い校正をします — 誤字、綴り — 文書全体から本 1 冊まで。ローカルの規則ベースの文法チェッカー Harper が動かしています。提案と、繰り返し使われている言い回しの指摘をまとめた校正レポートも別に作るので、黙って直したものと、判断が要るものとが区別されたままになります。

**Decide** は、あなたの板挟みを、組み込みの 10 人の名簿から選ばれた 3 つの原型的な人格に手渡し、記録に残しながら議論させます。手に入るのは推奨*と*その議事録なので、判定を信じるかわりに、理由のほうを量れます。

**Audit** は、まだ信じると決めていないもの — 誰かが送ってきたスキル、リードバイザー、パラダイム — を読み、それが何であるかを教えます。まず、そのものが実際に何をして、なぜ欲しくなるかの平たい説明。それから安全の確認：プロンプトインジェクションの試み、リードバイザーの手の届く範囲をこっそり広げる指示、認識論的な赤信号、そして同梱されたコードがあれば、モデルをまったく通さない決定論的な走査も。判定は 3 語のどれか — **pass**、**flag**、**fail** — で、点数ではなく、名指しされた所見に裏打ちされます。読むだけです：audit が、読んでいるものを実行したり、編集したり、インストールしたり、有効にしたりすることはありません。

レポートは `rness/io/output/analyzer/audits/<skill-name>/` に降ります：ほかのファイルと同じように読める日付入りの `.md` と、その隣の小さな `verdict.json`。監査は名指しでいつでも頼めますし（「有効にする前に見ておいて」「このスキルは実際のところ何をするの」）、enough は同梱していないスキルを初めてオンにしたとき、頼まれなくてもこのモードを走らせます。どちらの扉からでも、同じレポートが同じフォルダに書かれます。その話はセクション 18.8 に。

### 18.2 anything-finder

最初のページには出てこないものたちのための、捜索隊です。3 つの顔、1 つのスキル。

**find** が既定で、見つけにくいもの 10 種類それぞれの手引きと、行き詰まった探索のための 11 番目を抱えています。**テキスト** — パブリックドメインの本、詩、歴史的文書。**映像** — 稀少な、失われた、絶版の映画とテレビ。視聴先のリンクと、その合法性の明示つき。表紙や zine に使える、権利の片づいた**画像**。**製品** — 知られていない機材、シンセ、楽器と、実際に買える場所。**論文** — 有料の壁の向こうにある論文を、正規の公開版として見つけます：プレプリント、リポジトリ、アーカイブ。**コード** — 寛容なライセンスのリポジトリ。GitHub に一度も触れていないライブラリも含めて。**書籍** — すでに好きだったものからの、似た読み心地の本。**音** — 楽譜、MIDI、サンプル、機材のマニュアル。**素材** — フォント、テクスチャ、3D モデル、ストック映像。**データ** — データセット、公開 API、政府文書、新聞のアーカイブ。

結果は*find カード*として返ります：リンク、なぜそれが正しい品なのか、そして著作権に敏感なものについては、なぜ使ってよいのか — 公開年か、明示的なライセンスを書き下して。「*The Moonstone* のパブリックドメイン版で、組版に耐えるくらいきれいなものを」「1974 年版はどこで合法的に観られる？」「これをやる MIT ライセンスのライブラリはある？」と聞いてください。正直な答えも取引の一部です：「これは存在しますが、合法的には手に入りません」「候補は 3 つ、2 番目に 70% 賭けます」も、ここでは本物の結果です。そして唯一の経路が海賊版のサイトだけなら、そう言ったうえで、図書館か、貸し出しの仕組みか、販売店を渡してきます。

**patents** は先行技術の顔です。発明をひとつ渡せば、成立特許、公開出願、そして特許以外の文献にわたる構造化された新規性調査を走らせ、何を見つけたか、それが新規性と非自明性にとって何を意味するかを報告します — 法的助言ではない、という断りがどのレポートにも残ります。実際そうだからです。「これはもう特許になっている？」「磁石式の自転車ロックで、こういうものの先行技術は」「私のアイデアは特許になる？」。届かなかったデータベースは*未確認*と明記されて返り、黙って*該当なし*にされることはありません。

**venture** は「これは商売になるか？」の顔で、ほかの 2 つを組み合わせます。すでに存在するものの市場の一掃、先行技術の確認、そして企業、オープンソースの代替、隣接製品、そして挑んで畳んだものたちの墓場にわたる競合の見取り図。手に入るのは公平な読みです — どこが混み合い、どこが隣接し、どこが本当に空いていて、証拠が実際に支える楔はどこか — に続けて、いちばん強い*賛成*の論と、いちばん強い*反対*の論。すべての論点にリンクの錨が打たれ、最後に、あなたにしか答えに行けない短い問いの一覧が付きます。「これを作るべき？」「これは製品として存在する？」「ここの市場の隙間はどこ？」と聞いてください。あなたのアイデアに点数は付けませんし、事業計画も書きませんし、資金を集めろとも言いません。そして、空いている領域を、青信号ではなく問いとして扱います。

出力は `rness/io/output/anything-finder/` へ行きます。取ってくるものはすべて、ほかのウェブアクセスと同じくブローカーを通るので、許可リスト外のドメインは Tor 経由になります — そして、あるソースが答えるのを拒んだときは、レポートがそのホストを名指しし、`allowlists.md` に何を足せばよいかを教えます。結果に黙って穴を残すかわりに。

### 18.3 girraph-merirmaid

enough の 2 つの図の原型（セクション 19 と 18）のための、規律のスキルです。girraph 側は、まっとうな IBIS の描き方を教えます：1 ターンに 1 つの問い、解決へ飛びつかない、止めどきはあなたの確認。merirmaid 側は Mermaid を書くときの決まりを抱えています。たとえば、あとで気持ちよく編集できるくらいノードのラベルを短く保つこと。モードはこのスキルなしでも働きます。あれば、リードバイザーは本当に規律のある地図描きの相棒になります。

### 18.4 memoir-dialectic

辛抱強い、複数セッションにわたる回想録の相棒です。あなたに聞き取りをして — 一度に 1 つか 2 つの問いで、決してどっと浴びせず — 何もかもを綴じていきます：会話の順に番号を振った計画のドキュメント、素早く再開するための索引、雑多な吐き出しのためのメモファイル、そしていずれは構成の統合と、あなたが望んだときにだけ、下書き。フォルダが記憶です。何週間でも何年でも姿を消して構いません。置いてきたところから続きます。人生まるごとから、たったひとつの節目まで、全域のために作られていて、繊細な話題や踏み込まない領域の扱いも明示され、あなた自身の言い回しを丁寧に保ちます — 声は大事です。下書きが来るなら、なおのこと。

### 18.5 readvisory

リードバイザーを作るスキルです（セクション 16）。仕様を書くのではなく、人に話を聞くことで作ります。

集め方は 2 通り。**その場で**：あなた*自身*に、ゆっくりと、一度に 1 つか 2 つずつ、全部で 12 から 18 の質問をします。このリードバイザーがこれから訊かれることになる類のことを、あなたが実際どう決めているのか、についてです。**質問票**：判断を手もとに置いておきたい相手 — 友人、師、昔の編集者、親 — に送れる、飾りのない、そのままメールできるファイルを書きます。相手は自分の都合のよいときに答え、あなたはその答えが届いたときに貼り戻します。質問票は受信箱で 1 週間眠ることもあるので、この仕事は全体がリクエストファイル（セクション 8.3）で追われます。何週間もあとのセッションが、何も知らないところから引き継げるようにです。

どちらの道も、終わり方は同じです：まず、あなた*自身*への短い追いかけの問い（これがあるから、リードバイザーは書き起こしより良いものになります）。それから 2 つの文書が下書きされ、あなたが 1 行ずつ直せるように示されます。そしてようやく、あなたの了解のもとで導入されます — このプロジェクトに、あるいは、このマシンのすべてのプロジェクトから見える `~/enough/readvisors/` に。2 つの文書は、何かが書かれる前に、ダウンロードしたスキルが受けるのと同じ安全性の検査を通ります。そして最後の一歩を踏むのが enough なのか、あなたなのかは、ブローカーの**新しいリードバイザーを立てる**の切り替え（セクション 9）が決めます。

自分が何のためのものでないかを、はっきり分かっています。主任リードバイザーの名前を変えることはしませんし、議事会を招集することもしません：参加者を作るのが仕事で、会を回すのは仕事ではありません。

### 18.6 scaffold

考えごとの山を、眺められる構造に変えます。

頭の中身をそのまま渡してください — パネルに貼り付けても、プロジェクトの中のファイルでも、既にある composure でも構いません — すると、文ではなくかたちを読みます。物語のかたち（弧、場面、つながりの糸、結び、終わり方）も、論のかたち（主張、根拠、論拠、反対側の言い分、締め）も、計画のかたち（目標、段階、依存関係、リスク、何をもって終わりとするか）も知っています。はっきりさせるための質問は多くて 2 つ、たいていは 1 つもせずに、結果を enough に渡します。enough はそれを composure として並べます：場面や節や段階ごとに 1 枚のカードを、列や行にまとめて、目の前のキャンバスの上に（セクション 4.5）。

これを持っている値打ちを決めている決まりが、ひとつあります：**穴を埋めるために中身をでっち上げることは、けっしてありません。** 構造が求めているのに、あなたがまだ書いていないものがあれば、かわりに `[gap: …]` のカードを書きます — 色はオレンジ、問いはそのまま残します。かたちのほうから、あなたがまだ何を負っているかが見えるようにです。終わり方は分かっているのに転がし方が分かっていない物語には、まさにそう書かれた gap カードが付きます。そしてそれはたいてい、そのボードでいちばん役に立つカードです。

作品そのものは書きません。書くのは構造で、その上のカードはどれも、置かれたその瞬間からあなたが手を入れられます。

（同じ名前で 2 つのものを指しているので、一度だけ分けておきます：text-planning パラダイムが作る*足場（scaffold）*は — セクション 15.2 — 節ごとの構造の手引きで、あなたが文章に膨らませるために markdown で書かれます。こちらのスキルが作るのは、composure まるごとです。両者は仲がよく、text-planning で立てた計画は、このスキルに渡す頭の中身としてちょうどよいものになります。）

### 18.7 translator

MADLAD-400 による、約 419 言語のオフライン翻訳です — 一度きりの約 3 GB のダウンロードで、CPU でも Apple Silicon でも動き、外へ電話をかけません。短い一節から文書まるごとまで、主要言語から低資源言語や先住民の言語まで。手紙を訳す、README をローカライズする、ある一節の意味を確かめる、意味が保たれるかの試験として第三の言語を経由して往復させる — すべて、ネットワークを抜いたままで。一部の低資源言語には、より高い品質を出す NLLB-200 エンジンを任意で選べます。こちらは非商用のライセンスなので、translation パラダイムからの明示的な選択制になっています。

### 18.8 自分のものを書くこと、他人のものを信じること

上の 5 つは実演です。スキルの*仕組み* — markdown の指示、オンにしたときに読み込まれること、いつ働くかをリードバイザーに伝える `description:` — こそが、本当の機能です。文体の指針、分野ごとの確認事項、繰り返し使うレポートの書式、データの扱いの手順：ある能力を文章で説明できるなら、それをスキルとしてリードバイザーに手渡せます。workflow-design（セクション 15.4）で自分のものを作るか、5 つのどれかを分岐させて自分のものにしてください。

その輪のもう一方の端が、よそから届くスキルです。スキルとは、あなたのリードバイザーが従う指示です。つまり、インターネットから来たスキルは、インターネットから来たほかのどんなファイルとも、まったく同じだけの疑いに値します。そこで enough は、あなたのかわりにそれを読みます：

- **enough が同梱するものは信頼済みで、これまでどおりに見えます。** 上の 5 つは、インストール先の defaults へのリンクとして届きます。押せばすぐ切り替わります。監査は走りません。
- **それ以外はすべて、読まれるまでオフです。** スキルのフォルダを `rness/skills/` に置くと — ダウンロードしたもの、友人が送ってくれたもの、`.skill` から展開したもの — 無効のまま、サイドバーに*未検証*と印を付けて座っています。初めてオンにしたとき、enough は一言もリードバイザーに届く前に、analyzer の監査モード（セクション 18.1）をそれにかけます。行の中でそれが進むのが見えます：*未検証* → *監査中…* → *監査済み*。
- **要注意は、有効ではないということです。** 監査が何かを見つけると、行は*要注意*（あるいは*不合格*）と言い、スキルはオフのまま、ボタンが 2 つ出ます：**レポートを読む**は全文を読む表示で開き、**それでも有効にする**は確認を求めたうえで、その判断をあなたのものとして記録します — 所見は消されるのではなく、覆されるのであり、行はそれ以降*あなたが信頼済み*と読めます。監査は助言し、あなたが決めます。（ファイルの中で作業したいなら、そのスキルの `verdict.json` を `"verdict": "pass"` に編集しても同じことです。）
- **スキルを編集すれば、読み直されます。** 監査は、それが読んだまさにそのバイト列 — ファイル名も中身も — に結び付いています。何かを変えれば、次にそのスキルをオンにしたとき、また監査されます。前に「それでも有効にする」を選んだものも含めてです：上書きの判断は、ある一組のファイルの、ある一瞬についての記述であって、編集を生き延びはしません。
- **あなたのリードバイザーがあなたのために書いたスキルも、未信頼です。** それは見落としではなく、意図です。workflow-design が新しい `SKILL.md` を `rness/skills/` に書いたとき、リードバイザーは初回の有効化で自分の宿題を監査します。見つかるものが何もなければ、ほぼ一瞬で終わります。
- **モデルが動いていないと、監査は終われません** — そのときは、スキルを素通りさせるかわりに「監査の llm の側が走れませんでした」と印を付けます。モデルをオンにしてもう一度切り替えるか、中身がもう分かっているなら*それでも有効にする*を使ってください。

レポートは `rness/io/output/analyzer/audits/<skill-name>/` に暮らします — 会話で監査を頼んだときに analyzer が書くのと同じフォルダです。扉は 2 つ、書類は 1 つ。そしてそれは、開いて、取っておいて、消すこともできる、ふつうの markdown ファイルです。

## 19. girraph モードと `.girraph` 拡張子

読み方は「グラフ」。*ir* は黙字で、*iterative*（反復的）と *recursive*（再帰的）を表しています。動物のほうは 🦒 で、こちらも黙っています。

girraph は、難しい問いの地図です。やることの一覧ではありません：*意見の食い違い*の絵であり、自分自身との実りある食い違いも含みます。ある種の問題（「ホームスクールにすべき？」「この本は結局のところ何についての本？」「その資金を受けるか？」）は、どの答えからも異議が芽を出し、どの異議の下にも新しい問いが生えます。一覧はその争いを埋めてしまいます。girraph はそれを見えるところに置きます：

- ❓ **issue（論点）** — 開かれた問い。いつでも問いのかたちで書きます
- 💡 **position（立場）** — ありうる答え
- ➕ ➖ **argument（論拠）** — ある立場への賛成と反対の理由
- 📄 **note（メモ）** — 背景、制約、ドキュメントへの参照
- 🦒 **入れ子の girraph** — それ自体の地図に値するくらい大きな下位の問い

血筋は IBIS、「厄介な問題」のための 1970 年代の手法です — きれいな答えも、自然な止まりどころも無い類いの問題のための。girraph は、それに対する enough の平文での応答です。

形式は `.girraph` で終わるテキストファイルで、1 行に 1 つの考え。2026 年でも 2056 年でも、どのエディタでも読めます：

```
%girraph 0.1
title: Should enough ship a plugin API?

q1 ? Should enough ship a plugin API?
p1 ! Ship a minimal one < q1
a1 + Ecosystem growth needs stable hooks < p1 by:graham
a2 - API surface = forever maintenance < p1 by:open-skeptic
```

`< q1` は「これは q1 に答えている」という意味で、`by:` は誰の主張かを覚えています。データベースも、隠れているものもありません。ファイルが地図です。

アプリで `.girraph` をクリックすると girraph モードが開きます：折りたためるツリーを、その場で編集できます。ラベルをクリックすれば書き換えられます。行にカーソルを置けば、追加・リンク・削除のボタンが出ます。🦒 のチップをクリックすれば入れ子の地図へ降り — パンくずが連れ戻してくれます — 📄 のチップをクリックすれば、参照されたドキュメントをその場で読めます。チャットでは「girraph にして」「地図にして」と言えば、リードバイザーがあなたと同じノード単位の操作で同じファイルを編集するので、2 人で同時に地図をいじれます。ノードの削除にはいつでもあなたの確認が要りますし、子が黙って親を失うことはありません。

girraph は **merirmaid のミラー**を生やすこともできます：girraph のツールバーの merirmaid ボタンをひとクリックすれば、地図とリンクした、自動で作り直される Mermaid の図ができます — 論点は六角形、立場はスタジアム、支持と異議はそれぞれの色の線で — girraph が変わるたび、自分を最新に保ちます。girraph で地図を描き、merirmaid で眺める。

girraph を効かせる習慣が 3 つ。論点は問いのかたちで書くこと（「2 年目の資金をどう作るか？」であって、「お金の問題」ではなく）。論拠は論点ではなく立場に付けること — 理由とは、ある*答え*への賛成か反対の理由です。そして枝が広がりきる前に、自分のファイルへ分けること。girraph-merirmaid スキルを有効にすれば、リードバイザーがこの 3 つをあなたに守らせます。

## 20. merirmaid モードと `.merirmaid` 拡張子

girraph が議論を地図にするのに対し、**merirmaid** は構造を描きます。`.merirmaid` ファイルは [Mermaid](https://mermaid.js.org/) の図 — フローチャート、シーケンス図、状態機械、ER 図、Mermaid が描くものなら何でも — に小さなフロントマターのヘッダーを付けたもので、ブラウザで即座に描かれます。もちろんローカルで。enough のすべてと同じく、CDN はありません。

ヘッダーで宣言する、2 つのありよう：

- **wip** — 作業中のホワイトボード。どのノードの文字もクリックすれば、その場でラベルを編集でき、文字数が生で出ます。構造の変更（箱を足す、矢印をつなぎ替える）は、チャットピルを通してリードバイザーに頼みます。あなたのパイプライン、筋書き、組織の図を頼めば、リードバイザーがソースを書き、ブラウザが描き、あなたが言葉を整えます。
- **mirror** — よそに暮らす構造を映した、読み取り専用の反映です：キャッシュボックスの中身（セクション 12.1）か、girraph（セクション 19）。ミラーは、映しているものが変わると作り直されます。絵を変えたければ、そのものを変えてください。

図はリンクします。ノードは別の `.merirmaid` や `.girraph` や markdown ドキュメントを指すことができ、クリックすればそこへ移動し、パンくずが帰り道に印を付けます — こうして図の集まりは、あなたのプロジェクトのたどれる地図帳になります。そして図に構文の誤りがあるとき、merirmaid モードは白紙ではなく、エラーと生のソースを見せます。直すよりどころは、いつでもあります。

girraph-merirmaid スキル（セクション 18.3）が、どちらのファイル形式についても書き方の規律を抱えています。そこにある目安をひとつ、ここで繰り返す値打ちがあります：正直な最初の一手が問いを立てることなら、欲しいのは girraph です。箱と矢印を描くことなら、欲しいのは merirmaid です。

## 21. ここからどこへ

enough をいちばん速くあなたのものにする道：

1. 本物のプロジェクトで立ち上げてください — 実際に大事だと思っているもので。
2. 1 セッション、話すことに使って、プロジェクトプロファイルが溜まり始めるに任せてください。
3. `MOTIVATION.md` を編集して、このプロジェクトが実際のところ何のためのものかを書いてください。
4. 同じ指示を 2 度目に言いそうになったら、止まってください。かわりに `AGENT.md` に書きましょう。
5. あなたの仕事のかたちに既定が合わないと初めて感じたら、「これのためのパラダイムを設計しよう」と言ってください — スキルでも、リードバイザーでも — workflow-design が手を引いてくれます。

その輪 — 引っかかりに気づき、直し方を書き留め、仕事を続ける — が、この遊びのすべてです。組み込みのものは、あなたを出発させます。あなたが最後に手にしているシステムは、誰も出荷していません。あなたが書いたものです。
