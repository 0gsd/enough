こんにちは、enough を作った Graham です。このドキュメントは — いま読んでいるこの部分をのぞいて、という意味ですが — 主にエージェントたちが書き、手入れをしています。私もときどき、まず間違いなく Graham らしさをひとつまみ振りかけていくでしょうが、面白いものを書きたいという自分の欲に、行き届いたドキュメントの邪魔をさせない、というのが趣旨です。

# enough ヘルプセンター

> enough でできることのすべてを、ひとつの場所に。enough **0.3.0** に対して書かれています。ホーム画面（これまでに始めたすべてのプロジェクトをひとつの一覧に、入り口と出口つきで — セクション 2）、convert ラウンド（PDF、Word ドキュメント、電子書籍、スライド、ワークブックが、編集できる markdown のツインとして開き、書き出しと同期と画像ビューアがつく — セクション 6）、skills ラウンド（analyzer の新しい監査モード、`anything-finder` スキル、そして enough が同梱していないスキルを、通す前にかならず読む初回監査）、2026 年 8 月ラウンド（実現できるかを確かめながら入れられる 7 つのローカルモデルと、**enough.app** — 署名・公証済みのデスクトップアプリケーション）、2026 年 7 月のインターフェイスラウンド（モードスタック、フォルダごとのヘルプバブル、girraph→merirmaid のミラー）、そして 0.3.0 の設定ラウンド（プロジェクトごとの ui とテキストの拡大率、そして 6 言語で読めるインターフェイスとヘルプ — セクション 9）まで含みます。このドキュメントと目の前のアプリが食い違っていたら、正しいのはアプリのほうで、このドキュメントにバグがあります — 修正のご連絡は [enough.support](https://enough.support) へどうぞ。

enough は、あなた自身のマシンで動く、個人のための言語システムです。フォルダをひとつ指し示し、話しかければ、計画し、書き、見直し、調べ、翻訳するのを手伝ってくれます。モデルは既定でローカル。あなたのファイルはあなたのものです。そして、enough がすることのほとんどは、あなたが開いて読んで変えられる、平文の markdown ファイルで定義されています。

読みながら、ひとつだけ頭の隅に置いておいてください。**このマニュアルに載っている組み込みの機能は、enough にできることのほんの一部です。** 箱に入っているパラダイム、ロール、スキルは出発点の一式 — 3 つのカスタマイズの仕組みの、動く実例であって、その限界ではありません。行き着く先は、あなたが自分のものを書くこと、あるいはエージェントと一緒に書くことです：エッセイの計画の立て方に合わせたパラダイム、いちばん手厳しい読者のように反論してくるロール、あなたの文体を写し取ったスキル。その方法はセクション 3 にあります。このドキュメントでいちばん大事なセクションであり、これから何度もそこへ送り返すことになります。

## 1. インストール、ショートカット、このドキュメント

### 1.1 必要なもの

- Apple Silicon の Mac。（enough は macOS で作られ、テストされています。Linux 対応は予定にあり、Windows も可能です。）
- 少なくともモデル 1 つ分のディスク容量 — いちばん小さいもので約 5 GB です。
- アカウントも、API キーも、サブスクリプションも不要。あとからクラウドのモデル枠（セクション 13.2）を選ばないかぎり、すべてが手元で動きます。

### 1.2 インストール

扉は 2 つ、着く家は同じです。

**アプリ — 短い道。** リリースページから `enough` の DMG をダウンロードして開き、**enough** を Applications にドラッグして起動します。macOS は「インターネットから入手したアプリ」だと言ってきますが — 署名も公証も済んでいるので、これは戦って突破する警告ではなく、**開く**ボタンのある人当たりのよい青いダイアログが一度出るだけです。あとは初回ガイドが引き受けます：自分の Python 環境を作り、モデルの一覧を、*このマシン*に何が入るかの正直な判定つきで見せ（セクション 13.1）、任意のエクストラのうちすでに持っているものを並べ、作業したいフォルダを選ぶホーム画面へ渡してくれます（セクション 2）。待ち時間のほとんどはモデルのダウンロードです。Terminal も、Homebrew も、git も要りません。

アプリは自前の推論エンジンと Python を抱えています。任意のエクストラ — 音声入力、ウェブページの取得、文法チェック、翻訳 — はいまも別のプログラムで、ガイドの Extras ページが、それぞれ何なのか、無いと何が使えなくなるのか、どう手に入れるのかを説明します。どれも必須ではなく、勝手に入るものもありません。ひとつだけ、別プログラムではないエクストラがあります：**PDF の読み込み**は、enough の中からいつでもインストールできます（セクション 6.8）。

**ターミナル — 長い道、そのぶん手綱が多い。** リポジトリをクローンして、クローンの中の `install-enough.command` をダブルクリックします：

```bash
git clone https://github.com/0gsd/enough.git ~/Downloads/enough-seed
open ~/Downloads/enough-seed
```

初めてダブルクリックしたとき、macOS の Gatekeeper が「開発元が未確認」と渋ることがあります — その用心は `.command` ファイルに向けられたもので、アプリのようには署名されていないからです。ファイルを右クリックして**開く**を一度選べば、macOS はそれ以降、信頼を覚えています。

ランチャーは `bootstrap.sh` を走らせます。10 段階の対話式インストーラで、各段階の前に何をするかを説明して尋ねてきます。Ctrl-C はいつ押しても安全です。やり直しも安全 — 先に状態を確かめて、途中から続けます。段階はおおよそこうです：

1. お使いのプラットフォームを確認。
2. Homebrew があるか確かめ、無ければ入れるのを手伝う。
3. enough が頼っている補助プログラムを入れる：`llama.cpp`（ローカルモデルの推論）、`whisper-cpp`（音声入力）、`tor`（匿名でのウェブ取得）、`harper`（ローカルの文法チェック。analyzer スキルが使います）。ドキュメントの変換器 — 取得したウェブページや Word ファイルを markdown にする pandoc と、PDF を書き出す typst — はもうこの一覧にありません：どのプラットフォームでも、段階 5 で入る enough 自身の Python 環境に同梱されています。Homebrew の pandoc をお持ちなら、enough はそちらを使います。
4. 全体のインストール先 `~/enough/` を用意。
5. Python 環境を（`uv` で）準備。
6. モデルの重みをダウンロード。対応しているモデルはひとつずつ提示され、それぞれサイズと、お使いのマシンのメモリと空き容量に照らした実現可能性の判定がつきます — ✓ は余裕、~ はぎりぎり、✗ はよそを当たったほうがよい、という意味です。いくつ選んでも構いません。すべてはセクション 13.1 で説明しますし、見送ったものはあとからワンクリックで入れられます。
7. 音声入力（whisper）のモデルを配置。
8. オフライン翻訳のモデルを配置。`translator` スキルが使います。
9. `enough` コマンドを PATH に置く。
10. 完了。次にすることの一覧が印字されます。

あとで更新するには：`~/enough/` の `update-enough.command` を実行するか、チャット欄に `/update-enough` と打ちます。新しい defaults が出たときは enough がインターフェイスで知らせ、そのコマンドを指し示すので、こちらから見に行く必要はありません。モデルの重みだけを更新するには `update-weights.command` を使います。

### 1.3 起動

**アプリから：** ダブルクリックすると、**ホーム画面**に着きます — これまでに enough プロジェクトにしたフォルダがすべてひとつの一覧になり、もう 1 つ足すための場所もあります。ひとつ選べば開きます。それがセクション 2 で、このセクションより先に読む価値があります。

**enough** メニューには設定がひとつだけ、**Reopen Last Project on Launch**（起動時に前のプロジェクトを開く）があります。既定はオフ。オンにすると、アプリはホームを飛ばして、前にいた場所へまっすぐ戻ります。ウィンドウはひとつ、プロジェクトも一度にひとつ — そして **File → Close Project**（⌘W）を使えば、終了せずにいつでもホームへ降りて、別の場所へ移れます（セクション 2.5）。

素のフォルダピッカーもまだ中にありますが、おそらく出会うことはありません：ホーム画面そのものが立ち上がれないとき — 中途半端な更新、壊れたインストール — のための逃げ道で、悪い日にも仕事へ入る道が残るようにしてあります。

**ターミナルから：** enough はプロジェクトフォルダごとに動きます。好きなフォルダでターミナルを開き、こう打ちます：

```bash
enough
```

そして `http://127.0.0.1:3456` を開きます（enough が代わりに開いてくれます）。フォルダが違えば、プロジェクトも、エージェントの記憶も別です。ひとつだけ起動できないフォルダが `~/enough/` そのもので、CLI はこれを断ります。そこはインストール先であって、プロジェクトではないからです。

ホーム画面も、どこからでも呼べます：

```bash
enough --home
```

同じ画面、同じ一覧が、アプリのウィンドウではなくブラウザに出ます。そこからプロジェクトを開けば、起動に使ったターミナルがそのプロジェクトのターミナルになります。

コマンドを打ちたくないなら、`~/enough/shortcuts/` にランチャーが 2 つ入っています：

- **`enough-on.command`** — プロジェクトフォルダにコピーして（`cp ~/enough/shortcuts/enough-on.command ~/some-project/`）、Finder でダブルクリックします。そのフォルダで enough が動く Terminal ウィンドウが開き、⌘W か Ctrl-C で止まります。
- **`setup-quick-action.sh`** — 一度だけ実行すると（`bash ~/enough/shortcuts/setup-quick-action.sh`）、Finder のクイックアクションが手に入ります：どのフォルダでも右クリック → クイックアクション → **Launch in enough**。メニュー項目が出てこないときは、システム設定 → キーボード → キーボードショートカット → サービス → ファイルとフォルダ で有効にしてください。

### 1.4 このドキュメントと、その他のドキュメント

このファイルは長文のマニュアルです。ほかにこういうものもあります：

- **手元のヘルプ** — インターフェイスのあちこちにある `(?)` バブル。それぞれが、くっついている当のものを説明します：*what*、*how*、*ideas* の一覧つき。セクション 9.6 をどうぞ。
- **チートシート** — キーボードショートカットと markdown の記法が、UI ウィンドウからワンクリックで。セクション 9.5 をどうぞ。
- **[enough.support](https://enough.support)** — コミュニティのフォーラム：インストールの相談、進め方の見せ合い、そしてこのマニュアルがずっと勧めているカスタマイズを、喜んで一緒に作ってくれる人たち。

そしてそのすべて — このマニュアル、バブル、まわりのインターフェイス — が 6 言語で読めます：英語、フランス語、スペイン語、ドイツ語、中国語、日本語。ドロップダウンと細かい話はセクション 9.4 に。

## 2. ホーム画面

プロジェクトに入る前にいるのが**ホーム**です：これまでに enough プロジェクトにしたフォルダをすべて並べた 1 枚の画面と、もう 1 つ足すためのタイル。このアプリケーションでいちばん静かな画面になるよう、わざとそうしてあります。チャットも、サイドバーも、モデルも、エージェントもありません — まだ何も動いておらず、何も考えられていません。あるのはあなたのプロジェクトと、テーマとこのマニュアルのための、上部バーの ⚙ UI ボタンだけです。

ここに来るのは：

- 初回起動のとき、初回ガイドが終わった直後。
- そのあとの起動のたび。ただし **Reopen Last Project on Launch** がオンなら別です（セクション 1.3）。
- プロジェクトを閉じたとき（セクション 2.5）。
- ターミナルから、いつでも、`enough --home` で。

ホームを*見ない*ただひとつの方法が、あのトグルです。**Reopen Last Project on Launch** をオンにすると、enough は前にいたプロジェクトへまっすぐ戻り、ホームは間に入りません。オフにすれば、起動はいつもホームから始まります。設定はそれだけ。ほかに調整するものはありません。

### 2.1 グリッド、リスト、そして ¶ W C

表示は 2 つ。画面右上のボタン 2 つで切り替わり、enough はどちらが好みかを覚えています。

**アイコン**は眺めるための表示です：フォルダの絵、プロジェクトの名前、その下に平たい日本語の 1 行 — *3 日前に編集*、1 週間より古ければ実際の日付。

**リスト**は見比べるための表示です。列は 6 つ：

| 列 | 何を表すか |
|---|---|
| 名前 | プロジェクトの表示名（プロジェクトのタイトルバーで設定したもの、なければフォルダ名） |
| ¶ | 段落数 |
| W | 語数 |
| C | 文字数 |
| 最終更新 | それらの数に含まれるファイルへの、いちばん新しい変更 |
| 作成 | そのフォルダが enough プロジェクトになった日 |

真ん中の 3 列は、ドキュメントを開いているあいだ enough が上部バーに出しているのと同じ 3 つの数字を、プロジェクト全体で足し上げたものです — ¶ は段落（空行で区切られたブロック）、W は語、C は空白と改行を含む文字。*どの*ファイルが数えられるかの決まりは、この数字に意味を持たせている一文なので、書いておく値打ちがあります：プロジェクト自身のファイルツリーに出てくる markdown ファイルはすべて、**変換されたドキュメントのツインも含めて**数えます（ここで編集している `.docx` は、あなたの書いたものです）。そして `rness/` の中身は**数えません**（エージェントの足場は、あなたの本ではありません）。ですから W 列の数字は、まず間違いなく、あなたがどれだけ書いたかです。

列見出しをクリックすればその列で並べ替え、同じものをもう一度クリックすれば逆順になります。報告することが何もないプロジェクト — 一度も開かれず、数えられてもいないもの — は、どちらの向きでも最下段に沈みます。いちばん古いふりをするより、そのほうが正直だからです。既定の並びは、最近編集した順です。

いまフォルダがそこに無いプロジェクト — 外付けドライブを抜いた、Finder で移動した — は灰色で描かれ、覚えているパスがツールチップに出ます。一覧から**落とされることはなく**、最後に見たときの数字もそのまま保ちます。引き出しの中のドライブにあるプロジェクトは、失われたプロジェクトではありません。

### 2.2 プロジェクトをクリックする：地図

シングルクリックではプロジェクトは開きません。かわりに**地図**を描きます：そのフォルダの目に見える中身を、読み取り専用の merirmaid 図（セクション 18）にしたもので、上の小さな情報ノードにパス、ファイル数、¶ と W の合計、作成日・最終起動日・最終編集日が入ります。cacheawl がキャッシュボックスに描くのと同じ種類の絵を（セクション 11.1）、プロジェクトに向けたものです。

この地図は、それらしい名前のフォルダが 4 つあって、章が入っているのはどれかを知りたい、あの瞬間のためのものです。見て、それから決める。

決まったら、ツールバーの**プロジェクトを開く**ボタンで開きます。Esc か右上のリボンでグリッドに戻ります。そして、どれを開きたいかもう分かっているなら、タイルや行を**ダブルクリック**すれば寄り道なしで開きます。

開く様子はどちらでも同じです：enough がホーム画面を畳んでプロジェクトを立ち上げるあいだ、ローダーが 1、2 秒あらわれ、そのあとは、最初からそのフォルダで起動したのと変わらない discussion 表示（セクション 4）にいます。

### 2.3 フォルダを足す

グリッドのいちばん最後のタイル — プラスの付いたもの — が、フォルダをプロジェクトにする方法です。

クリックすると macOS 自身のフォルダ選択画面が開きます。メモでも下書きでもドキュメントでも、好きなフォルダを選んでください。enough はそこに `rness/` を足し（セクション 7）、ホーム画面に登録して、開きます。ダイアログが出ているあいだ、タイルは*フォルダ選択を待っています…*と言っているので、じっくり探して構いません。

断られるフォルダが 2 種類あります。enough は、ぼんやり失敗するかわりに、どちらでなぜかを伝えます：

- **`~/enough` そのもの、およびその中身。** そこはインストール先であって、プロジェクトではありません。（`enough` コマンドも、同じ理由で同じフォルダを断ります。）
- **クラウド同期フォルダの中身すべて** — Google Drive、Dropbox、iCloud Drive。これは神経質さではありません。プロジェクトの `rness/` は、全体の defaults へ戻るシンボリックリンクで組まれていて、同期クライアントはシンボリックリンクを日常的に書き換えたり壊したりします。結果として、全体の設定を静かに追わなくなったプロジェクトが、あなたが気づかないほうのマシンにできあがります。プロジェクトはローカルディスクに置いて、仕上がったものを同期してください。

すでにホーム画面にあるフォルダはエラーではありません — enough はただ開きます。

フォルダ選択画面がそもそも出せないとき（Mac でないマシン、拒否するサンドボックス）は、モーダルがパスを打ち込む素のテキスト欄を出し、その上に理由を書きます。そこから先はまったく同じです。

### 2.4 プロジェクトを隠す

ホームはすべてを、いつまでも並べます。実験を 1 年も続ければ、それは長くなります。というわけで：**タイルや行を option+クリックすると隠せます。**

隠すというのは enough 自身の一覧に付けたメモであって、それ以外の何でもありません。尋ねるときにもそう書いてあります：ディスク上のフォルダには触れず、`rness/` にも触れず、その中の一語も変わりません。ホーム画面に「このプロジェクトを削除」はありませんし、それはわざとです — プロジェクトを削除するとは、あなたの書いたもので一杯のフォルダを削除するということで、それは Finder の仕事です。自分が何をしているか、目で見える場所の。

表示ボタンの隣の**非表示**チップが、隠したものを呼び戻します。いくつあるかも書いてあります。隠されたプロジェクトは灰色で、行に*非表示*と出ます。option+クリックで戻せます（確認はありません — 即座で、即座に取り消せるからです）。アプリでは **View → Show Hidden Projects** から同じスイッチを動かせます。

### 2.5 プロジェクトを閉じて、また戻る

扉は 2 つ、部屋は同じです。

**アプリで：** **File → Close Project**、または **⌘W**。プロジェクトのバックエンドが行儀よく終了し、1 秒ほどでホーム画面がその場に現れます。

**どこでも、アプリでもブラウザでも：** ⚙ UI ウィンドウ（セクション 9）の上にある**プロジェクトを閉じる → ホーム**ボタン。先に尋ねてきます。閉じることはセッションの終わりだからです — 目の前の会話は、終了したときと同じように終わります — そのあとは、⌘W とまったく同じ場所に着きます。

どちらもあなたのフォルダには触れません。ファイルも、`rness/` も、リクエストファイルも、セッションログも、置いてきたところにそのままあります。終わるのは、動いていた会話だけです。

新しくなった ⌘W について、enough を長く使ってきた人が知っておくとよいことがひとつ：**⌘W はもうウィンドウを閉じません。** enough はウィンドウがひとつのアプリケーションで、そのウィンドウを閉じれば終了してしまいます。だから ⌘Q と赤いボタンですでに足りていて、⌘W にはもっとよい仕事があったのです。

そして、これと再開設定のあいだの相互作用がひとつ。書いておかないと、きっちり一度は驚かせるので：**プロジェクトを閉じても、enough はそれを忘れません。** **Reopen Last Project on Launch** がオンのときに、プロジェクトを閉じ、しばらくホームにいて、それから終了すると — 次の起動で開くのはホームではなく、そのプロジェクトです。トグルは「どこから始めるか」を決める設定で、Close Project は「いま自分がどこにいるか」を決めるボタンです。これからはホームで始めたい、というときは、トグルをオフにしてください。

### 2.6 ホームが覚えていること

小さなものが 3 つ。どれもマシン全体のもので、プロジェクトからプロジェクトへ、そしてホームへ、あなたについてきます。どのプロジェクトフォルダにも保存されません：

- **テーマとフォント**（セクション 9.1）。ホームは最後に選んだ装いをまといますし、ホーム画面*で*切り替えたテーマが、プロジェクトを開いたときのテーマになります。これは以前、人をいらだたせていたところです：起動の画面と仕事の画面は、いまはいつでも同じことを言います。
- **アイコンかリストか**（セクション 2.1）。
- **隠したプロジェクトを出しているかどうか**（セクション 2.4）。

プロジェクトについてのそれ以外は、すべてそのプロジェクトのフォルダの中、あなたが読める場所にあります。

## 3. 仕事のやり方を、根っこからカスタマイズする

ひとつだけ読むなら、ここを読んでください。

たいていのソフトウェアは機能を手渡します。enough が手渡すのは仕組みです。エージェントの人格、方法、持ち技は、あなたのディスクにある markdown ファイルから、メッセージ 1 通ごとに新しく組み立てられます：

- **`AGENT.md`** — エージェントが誰で、どう動くか（セクション 4.1）
- **`MOTIVATION.md`** — なぜ：価値観、優先順位、「終わった」がどんな感じか
- **ポリシー** — 何を読み、書き、取ってきてよいかの動かせない規則（セクション 4.2）
- **有効なパラダイム** — いま効いている思考の枠組み（セクション 14）
- **有効なスキル** — 手を伸ばせる能力（セクション 16）
- **有効なロール** — 呼び出せる別の人格（セクション 15）
- **プロジェクトプロファイル** — このプロジェクトについて学んだこと（セクション 7.1）

これらを、アプリでもお好みのテキストエディタでも編集すれば、次のメッセージから効きます。ビルドも、再起動も、プラグイン API も要りません。markdown ファイルが書けるなら、あなたはエージェントをプログラムし直せます。

### 3.1 全体のもの、プロジェクト専用のもの

カスタマイズできるものはすべて、ひとつの型に従います：**既定は `~/enough/defaults/` にあり、プロジェクトはそこへリンクし、どのプロジェクトもそのリンクを切ることができる。**

`~/enough/defaults/` のファイルを編集すれば、まだリンクしているすべてのプロジェクトに変更が届きます。プロジェクトの中でリンクされたファイルを開き、**カスタマイズ**をクリックすると、リンクはプロジェクト専用のコピーになり、それ以降そのプロジェクトは自分の道を行き、ほかは全体の既定に付いていきます。どちらなのかは、ファイルツリーがひと目で教えてくれます：リンクされたファイルは*斜体で淡く*、ローカルのコピーはふつうに描かれます。

`~/enough/defaults/` に置かれた新しいスキル、ロール、パラダイムは、次の起動ですべてのプロジェクトに現れます。スキルとロールはオフの状態で来るので、知らないうちに何かが変わることはありません。欲しくなったときに、プロジェクトごとに有効にしてください。enough が同梱していないスキル — ダウンロードしたもの、友人が送ってくれたもの、あなた自身のエージェントが書いたもの — は、通す前にかならず読まれます。セクション 16.6 がその話です。

### 3.2 3 種類の部品

| | パラダイム | スキル | ロール |
|---|---|---|---|
| 何なのか | 思考の枠組み — エージェントの仕事への向かい方 | 焦点の定まった能力 — 語彙、レシピ、手順 | 呼び出せるもうひとつの人格 — 自前の AGENT.md と MOTIVATION.md を持つ |
| 同時にいくつ | 常にちょうど 1 つ | オンにした数だけ | オンにした数だけ |
| 置き場所 | `rness/paradigms/<name>.md` | `rness/skills/<name>/SKILL.md` | `rness/roles/<name>/` |
| 同梱の例 | default、text-planning、translation、workflow-design | analyzer、anything-finder、girraph-merirmaid、memoir-dialectic、translator | block-breaker、open-skeptic |

### 3.3 自分のものを作る

これらのファイルは手で書けます — 先頭に小さな YAML ブロックの付いた markdown です — が、手で書く必要はありません。同梱の **workflow-design パラダイム**（セクション 14.4）は、エージェントがあなたと一緒に作るために存在します。「こういうスキルを作って」「こういうロールを作って」「こういうパラダイムを作って」と言えば、エージェントは workflow-design に切り替わり、確かめるべきことを尋ね（範囲は？　名前は？　どんなときに動く？　付随するファイルは？）、部品をきちんと書き上げます。将来のターンにいつそれへ手を伸ばすべきかを伝える `description:` のフロントマターも込みで。

実際に作られているもの：

- 仕事の性質ごとの**パラダイム** — 調査、下書き、推敲 — と、いつ切り替えるかの明示的な規則。
- ニュースレターの声、引用の書式、学位論文の用語法を写し取った**スキル**。
- ソクラテス式に問い返すラバーダック、疑い深い査読者、自分の知識ファイルから組み上げた分野の専門家といった**ロール**。

このマニュアルの残りは、組み込みのものを説明します。そのひとつひとつを、あなたがコピーし、分岐させ、改良してよい実例として読んでください。

## 4. Agent Discussion — 積み重ねの土台

プロジェクトを開くと着くのが discussion 表示（エージェントとの対話）です：エージェントとの会話と、プロジェクトを見せるサイドバー。ここが 1 階です。ほかのモードはすべてこの上に積み重なり、最後にはここまで閉じて戻ってきます。（セクション 2 の*ホーム画面*はまったくの別物です — あちらはプロジェクトを開く前にいる場所、ここは開いたあとにいる場所です。）

ここにあるもの：

- **チャット。** メッセージを打ち、⌘Enter（または送信ボタン）を押します。返事は流れるように届き、エージェントは話しながら動けます — ファイルを読み書きし、シェルコマンドを走らせ、ページを取ってきて — ツールの呼び出しは、起きたそばから記録に現れます。
- **マイクボタン。** クリックして口述してください。音声はローカルの whisper.cpp で文字起こしされ、あなたの声がマシンを出ることはありません。録音中はボタンが脈打ちます。もう一度クリックで止まります。
- **サイドバー。** プロジェクトのファイルツリーと、操作の欄：有効な**パラダイム**、**スキル**と**ロール**のオン／オフ、そしてあなたの**リクエスト**。ファイルやフォルダを option+クリックするとコンテキストメニューが出ます（新規ファイル、新規フォルダ、パスをコピー、名前をコピー）。⌘\ でサイドバー全体を隠したり出したりできます。
- **上部バー。** モデルウィンドウ、ブローカー、UI ウィンドウ、wikisink（🚰）、cacheawl のボタン — そして右端に、いま重なって開いているモードの印（セクション 12）。

### 4.1 AGENT.md と MOTIVATION.md

どのプロジェクトも、この 2 つのファイルを `rness/` に自分のコピーとして持っています。エージェントの正体の根であり、両方が毎ターン読み込まれます。

**`AGENT.md`** は*どう*のほう：作業の指示です。口調、歯止め、作法、いつも守ってほしいこと。「文章は小文字のままで」「`archive/` の中のファイルには絶対に触らないこと」「1 行を超えるシェルコマンドを走らせる前に尋ねること」。

**`MOTIVATION.md`** は*なぜ*のほう：目の前の作業を越えた価値観と優先順位です。このプロジェクトは何のためで、誰のためか、どのトレードオフが大事か（速さより正しさ？　網羅より簡潔さ？）、そして「終わった」がどんな感じか。

サイドバーでどちらかのファイルをクリックすれば読めます。**カスタマイズ**を押せばプロジェクト専用のコピーに分岐しますし、好きなエディタで編集しても構いません。変更は次のメッセージから効きます。ロールも同じ 2 ファイルの型を使います（セクション 15）— 主エージェントは特別ではなく、ただ最初にいるだけです。

### 4.2 policies フォルダと許可リスト

`rness/policies/` には、エージェントの動かせない規則が入っています。人格ではなく、法です。既定では 4 つのポリシーが同梱されています：

- **`allowlists.md`** — 手の届く範囲の規則。一覧は 3 つ：
  1. *読み取りを許すパスの接頭辞：* プロジェクトの外でエージェントが読んでよい絶対パス（既定は `~/enough/`）。
  2. *読み書きを許すパスの接頭辞：* プロジェクトの外で書き込みもしてよいパス。この一覧は**空**で出荷されます：箱から出したままなら、エージェントが書くのはあなたのプロジェクトの中だけで、あなたが自分でパスを足すまでそのままです。
  3. *インターネットのドメイン：* 直接取りに行くホスト（既定には `gutenberg.org`、`en.wikipedia.org`、`en.wikisource.org`、`archive.org`、`standardebooks.org`、そして Kiwix のダウンロードホストが入っています）。一覧に無いドメインは、遮断されるのではなく、ローカルの Tor プロキシ経由に回されます。ちょっとした調べ物で、どこかのサーバーのログにあなたのアドレスを残さずに済むように。ブローカーの切り替えでこの逃げ道を切れば、一覧外の取得はそのまま失敗します。
- **`context-management.md`** — 埋まっていくコンテキストウィンドウをどう感じ取り、状態を失わずに行儀よくリセットするか（セクション 7.3）。
- **`requests.md`** — 長く続く仕事を、いつ、どうリクエストファイルとして追いかけるか（セクション 7.3）。
- **`profile-maintenance.md`** — プロジェクトプロファイルに書くべきもの、書かないもの（セクション 7.1）。

ポリシーもほかと同じく defaults からシンボリックリンクされているので、許可リストを全体で締めることも、もっと緩い（あるいは厳しい）範囲が要る 1 つのプロジェクトのためだけにカスタマイズすることもできます。実際にいちばんよくあるカスタマイズが `allowlists.md` の編集です：信頼しているドキュメントのサイトを足し、エージェントに書かせたい共有フォルダを足して、あとは一日を進めてください。

## 5. read/edit モード

ツリーのファイルをクリックすると、ひとつにまとまった read/edit モード（読み／編集）で開きます。ひとつのモードに*面*が 2 つ：見直すための**読む面**（目）と、文章を変えるための**編集の面**（鉛筆）です。

### 5.1 全画面とミニ、そしてすべてのあいだの行き来

read/edit の大きさは 2 通り。**ミニ**はチャットの隣のサイドパネルです：話しながら、資料を肘のあたりに置いておけます。（ミニパネルにはレビューのツールバーをあえて置いていません — 読むことと軽い編集のためのもので、書き込みのためではないからです。）**全画面**は画面いっぱいを取ります。長いドキュメントや、腰を据えた編集のために。

大きさはパネルの枠のミニ↔全画面ボタンで、面はその隣の面切り替えボタンで変えます。編集の面では ⌘S で保存します。いま見ているものが変換されたドキュメントのツインなら、枠には元ファイルの名前も出て、変更を書き戻すための**書き出し**ボタンが付きます（セクション 6.5）。そしてすべてに未保存の見張りが付いています：保存していない編集があるとき、enough はそれを捨てさせる前にかならず尋ねます — 別のファイルへ移るとき、モードを閉じるとき、別のドキュメントへ跳ぶとき。うっかりのクリックで 1 時間分の仕事を失うことはありません。

ドキュメントを開いているあいだ、上部バーに 3 つの数が出て、あなたの打鍵に付いてきます：**¶** 段落、**W** 語、**C** 文字。（ホーム画面のリスト表示は、同じ 3 つの合計をプロジェクト全体について見せます — セクション 2.1。）

ほかの全画面モードと同じく、read/edit も右上の印の場所に自分のアイコンを出し、閉じるための小さな赤い × のリボンを下げています（セクション 12）。

### 5.2 ハイライト

どの markdown ドキュメントでも、読む面で文章を選べば、4 色 — **黄、緑、青、ピンク** — のどれかで塗れます。ツールバーからでも、選択の上に出るポップアップからでも。同じツールバーが軽い書式も出します：太字、斜体、下線（⌘B / ⌘I / ⌘U）。

ハイライトは消えませんし、本文の外側に暮らします：ドキュメントごとに隠しの伴走ファイル（`.<filename>.highlights.json`）ができるので、あなたの文章にマークアップが割り込むことはなく、ドキュメント自体はきれいなままです。ハイライトされた行には、余白に色の帯が付きます。ハイライトはセッションをまたいで残り、色が重なれば重なったまま積まれます。

ここからが、仕事のやり方を変えるところです：エージェントにもハイライトが見えます。`read_highlights` ツールはドキュメントの中のハイライトを色ごとに並べ、`navigate_to_highlight` はそのひとつへ表示を飛ばします。これでハイライトは、ひとつの通信路になります。書き直してほしい 4 つの段落を黄色に、気に入っている 2 つを緑に塗って、「黄色のところを書き直して。緑のところの調子は残して」と言えばいい。あなたが色を口にしたとき、エージェントはそれがあなたのハイライトのことだと分かっています。

### 5.3 対応しているファイル形式

- **markdown（`.md`）** は、読む面では整形されて、編集の面ではソースとして出ます。markdown は enough の母語です — このシステム自身が書くもののほとんどが markdown です。
- **平文テキスト**と、テキストらしいものはすべて、read/edit でテキストとして開きます。
- **`.girraph`** ファイルは、かわりに girraph モードで開きます（セクション 17）。
- **`.merirmaid`** ファイルは、かわりに merirmaid モードで開きます（セクション 18）。
- **保存した Wikipedia の記事**（`wiki/` フォルダの中の `article.html`）は、wikisink の読み手で完全なまま開きます（セクション 10.2）。
- **Word ドキュメント、PDF、電子書籍、スライド、ワークブック**は、編集できる markdown の**ツイン**として開きます — ツリーでは 1 行、クリックは 1 回、そして枠には変更を書き戻すための**書き出し**ボタン。それがセクション 6 で、話はそこにすべてあります。
- **画像**（`.png`、`.jpg`、`.gif`、`.webp`、`.bmp`、`.svg`）は素のビューアで開きます（セクション 6.9）。ドキュメント*の中*の画像は、markdown のほかの絵と同じように読む面で描かれます。

enough はいまもテキストのシステムですし、これからもそうです：描くのは markdown であって、ページのレイアウトではありません。それ以外のものに対してすることは、変換です — 中で仕事ができる程度には損なわず、何が生き残らなかったかを言う程度には正直に。

## 6. PDF、Word ドキュメント、その他のファイルを扱う

enough は PDF を描画しませんし、Word ドキュメントのレイアウトもしませんし、表計算も描きません。そのふりもしません。かわりにすることは、もっと静かで、ここでするような仕事にはもっと役に立ちます：ドキュメントを、実際に読めて、編集できて、ハイライトできて、エージェントに渡せる markdown に変換し、その markdown を元ファイルにつなぎ止めておく — だから、あなたの変更は帰れるのです。

これのどこにも、別のモードや別のアプリはありません。ファイルをクリックする。開く。それだけです。

### 6.1 ツイン

`memo.docx` を開くと、enough はその隣に `memo.docx.md` を書きます。この 2 つめのファイルが**ツイン**：ドキュメントの素の markdown コピーで、あなたのプロジェクトフォルダに座り、ほかと同じように編集できます。これを作っても、元ファイルには決して手が入りません。

ファイルツリーに見えるのは 1 行のまま — `memo.docx` です。ツインと、ドキュメントから取り出された画像のフォルダ（`memo.docx.assets/`）と、何を何から変換したかを記録した小さな隠しファイルは、すべてその 1 行に畳み込まれます。だからあなたのプロジェクトは、Finder で見たときの姿のままでいられます。行をクリックすればツインが read/edit モード（セクション 5）で開き、そのモードが与えるものはすべて使えます：2 つの面、⌘S、未保存の見張り — そして全画面にすればハイライトも。

知っておくとよい帰結が 2 つ。名前がぶつかることはありません：あなたが書いた `memo.md` と `memo.docx.md` は別のファイルで、enough が取り違えることはありません。そして Finder で `memo.docx` を消しても、何も壊れません — ツインは静かに、ツリーの中のふつうの markdown ファイルになります。もともとそれ以上のものではなかったのです。

エージェントにも、あなたと同じものが見えています。`report.pdf` を読んでと頼めばツインが渡され（まだ無ければ先に 1 つ作られます）、何かを変えてと頼めばツインを編集します。あなた自身の編集が行くのと、まったく同じ場所です。

### 6.2 enough がこの形で開けるもの

この一覧は、誰かが更新を思い出さなければならない文章ではなく、アプリ自身から来ます — enough の外でこれを読んでいるなら、アプリでヘルプセンターを開けば（セクション 9）中身の入ったものが見られます：

{{convert-formats}}

### 6.3 ツリーの中のバッジ

変換できるドキュメントはどれも、行の右端に小さなバッジを付けています。バッジの仕事はきっかりひとつ：2 つの半身がまだ一致しているかどうかを伝えることです。

- **静か** — 変換済みで、両側が一致。することはありません。
- **点灯、あなたの色** — あなたがツインを編集しました。その変更は markdown にあって、まだ元ファイルにはありません。用意ができたら書き出してください（セクション 6.5）。
- **点灯、エージェントの色** — 変換されたあと、元ファイルが enough の外で変わりました。誰かが Word で編集した、新しいコピーが上に落ちてきた、共有ドライブから降りてきた。
- **点灯、エラーの色** — 上の 2 つが両方。enough があなたに尋ねる唯一の場面で、実際に尋ねます（セクション 6.7）。
- **中抜き** — 変換できるが、まだ変換していない。クリックすれば変換されます。
- **中抜きで、クリックするとエクストラの説明が出る** — まだそれを読めないインストールでの PDF、スライド、ワークブック（セクション 6.8）。

バッジにカーソルを置けば、同じことが一文で出ます。バッジをクリックしたときの動きは、ファイル名をクリックしたときとまったく同じです。

### 6.4 初めて開くとき

ドキュメントの*種類*ごとに、初めて開くときだけ、これから何が起きるかを短いモーダルが説明します — ツインとは何か、どこに置かれるか、元ファイルはそのままだということ。ボタンは OK ひとつ。ファイルごとではなく種類ごとに一度なので、2 つめの Word ドキュメントはただ開きます。

オフィス文書の変換は速く、ふつうのものなら 1 秒もかかりません。走っているあいだ、隅に小さなトーストが出て、時間のかかるものには**キャンセル**ボタンが付きます。PDF はもっと時間がかかり、正直な進捗バーが付きます（セクション 6.8）。

### 6.5 変更を書き出して戻す

開いたツインは、その枠に**書き出し**ボタンを持っています。モーダルはひとつ、決めることは 3 つ：

**どの形式か。** 元ファイル自身の形式があらかじめ選ばれていて、ほかの書き出し先も並びます — Word ドキュメントは PDF にも、EPUB にも、単体で完結する HTML ページにもできます。その形式にできないことは、理由つきで灰色になります。黙って消えることはありません。

**コピーか、元ファイルか。** 既定は元ファイルの隣に書かれる**日付入りのコピー** — `memo-2026-08-19-1042.docx` — で、確定する前に正確なファイル名がモーダルに出ます。何も危険はありません：新しいファイルが 1 つできて、古いほうは無傷です。2 つめの選択肢は元ファイルをその場で上書きするもので、書き出し先が元ファイル自身の形式のときにだけ出ます。これを選ぶと、enough はあとから**取り消し**を差し出します：新しいファイルを残すか、古いバイト列を 1 バイトも違わず戻すか。

**これから同期を保つかどうか** — セクション 6.6 へ。

この旅で何が生き延びるかについて、ひとこと。`.docx` や `.odt` を上書きするときは元ファイルをスタイルの手本として使うので、ページサイズ、フォント、ランニングヘッダーやフッターは、あなたの文章と一緒に帰ってきます — markdown では表しようがなく、そうでなければ失われていたものです。markdown が本当に運べないものは帰りません：変更履歴とコメント（取り込むときに反映して落とします）、テキストボックス、フィールド、画像の精密なサイズ指定。この非対称さこそが、日付入りコピーが既定である理由であり、enough が自分の判断で元ファイルを書き換えない理由です。

### 6.6 元ファイルを同期しつづける

書き出しのモーダルで**元ファイルを同期しつづける**にチェックを入れると、ツインを保存するたび、元ファイルも静かに書き直されます。enough で編集していれば、同僚に求められたときの `.docx` はいつでも最新です。ファイルごとの設定で、チェックを入れたその瞬間から効き、保存が向こう側まで届くたびに小さな確認が出ます。

これは書き戻せる形式にだけ出ます — Word、OpenDocument、リッチテキスト、EPUB。セクション 6.2 の「同期できるか」の列が正です。PDF は参加できず、その理由ははっきり言う値打ちがあります：enough は markdown から PDF を*書け*ますが、そのとき組版を一から作り直します。同期される PDF は、保存のたびに、丹念にレイアウトされた元ファイルを、言葉だけを素で組み直したものに置き換えてしまう。それは同期ではなく取り壊しなので、差し出さないのです。

### 6.7 両側が変わったとき

元ファイルは、あなたを置いて先へ進むことがあります。あなたはここでツインを編集し、誰かが Word で `.docx` を編集する。いま、真実が 2 つあります。

enough は気づきます。大事な瞬間 — ツリーが描かれるとき、ドキュメントを開くとき、保存するとき、書き出すとき — のたびに、変換時に記録した内容と元ファイルを比べます。単に*触られた*だけのファイル（コピーされた、バックアップされた、開いて閉じられた）は数えません：この確認はタイムスタンプではなく中身を読みます。

本当に両側が変わっていたとき、平たい言葉で 3 つの選択肢を出すモーダルが現れます：

- **ツインを残す。** 何も書きません。バッジは「あなたが変えた」に戻り、判断はあとに回ります。
- **元ファイルに書き出す。** あなたの markdown が勝ち、元ファイルは書き直され、いつものように取り消しが差し出されます。
- **元ファイルから変換し直す。** 元ファイルが勝ち、新しいツインが書かれます — そして古いツインは、削除されるのではなく、その隣に取り消し用のファイルとして退避されます。

このモーダルのどの選択肢も、取り返しのつかないものを壊しません。この機能全体が、その設計の決まりの上に立っています。

### 6.8 PDF、スライド、ワークブックを読む：PDF エクストラ

PDF を読むのは、Word ファイルを読むより難しい問題です。`.docx` はまだ、見出しとは何かを知っています。PDF が知っているのはインクがどこに落ちたかだけで、そこから表や 2 段組やスキャンを取り出すには、本物のドキュメントモデルが要ります。そのモデルは大きいので、基本のインストールには入っていません — かわりに、ワンクリックのところに置いてあります：**⚙ UI ウィンドウ → extras → PDF エクストラをインストール**。

かかるものを、正直に：

- ダウンロードで約 **250 MB**、インストール後のディスクで約 **1 GB**。
- 加えて**モデルの重み約 0.7 GB**。一度だけ取ってきて、`~/enough/weights/docling/` に置かれます。
- 時間は数分、ほとんどはダウンロード。インストーラはログをウィンドウに流すので眺めていられますし、エンジンは動いたまま切り替わります — 再起動は要りません。

手に入るもの：**PDF**（スキャンされたものも含みます。文字は OCR でピクセルから読み出されます）、**PowerPoint のスライド**（各スライドが見出し付きのセクションになります）、そして **Excel のワークブック**（各シートが markdown の表になります）。

速さは、当て推量ではなく実測で、Apple silicon にて：デジタルの PDF で 1 ページあたり約 **0.9 秒**、加えて変換ごとに 1 回だけ約 **10 秒**のモデル読み込み。ですから 1 ページの PDF で約 10 秒、100 ページの本で 1 分半ほど、スライドやワークブックなら数秒です。長い変換は進捗を出し、途中で止められます。止めても何も残りません — 書きかけのツインも、迷子のフォルダも。

あとで首をかしげずに済む話が 2 つ。ひとつめ：**PDF を書き出すのに、これは何ひとつ要りません。** どのツインも、エクストラの有無にかかわらず、どのインストールでも PDF に書き出せます。それをする組版器が enough に同梱されているからです。エクストラは*読む*ためのものです。ふたつめ：入れたはずのマシンで「エクストラが必要です」と出たら、どちらの文言が出たかを読んでください — パッケージとモデルの重みは別々のダウンロードで、途中で切れた接続は、前者だけあって後者が無い状態を残すことがあります。もう一度インストールを走らせれば仕事は仕上がり、すでに持っているものを取り直すことはありません。

更新してもエクストラは残ります。`update-enough.command`（と `/update-enough`）は、あなたが何を入れたかを覚えていて、同期のたびにそれを取り直します。日常の更新が、PDF の読み込みを黙って取り上げることはありません。

### 6.9 画像と、元ファイルを見ること

画像をクリックすると素のビューアで開きます：既定は幅に合わせ、クリックすれば実寸に切り替わってスクロールでき、透明なところの後ろには市松模様、ヘッダーには名前、ピクセル寸法、ファイルサイズ。読み取り専用です。enough は画像エディタではありませんし、そちらへの野心もありません。

ドキュメント*の中*の絵は話が別で、ちゃんと渡ってきます：Word ファイルの中の写真は `memo.docx.assets/` に取り出され、ツインの読む面で、markdown のほかの画像とまったく同じように描かれます。

そしてツインでは足りないとき、PDF の枠には**元ファイルを見る**があります：実際の PDF をパネルに開くので、ツインを本物のページと突き合わせられます。閉じれば、離れたところからツインに戻ります。

### 6.10 変換で失うもの、2 文で

自分で見つけてもらうより、声に出して名指しておく値打ちのある限界が 2 つ。ワークブックのシートは、**シート名の見出しなしで**表が続けて並ぶ形で届きます — リーダーがそれを出さないので、enough はラベルをでっちあげるより空白を残すほうを選びます。そして PDF から取り出された絵には、毎回「Image」という代替テキストが付きます：ファイルの中に、もっとよい名前をあげられるキャプションが無いのです。

それを越えたところに、変わらない約束があります：**あなたの元ファイルは、あなたが頼まないかぎり変更されません。** 変換がすることは、その隣に新しいファイルを書くことだけです。元ファイルに触れる道は書き出しの上書きただひとつで、それには意識したクリックが要り、そして取り消しが残ります。

## 7. プロジェクトフォルダと `rness/`

プロジェクトとはフォルダです。どんなフォルダでも構いません。enough がそこに足すものはきっかりひとつ、`rness/` — このプロジェクトにおける、外に出されたエージェントの頭です。ここでエージェントであるもの、知っていること、覚えていることは、すべてそのフォルダの中にふつうのファイルとして置かれます。全部読めますし、全部編集できますし、その習慣があるなら git に入れても構いません。

構成はこうです：

```
your-project/
  rness/
    AGENT.md            who the agent is here          (4.1)
    MOTIVATION.md       why it works                   (4.1)
    active-paradigm     which paradigm is in force     (14)
    paradigms/          available reasoning frameworks (14)
    skills/             available skills               (16)
    roles/              available personas             (15)
    policies/           the hard rules                 (4.2)
    knowledge/          project memory                 (7.1)
    io/                 input/output workspace          (7.2)
    requests/           long-running work tracking      (7.3)
  ...your actual files...
```

シンボリックリンクの項目（ツリーでは斜体）は全体の既定に付いていきます。どれでもカスタマイズすれば、ローカルのコピーに分岐します（セクション 3.1）。どんな手段で置かれたファイルでも — Finder、別のエディタ、エージェント — 次のターンには全員に等しく見えています。

変換されたドキュメント（セクション 6）も、ここにファイルを足します。いつでも元ファイルの隣、いつでもその名前にちなんで：`memo.docx` にはツイン `memo.docx.md`、絵は `memo.docx.assets/`、そして何を何からいつ変換したかを記録する隠しの `.memo.docx.convert.json`。ツリーはこの 3 つを元ファイルの行に畳み込みますが、ディスク上ではふつうのファイルです — 2 つまとめて別のマシンにコピーしても、git に入れても、ツインを消して元ファイルをまたクリックして新しいものを作らせても構いません。隠しのマニフェストは enough の帳簿です。放っておけば正確なままですし、消せば enough は単に、そのドキュメントを一度も変換していないものとして扱います。

### 7.1 knowledge フォルダ

`rness/knowledge/` は、プロジェクトごとの記憶です。

**`project-profile.md`** は、このフォルダでいちばん役に立つファイルです。中身は毎ターン、エージェントのシステムプロンプトに流し込まれます：ここに書かれていることは、探しに行かなくてもエージェントの作業記憶に入っています。エージェントは働きながらこれを手入れします — 観察したあなたの好み、よく出てくるファイルや人、採用した作法、開いたままの糸口 — そしてあなたも直接編集できます。毎回のセッションで繰り返すかわりに、いつもの好みはプロファイルに一度書いてください。profile-maintenance ポリシーがこのファイルを引き締めます：漠然としたラベルではなく具体的な観察を、書庫ではなく蒸留を。

**`session-logs/`** には、各セッションのやりとりを日付ごとにまとめた markdown のログと、ブローカーの日誌（セクション 8）が入っています。追記だけの履歴です。先週の火曜に何があったかを組み立て直したいときに、眺めるなり grep するなりしてください。

その 2 つを別にすれば、このフォルダはあなたのものです。`glossary/` のサブフォルダ、学んだことのファイル、背景メモ — ここに置いたものは何でも、エージェントが参照できます。

### 7.2 io フォルダ

`rness/io/` は、通り抜けるための作業場です：

- **`input/`** — エージェントに処理してほしいファイルを置きます。取ってきたウェブページも、markdown に変換されキャッシュされて自動的にここへ降りるので、一度取ったページは永遠に足場になります。
- **`output/`** — 生成物が降りる場所。目を通し、よいものは残し、あとは片づけてください。
- **`cloud-cache/`** — クラウドのモデル枠を使っているなら、クラウドとのやりとりはすべてここに記録されます（セクション 13.2）。クラウドでの仕事も、ローカルに、grep できる紙の跡を残します。

### 7.3 リクエスト：長い仕事はどう生き延びるか

これは駆け足の案内にはあまり出てきませんが、複数のセッションにまたがる仕事を可能にしている仕組みなので、2 分の値打ちがあります。

1、2 ターンでは終わらないことを頼むと、エージェントは `rness/requests/` に**リクエストファイル**を開きます：目的、進捗のチェックポイント、道すがらの判断を記した markdown です。こちらから頼む必要はありません。仕事のかたちを見て取るのは、エージェントの仕事です。

このファイルが大事なのは、コンテキストウィンドウが埋まるからです。enough は会話の圧力を見ていて — context-management ポリシーに従い — あふれる前に、エージェントが状態を、動いているリクエストファイルにチェックポイントとして書きます。オーケストレータの設定によって、enough はそのあと自動でリセットする（メモリ上の会話を消し、チェックポイントから新しく再開する）か、バナーを出して止まり、あなたの用意ができたときにリセットさせます。どちらにせよ、本当の記憶は会話ではなくファイルシステムです：新しいセッションはリクエストファイルの継続ブロックを読んで、物事が立っていたところから続けます。

終わったリクエストは `rness/requests/done/` に移ります — 開いているリクエストで**完了にする**を押すか、エージェントに言ってください。done フォルダはエージェントからは書き込めないようになっていて、二人が実際に世に出したものの、正直な日誌も兼ねています。

## 8. ブローカーウィンドウ

ブローカーは enough の信頼の錨です。エージェントが行うツールの呼び出しはすべて — ファイルの読み、書き、シェルコマンド、ウェブの取得 — ここを通ります。🔀 のブローカーウィンドウは、それを眺め、調整する場所です。

切り替えは 11 個、いくつかの組に分かれています：

| 切り替え | 何を制御するか |
|---|---|
| trace log | ブローカーが日誌を書くかどうか、そもそも |
| local models only | クラウド枠（OPRO-API）をモデル選択に出すかどうか |
| read_file / write_file / shell brokered | ツールごとのトレース記録。1 つずつで計 3 つ（許可リストは、これに関係なく*常に*効きます） |
| fetch_url enabled | エージェントのウェブ取得ツールがそもそも動くかどうか |
| Tor for off-list fetches | 許可リスト外のドメイン：Tor 経由にする（オン）か、断る（オフ）か |
| cache & convert fetches | 取ってきたページを markdown に変換し、`rness/io/input/` にキャッシュするか |
| wikisink tools | エージェントの 4 つの wiki ツールが動くかどうか（あなた自身の 🚰 での閲覧は決して止められません） |
| wikisink live updates | 更新の実行が Wikipedia に接触してよいかどうか（オフ = ローカルの状態だけからレポート） |
| cacheawl tools | エージェントのキャッシュボックスツールが動くかどうか（あなた自身の cacheawl モードは決して止められません） |

既定はすべてオンです：既定の姿勢は、エージェントにプロジェクトを任せ、紙の跡で誠実さを保つというもの。その跡 — **トレース日誌** — は `rness/knowledge/session-logs/<date>-broker.md` に降ります：ブローカーを通った呼び出しごとに、時刻、ツール、判断、引数、結果。そして切り替えや許可リストが何かを止めたとき、エージェントには「何がなぜ止められたか」を書いた明快な拒否メッセージが届くので、黙って失敗するかわりに、あなたに伝えられます。

この表にある設計の原則に気づいてください：エージェントのツールを閉じる切り替えは、決して*あなたの*インターフェイスを閉じません。cacheawl tools を切っても、あなたが cacheawl モードから締め出されることはありません。エージェントが自分で保管庫に手を伸ばせなくなる、というだけです。

## 9. UI ウィンドウとヘルプ

⚙ の UI ボタンは、表示の設定と参照資料を開きます。そのウィンドウの右上、× の隣に小さな**ヘルプ**ボタンがあります：このマニュアルを読み取り専用で、アプリの中に、ほかと同じ全画面モードとして開きます（セクション 12）。

出口はいまタイトルバーに乗っています：**プロジェクトを閉じる → ホーム**が、ヘルプボタンの隣に。このセッションを終えてホーム画面に戻ります（セクション 2.5）。実行の前に尋ねますし、何を*しない*かも書いてあります — ディスク上のフォルダには触れません。アプリでならたぶん ⌘W に手が伸びるでしょう。このボタンは同じもので、ブラウザで enough を動かしているときは*唯一の*ものです。（閉じるプロジェクトが無いホーム画面には、これはありません。）

ここにはもうひとつ、enough の中からインストールできる唯一のものもあります：**PDF の読み込み**のための **extras** の行です（セクション 6.8）。行にはいまの状態が出ます — 未インストール、インストール中、インストール済み、あるいはインストール済みだが未完了 — そしてインストールボタンは走りながらログをすべてウィンドウに流すので、長いダウンロードは、待ち構えるものではなく眺めるものになります。終われば PDF が開くようになります。再起動は要りません。

### 9.1 テーマ

enough には 4 つ同梱されています：**Enough Default**（深い青紫のダーク）、**Pastel**（淡い紙。Terminal の「Man Page」配色の精神で）、**Wireframe**、**Darknest**。切り替えは即座で、インターフェイスのアイコンはすべて、明るい版と暗い版をその場で導き直します。

テーマは焼き付けられていません。`~/enough/config/ui.json` に、名前の付いた色の値の塊として置かれ、それぞれが CSS のカスタムプロパティとして当てられます。既存の塊をコピーして名前を変え、色を変えて読み込み直せば、あなたのテーマがドロップダウンに入ります。ファイル先頭の `_doc` の塊が、各キーを説明しています。

### 9.2 フォント

同じ型です。同梱の 4 組 — SF Mono、システムのサンセリフ、Georgia のセリフ、Courier — と、同じ `ui.json` へのあなた自身の追加を歓迎します。大きさについては、下のダイヤル 2 つを（セクション 9.3）。そしてブラウザのタブでなら、昔ながらのブラウザのズーム（⌘+ / ⌘−）も、その上から問題なく効きます。

### 9.3 大きさ — ui scale と text scale

ここでの答えはずっとブラウザのズームでした。ブラウザに包まれていないデスクトップアプリが現れるまでは。そこで enough は自前のものを育て、ついでにもう一歩よくすることにしました：ひとつではなくふたつのダイヤルを、テーマの下の行に。

**ui scale** は*すべて*の大きさを変えます — アイコン、ラベル、サイドバー、チャット、まさにこのウィンドウ — 0.1 倍刻みで。**text scale** は目の前のドキュメントだけを変えます：read/edit のページ、wikisink の記事、ファイルのプレビュー、リファレンスモードのこのマニュアル。ふたつは掛け合わさり、互いの邪魔をしません：0.9 倍のインターフェイスに 1.5 倍の文字は、原稿を読むのにまったく理にかなった構えですし、その逆は、午後の視界から原稿を追いやるのにまったく理にかなった構えです。どちらかの数字をクリックすれば、そのダイヤルだけが 1.0 倍に戻り、もう一方はそのままです。

どちらも**プロジェクトフォルダごとに**覚えられます — 部屋の向こうから読む原稿と、机で開くメモは、それぞれ自分の大きさを持ち、どちらも相手を引きずりません。ホーム画面は素の大きさのままなので、そこにダイヤルは出ません。

限界はあなたの画面に合わせて呼吸します：いまどきのディスプレイでおよそ 0.5 倍から 2 倍。小さなウィンドウでは締まり（インターフェイスがインターフェイスでいられるだけの余地を、いつでも残すために）、とても大きくとても密な画面では緩みます（2046 年の 8K の壁なら 3 倍まで）。ひと刻みで線を越えるとき、ボタンは身をよじり、数字は赤く脈打ち、何も変わりません — それが、エラーメッセージのすべてです。

### 9.4 言語

インターフェイスは 6 つの言語を話します：英語、フランス語、スペイン語、ドイツ語、中国語、日本語。同じ行の **ui language** ドロップダウンが、目に見えているものすべて — ラベル、ツールチップ、`(?)` バブル、このマニュアル — をその場で切り替えます。再起動は要りません。選択はマシン全体のもので、テーマと同じように `ui.json` に乗るので、ホームもすべてのプロジェクトも同じ言語で揃います。

これがあえて*触らない*もの：あなたのファイル、あなたのチャット、あなたのエージェント。エージェントとは好きな言語で話してください — ローカルのモデルはこの 6 言語のどれでも心地よく振る舞います — が、enough は自分の足場（スキル、パラダイム、プロンプト、プロジェクトファイル）を英語のままにします。モデルがいちばん確かに読むのがその言語だからです。生成されるものの一部も英語のままです — *あなたの*マシンに入っているものから生で引かれる一覧、たとえばバブルの中のスキルや、ファイル形式の表。そして、新しい英語のラベルに翻訳が追いつけていないところでは、空白ではなく英語が出ます：見た目は劣りますが、壊れてはいません。見つけたら、それはバグです — [enough.support](https://enough.support) が歓迎します。

### 9.5 チートシート

UI ウィンドウの中に、参照が 2 列。

**キーボードショートカット：**

| キー | 動作 |
|---|---|
| esc | いちばん上のモードを閉じる |
| ⌘ \ | サイドバーの表示／非表示 |
| ⌘ K | チャット入力にフォーカス |
| ⌘ Enter | メッセージを送信 |
| shift Enter | 送信ではなく改行 |
| ⌘ B / I / U | 選択範囲を太字／斜体／下線（読む面） |
| ⌘ S | 保存（編集の面） |
| ⌥ クリック | ファイルツリーのコンテキストメニュー |

（Mac 以外のキーボードでは：⌘ は Ctrl、⌥ は Alt。）

これらはインターフェイス自身が扱うショートカットなので、アプリでもブラウザのタブでも同じように効きます。アプリはメニューバーから、自分のものを 2 つ足します：**⌘W** はプロジェクトを閉じてホーム画面に戻り（セクション 2.5）— もうウィンドウは閉じません — **⌘Q** は、これまでどおり終了します。

**markdown のチートシート：** 見出し、リスト、リンク、コード、引用 — markdown にまだ慣れきっていない人のための、ひととおりの早見表です。慣れておく値打ちはあります。enough はどこでもそれを母語として話すので。

### 9.6 手元のヘルプ（IHH）

インターフェイスのあちこちに散らばる `(?)` バブルが、組み込みのヘルプです：概念 1 つにバブル 1 つ — スキル、ロール、パラダイムの選択、rness、io、knowledge、cacheawl、wikisink、モードの仕組み、変換されたドキュメント、等々 — それぞれに **what**、**how**、**ideas** の一覧が付いています。スキル、ロール、パラダイムのバブルは、*あなたの*プロジェクトに実際に入っているものを並べますし、変換されたドキュメントのバブルは、アプリ自身の形式レジストリからファイル形式の表を引いてきます — すべて生成されたてなので、ヘルプが現実とずれることがありません。（このマニュアルのセクション 6.2 に出る表も、同じ出どころです。）

バブルは、UI ウィンドウの「ヘルプ (?) バブル」チェックボックスで、プロジェクトフォルダごとに制御します。新しいフォルダでは既定でオン、設定はフォルダごとに残ります — だから、毎日の相棒になった歴戦のプロジェクトは静かにしていられて、生まれたての実験は補助輪を付けたままでいられます。

ヘルプさえカスタマイズできます。中身は markdown ファイル 1 つ（`enough/static/help-docs.md`）にあり、それを編集すればバブルが変わります。

## 10. Wikisink

wikisink（🚰）は、英語版 Wikipedia のオフラインコピーをあなたのマシンに置きます：アプリの中で読めて、全文検索でき、エージェントも読めて、注釈を付けられて、変更レポートつきで好きなときに更新できます。セットアップが済めば、インターネットはまったく要りません。

### 10.1 セットアップ

🚰 を初めてクリックすると、ウィザードが 3 つのことを尋ねます。

1. **サイズ。** アーカイブは Kiwix のビルドで、断りがなければテキストのみです：

   | 版 | 中身 | おおよそのサイズ |
   |---|---|---|
   | 上位 100 万記事 *(既定)* | いちばん読まれている 100 万件 | 約 16 GB |
   | 英語版 Wikipedia のすべて | 全記事 | 約 49 GB |
   | 上位 5 万 | いちばん読まれている 5 万件 | 約 2.1 GB |
   | 上位 5 万 mini | 上位およそ 5 万件、導入部だけ | 約 320 MB |
   | Simple English | Simple Wikipedia のすべて | 約 950 MB |

2. **置き場所。** 既定は `~/enough/wikisink`。どのフォルダでも、外付けドライブでも構いません。アーカイブのサイズに加えて 5% ほどの余裕を残しておいてください。
3. **確認。** ダウンロードは中断から再開でき、終了しても生き延びます — 同じウィンドウから一時停止、再開、中止ができ、そのあいだも enough のほかの部分は動き続けます。

アーカイブは `.zim` ファイル 1 つで、その場のまま読まれます。展開されることはなく、ファイルマネージャーを散らかすこともありません。**複数のインストール**を登録することもできて — たとえば外付けドライブに全体、内蔵ディスクに小さいもの — ⚙ のインストール一覧で切り替えられます。ドライブを外しても何も壊れません：そのインストールが「届きません」と出るだけで、ドライブが戻れば戻りますし、あなたのコメントと上書き設定は、どのアーカイブとも独立に暮らしています。

入れてしまえば、🚰 が読み手を開きます：戻ると進む、検索欄での見出し候補の即時表示（Enter でアーカイブ全体の全文検索）、🎲 のランダム記事のサイコロ、そして今読んでいるものがアーカイブのスナップショットなのか（`ZIM <date>`）、更新の実行で得た新しいコピーなのか（`live <date>`、つまり「最新」）、保護されたコピーなのか（`preserved`、つまり「保護」）を教える出どころのバッジ。内部リンクはアプリの中に留まり、外部リンクはブラウザで開きます。下のチャットピルが、いまの記事 — あるいは選択した一節 — をそのままエージェントに手渡します。

**新しいスナップショットのピル。** Kiwix はこれらのアーカイブを定期的に作り直しますし、あなたがそれを探しに行く必要はありません。*あなたの*版に新しいビルドが出ると、読み手のツールバーに小さなピルが現れます — `newer snapshot: <date> · <size>`。押してサイズを確かめれば、その場での入れ替えが走ります：同じ保存先フォルダに、先にダウンロードして、終わってから初めて差し替え、古いファイルはそのあとで消されます。その前ではありません。あなたのコメント、保存、🛡 の上書き設定はそのまま渡ります。どれもアーカイブの中には暮らしていないからです。ピルはダウンロード中は進捗の表示になり、それから消えます。enough がこれを確かめるのは 1 日に多くて 1 回、読み手が描画している最中には決してせず、オフラインのときは黙っています — オフライン Wikipedia の機能にとって、それがふつうの状態だからです。同じ入れ替えは遠回りの道、⚙ のインストール一覧からもできますし、エージェントの wikisink の実行もそれを報告します（セクション 10.3）— けれどボタンを押すのは、いつでもあなたです。

### 10.2 記事を保存し、鍵をかける

**保存。** 保存ボタンは行き先を 2 つ出します：このプロジェクトの `wiki/` フォルダか、すべてのプロジェクトで共有される、マシン全体の wiki キャッシュボックス（`~/enough/cacheawl/wiki/`）。どちらでも、保存 1 件はフォルダ 1 つ — `article.html`（アーカイブが持っていたままの、1 バイトも違わない記事）と、題名、出典 URL、取得日、CC BY-SA のライセンス行を載せた `_manifest.md`。保存された記事はどれも自分を説明できます。つまり、その文章がいつかあなたの発表するものに入っても、必要な帰属表示はもう隣に座っているということです。ツリーで保存された `article.html` をクリックすれば、アーカイブに手が届かないときでも、読み手で完全なまま開きます — インフォボックスも表も。保存をやめるには、ツリーでそのフォルダにカーソルを置き、現れる 🗑 をクリックしてください。

保存は*あなたの*ためのものです：オフラインのさらにオフラインのコピー、発表のための帰属表示。エージェントに保存は要りません — ツールが、アーカイブの中のどの記事でも、きれいなテキストとしてその場で読めます。

**コメント。** 文章を選んで 💬 を押すか、ツールバーの 💬 で段落単位のメモを付けます。スレッドは 🗨 のパネルに暮らします：返信、解決、再開、その場所へ跳ぶ。コメントは保存ファイルではなく*記事*に付き、記事の更新もゆるやかに劣化しながら生き延びます。まだ残っている文章には**そのまま留まり**ます。編集で消えた文章は、段落に**貼り直され**ます。段落ごと消えたときは、パネルの中で**宙に浮いた**まま残ります — 印は付きますが、自動で消えることはありません。

**鍵（削除の上書き設定）。** ライブの Wikipedia が、あなたの頼りにしていた記事を消してしまうことがあります。典型例は、品質ではなく「特筆性」を理由に切られたニッチな話題です。🛡 ボタンは、手元のコピーを永久に保ちます — それ以降は `preserved`（保護）のバッジ付きで供され、今後の更新からは外れ、検索にはかかり続けます。更新の実行のレポートは、検出した削除に実際に点数を付けるので（特筆性めいた理由は「疑わしい」、著作権侵害は「まっとう」）、どの削除に目を向ける値打ちがあるか分かります。そして上書きは、意図してあなただけのものにしてあります：エージェントは 🛡 を勧めることはできても、押すことは決してできません。

### 10.3 wikisink の更新と、変更レポート

「wikisink」は動詞でもあります。保存した記事、コメントした記事はすべて*監視中*で、エージェントに「wikisink を走らせて」と頼めば（あるいはエージェントが自分の `wikisink` ツールを呼べば）、監視中の一式をライブの Wikipedia と突き合わせ、報告してきます。1 回の実行は：

1. 変わっていた監視記事を、ローカルのオーバーレイに取り込んで更新します（バッジが `live` に変わります）。
2. **編集の急増**に印を付けます — 監視記事が急に 1 日に何十回も編集されているとき、加えて Wikipedia 全体での急増候補も。
3. 日次の**上位 1000 の閲覧数**を前回と比べます：上がったもの、下がったもの、新顔、脱落、そして監視記事の閲覧の傾向。
4. 監視中または最近見た記事の**削除**を確かめ、疑わしさに点数を付けます（セクション 10.2）。
5. **新しい基盤スナップショット**が出ていれば、それを書き添えます。数 GB の基盤アーカイブを入れ替えるかどうかは、いつでもあなたの判断です — 読み手のツールバーのピルを押すか（セクション 10.1）、⚙ のインストール一覧を使ってください。これを入れ替えるエージェント用のツールはありません。

レポートは markdown としてチャットに届き、上限のない完全版は wikisink の状態フォルダの下に残ります。実行は Wikipedia に対して礼儀正しく — まとめて、正直な User-Agent で — 中断されても再開でき、`report-only` の実行なら更新の段階を飛ばします。すべてを支配するのはブローカーの切り替え 2 つ：ひとつはエージェントの wiki ツールをまるごと閉じ、もうひとつは実行を完全にオフラインへ強制します。

## 11. Cacheawl

cacheawl は、マシン全体で共通のテキスト保管庫です：ずっと持っておきたくて、どのプロジェクトからも手を伸ばしたいものの場所。`~/enough/cacheawl/` にあり、どのプロジェクトのファイルツリーにも現れず、あなたのすべての enough で共有されます。（以前の enough を使っていたなら、古い `infoworld/` の書庫は 0.1.6 の初回起動で cacheawl に溶け込みました — `personal/`、`public/`、`wiki/` が、最初の 3 つのキャッシュボックスになったのです。失われたものはありません。）

### 11.1 キャッシュボックスと、その merirmaid の図

**キャッシュボックス**は保管庫の最上位フォルダで、2 つの型があります。**素のボックス**は、あなたが自分で整理する、ずっと持っておきたいテキストのためのもの：参照メモの `personal` ボックス、発表した文章の `press` ボックス、あなたに合う構成なら何でも。**キャッシュ複製**は、あるソース — ローカルのフォルダ、web サイト、Wikipedia の記事群 — から*取り込まれた*ボックスで、どこから来たかを覚えています。

どのボックスも **merirmaid の図**を持っています：`_cachebox.merirmaid` は、ボックスの構造を映した生きた図で、中身が変わるたびに作り直されます。ダブルクリックすれば、ボックスのかたちがひと目で分かります。この図は*ミラー*で、設計として読み取り専用です。現実を映しているからで、図を変えたければボックスを変えてください。安上がりな突き合わせの処理が、enough の背中越しに Finder からファイルを落としたときでも、ミラーを正直に保ちます。

上部バーから **cacheawl モード**を開くと 2 ペイン表示になります。片側にプロジェクト、もう片側に保管庫。ドラッグでファイルをコピー、shift ドラッグで移動、shift クリックでコンテキストメニュー、そしてダブルクリックでどのファイルもその自然なモードで開きます — girraph、merirmaid、read/edit、wiki の読み手 — 保管庫からまっすぐに。

### 11.2 キャッシュボックスと、ローカルや web のドキュメントを捕まえること

cacheawl モードの**取り込みバー**（あるいは、ふつうに会話で頼むこと）が、外の材料をボックスへ捕まえます：

- **ローカルのパス** — メモやドキュメントのフォルダを、保管庫に複製します。
- **web サイト** — ドキュメントや参照のサイトを、選んだ深さまで（上限はおよそ 500 ページ）クロールして、ローカルの markdown として保ちます。web の取り込みは、あなたの取得の切り替えと許可リストに従います。Tor 経由も含めて。
- **Wikipedia** — ある話題の記事を（上限はおよそ 200 件）wikisink のアーカイブから引き出して、プロジェクトに縛られない永続的なテキストにします。

取り込みは裏側で走ります。ボックスはすぐに「取り込み中」の状態で現れて、様子を眺められますし、失敗した取り込みは、終わったふりをせずに失敗したと言います。エージェントのキャッシュボックスツール（一覧、作成、取り込み）はブローカーの cacheawl の切り替えで制御されます。あなた自身の cacheawl モードの利用は、決して制御されません。

なぜそうするのか。プロジェクトフォルダは作業場で、cacheawl は書庫だからです。あるフレームワークのドキュメントを一度取り込んでおけば、これから先のどのプロジェクトも、オフラインでそこに足場を置けます。長く効く参照メモをボックスに置いておけば、これから話すどのエージェントもそこに手が届きます。成果物を仕上げてボックスへ移せば、それを生んだプロジェクトより長生きします。

## 12. 複数のモードを重ねる

enough の全画面モード — read/edit、girraph、merirmaid、wikisink、cacheawl — は、互いを置き換えません。紙を重ねるように**積み重なり**ます。cacheawl を開き、ボックスの中から girraph を開き、その上にメモのファイルを開く：3 段の深さで、ひとつずつ閉じれば、その下のものが置いてきたままの姿で現れます。同じスクロール位置、同じ潜り方、同じ未保存の編集で。

上部バーは、開いているモード 1 つにつき四角い印を 1 つ出します。新しいものが左です。それぞれに、そのモードだけを閉じる小さな赤い × のリボンが付いていて、埋もれたものにも効きます。埋もれたモードの印をクリックすれば、ほかを乱さずにそれだけを最前面に上げられます。Esc はいつでも、いちばん上のモードを閉じます。最後のひとつが閉じれば、discussion 表示 — 空のスタック（セクション 4）— に戻っています。

知っておくと便利なことが 2 つ：

- ミニの read/edit パネルは、全画面モードの*上*に浮きます。だから、たとえば下で girraph モードの仕事をしながら、肘のあたりにドキュメントを置いておけます。
- スタックのどこかにすでにあるモードを開いても、複製はされません。前に開いたものへ狙いを付け直し、それを上げます。

## 13. モデルウィンドウ

上部バーのモデルバッジが、モデルウィンドウを開きます：いまどの頭があなたに答えているのか、ほかに何が使えるのか、そして — 望むなら — クラウドの枠。

### 13.1 ローカルモデル：概観と使い分けの勧め

対応するローカルモデルは 7 つ — そしてこのウィンドウは、いまやそれらをインストールする場所でもあります。まだ持っていない行には、ダウンロードのサイズと、*このマシン*のメモリと空き容量に照らして計算された実現可能性の判定が出ます：✓ は余裕、~ はぎりぎり、✗ は勧められません。ダウンロードは進捗バー付きで走り、終了しても生き延び（止まったところから再開します）、すでに受け取った分を失わずに中止できます。インストール済みのモデルはクリックで切り替わり、いま動いているもの以外は、ディスクを取り戻したくなったときにその行から削除できます。

| 愛称 | モデル | ディスク | 最小 RAM | 備考 |
|---|---|---|---|---|
| **G40-04** | Gemma 4 4B (E4B) | 約 5.4 GB | 8 GB | いちばん小さい。どこにでも入る。既定 |
| **Q35-09** | Qwen3.5-9B | 約 5.9 GB | 10 GB | 均衡のとれた中型。MTP による投機的デコード |
| **G40-12** | Gemma 4 12B (QAT) | 約 7.0 GB | 12 GB | 量子化を織り込んで学習済み。16 GB の甘い場所 |
| **G40-26** | Gemma 4 26B MoE (4B active) | 約 15.6 GB | 20 GB | 大型の質を、中型の速さで |
| **Q36-27** | Qwen3.6-27B dense | 約 17.1 GB | 22 GB | 場数を踏んだ重量級。MTP つき。息が長い |
| **Q38-04** | Qwen3.8 27B (4-bit) | 約 19 GB + draft 1.7 | 24 GB | 最新の Qwen。自分の投機を自分で下書きする |
| **Q38-16** | Qwen3.8 27B (16-bit) | 約 54 GB + draft 3.2 | 64 GB | 完全精度。いちばん大きな Mac のために |

名前のちょっとした落とし穴をひとつ、つまずかないように：Q38 の 2 つでは、ダッシュのあとの数字は**量子化のビット幅**であって、パラメータ数ではありません — Q38-04 と Q38-16 は、4 ビットと 16 ビットの精度で動く、*同じ* 270 億パラメータのモデルです。（G40-04 は、古い流儀の名前なので、本当に 40 億パラメータのモデルです。）ウィンドウのラベルがそこを書き下しているので、愛称のほうが説明する必要はありません。

目安。8〜16 GB のマシンなら G40-04 で暮らし、余裕ができたら G40-12 を次の一歩に — 量子化を織り込んだ学習のおかげで、そのサイズにしては珍しくきれいな出力をします。32 GB なら G40-12 か Q35-09 が心地よい常用機で、難しい統合の仕事には G40-26 か Q38-04 を。64 GB 以上なら Q38-04 か Q36-27 を既定にして、もう考えないでください。Q38-16 はそれ自体がひとつの分類です：本気の統合メモリと約 57 GB の空き容量を持つマシンのための、完全精度の重量級 — Mac Studio があって天井が見たいなら、これが天井です。コンテキストウィンドウは RAM に合わせて自動で伸び縮みし（モデルごとに RAM 階層別の妥当な既定が付いていて、設定で上書きできます）、Qwen のビルドは追加の速さを無料でくれる Multi-Token Prediction を積んでいます：Q35/Q36 はモデルファイルに内蔵、Q38 の 2 つは小さな相棒の「draft」ファイル経由で、これは一緒に自動でダウンロードされます。

ターミナルからインストールした人へ、もうひとつ。モデルはどの llama.cpp でも*ダウンロード*できますが、*動かせる*のは十分に新しいビルドだけです。お使いのものが新しいモデルに対して古すぎるときは、ウィンドウがそう言い、直し方（`brew upgrade llama.cpp`）を教えます。アプリでインストールした人が、この注意書きを見ることはありません — アプリは自前の推論エンジンを積んでいます。

モデルを切り替えると、ローカルの推論サーバーが再起動し、メモリ上の会話が消えます。ファイルもログもリクエストの状態も残ります。切り替えで失うのはチャットのスクロールバックであって、仕事ではありません。

### 13.2 OpenRouter への対応（OPRO-API の枠）

enough はローカル優先であって、ローカル専用ではありません。5 つめのモデル枠、**OPRO-API** は、OpenRouter を通してクラウドのモデルへつながります。既定はオフ、有効にするにはあえて手間がかかるようにしてあり、取引の中身については正直です：あなたのプロンプトと出力はマシンを出ます。その代わりに、最前線のモデルの力と、ときには、同じ力のローカルモデルが要求するハードウェアと電気より安い費用が手に入ります。

有効にするには：ブローカーで **local models only** をオフにし、モデルウィンドウで OPRO-API をクリックします。3 画面のウィザードが案内します — 明示的な確認のチェックボックスが 3 つ（アカウントを持っていること、課金を理解していること、プライバシー上の取引を理解していること）、それから API キー、そして生きた疎通確認。キーは macOS のキーチェーンに保管されます。どのファイルにも書かれることはなく、エージェントには読む手立てがなく、ブローカーはそれを取りに行こうとするように見えるだけのシェルコマンドさえ断ります。確認が済めば、OPRO-API はほかのモデルと同じように選べるようになり、その設定パネルから再テスト、キーの更新、キーの削除、そして好きな OpenRouter のモデル id を選べます。

クラウドの利用に説明責任を持たせているものが 2 つ：

- **すべてがローカルにキャッシュされます。** クラウドとのやりとりはすべて、トークン数と索引つきで `rness/io/cloud-cache/` に書かれます — あなたのローカルのエージェントが、あとから読めるローカルの紙の跡です。
- **`cloud_pipeline`** は、大きな仕事をクラウド枠へまとめて流させます — 最大 200 段階、段階ごとのキャッシュ、任意で段階ごとの要約、そして最後の取りまとめ — 結果は会話にあふれさせるかわりに、ディスクへ書かれます。「12 章分の要約をぜんぶ下書きするクラウドパイプラインを」と頼めば、重い持ち上げは会話の外で、すべて記録されながら行われます。

## 14. パラダイム

パラダイムはエージェントの思考の枠組み — 仕事がどう進むかについての、交戦規定です。有効なのは常にちょうど 1 つ（サイドバーの上部に出ます。● をクリックで切り替え）で、有効なパラダイムの全文が毎ターン、システムプロンプトに乗ります。エージェントは他のパラダイムの 1 行の目録も見ているので、あなたの依頼がよそでもっとうまく扱えそうなときは、切り替えを提案 — あるいは実行 — できます。エージェントからの切り替えは、何も奇をてらったものではありません：そのパラダイムの名前を `rness/active-paradigm` に書き、そうしたとあなたに伝えるだけです。

### 14.1 default

自由なかたちの、エージェント 1 体との会話。たいていの仕事のためのパラダイムであり、別のパラダイムのほうが合う瞬間を見張っている案内役でもあります。いつも守る作法もここが抱えています — たとえば「黄色のところ」があなたのハイライトを指すと知っていること。

### 14.2 text-planning

文章の前にある、長い助走路のために：小説、エッセイ集、ノンフィクションの本、あるいは宣言を、「何か書きたい気がする」から使える計画にまで持っていきます。エージェントはプロジェクトのルートに、あなたと一緒に計画のドキュメントを 1 つ作ります — 辛抱強く、繰り返し、必要なだけのセッションをかけて — そして頼まれれば、セクションごとの*足場*を作ります：構造の手引き（拍、見出し、声の覚え書き、語数の目安）で、それをあなた自身が文章にふくらませます。このパラダイムを定めている決まりは：**あなたの文章は決して書かない。** 足場に入るのは構造だけです。あなたの声はあなたの声のまま。（`analyzer` または `memoir-dialectic` スキルと一緒に働きます。回想録は memoir-dialectic に渡されます。あちらがそのために作られたものだからです。）

### 14.3 translation

オフラインの翻訳を、一等市民の能力として宣言します。`translator` スキル（セクション 16.5）と組みます：依頼が人間の言語のあいだで文章を動かすものだと、エージェントはここへ切り替え、スキルがオフなら、何を逃しているかを教えます — そしてあなたがオンにするまで言い続けます。スキルをオンにすれば、アカウントも、レート制限も、ネットワークへの依存もない、約 419 言語のローカル翻訳者が手に入ります。

### 14.4 workflow-design

enough そのものについてのパラダイムで、仕事の中で働くのではなく、仕事のやり方を作ったり変えたりしているときに有効になります：新しいスキル、新しいロール、新しいパラダイム、AGENT.md や MOTIVATION.md への編集。ここでのエージェントは、設計における思慮深い共同作業者としてふるまいます — 作る前に確かめる問い（範囲は？　名前は？　どんなときに動く？）、最初の思いつきがもっと鋭くなりそうなときの代案、そして作るたびに追いかけるリクエストファイル。仕事のやり方の変更は、それを生んだ会話より長く生きるからです。セクション 3 を本当のものにしているのが、このパラダイムです。

## 15. ロール

ロールは、会話に呼び出せるもうひとつの人格です：自分の `AGENT.md` と `MOTIVATION.md` を持ち — 主エージェントを定めているのと同じ 2 ファイルの型で — 補い合う、あるいは意図して噛み合わない性格に絞られています。ロールはサイドバーからプロジェクトごとにオン／オフします。有効なロールはシステムプロンプトに乗り、名前で呼びかけます（「この計画について open-skeptic なら何と言う？」）。

### 15.1 block-breaker

書けなくなることの専門家で、実在の書き手が「どうやって行き詰まりを溶かすか」に答えたものから蒸留されました。処方の前に診断します — アイデアが尽きた、度胸が尽きた、構造が尽きた、許しが尽きた、はそれぞれ別の問題です — そのうえで制約、反復による発想（「10 通り出してから削る」）、奇妙な捉え直し、そして望まれれば実際の次の一文へ手を伸ばします。徹底して敗北主義に与しません。その核にある信念：自ら望んで書いている人にとって、行き詰まりはいつでも解けます。規則は誰かがこしらえたものであり、治し方もこしらえられるからです。

### 15.2 open-skeptic

「啓発可能な悲観論者」です：AI が強いところには心から熱を上げ、売り込みが過ぎるところには職業的に疑いをかけます。これから仕事のやり方を作ろうというときに呼び出して、失敗の筋道を早いうちに名指ししてもらってください。人間の経験を AI に再現させることに、人の目を通さない誤差の連鎖に、そして流暢な自信が専門性の仕事を代行することに、押し返します — その一方で、集める機械として、知識の義肢として、稽古の相手としての AI には声援を送ります。証拠があれば意見を更新します：うまくいっている仕事のやり方を見せれば、そう言います。あっさりと。

### 15.3 自分のロールを立てる

例は 2 つ、型はひとつ — 指示と動機を、markdown ファイル 2 枚で。ロールは、いま欠けている声を足すいちばん安上がりな方法です：ソクラテス式のラバーダック、コンプライアンスの査読者、想定読者を演じる読み手、自分の知識ファイルから育てた分野の専門家。workflow-design パラダイムでひとつ頼めば、エージェントがあなたに聞き取りをして、両方のファイルを書き上げます。

## 16. スキル

スキルは、焦点の定まった能力の包みです：`SKILL.md`（と、任意の参照ドキュメントやスクリプト）の入ったフォルダが、手順や語彙や規律をエージェントに教えます。スキルはサイドバーからプロジェクトごとにオン／オフします。オフは本当にオフ — プロンプトにまったく入りません — そして新しいスキルはオフの状態で来るので、知らないうちに何かが変わることはありません。enough が同梱していないスキルは、そもそも有効にできるようになる前に読まれます（セクション 16.6）。全部オフにするのも、れっきとしたやり方です：素の会話、足場なし。モデルがあなたを驚かせるための余白は、そのほうが広いこともあります。

### 16.1 analyzer

ひとつのスキルに、分析のモードが 4 つ。

**Summarize** は、どんな文章についても 1 ページの、公平な要約を作ります：何を言っているか、誰に向けたものか、書き手の動機と偏り、調子、鍵になる引用。

**Proofread** は軽い校正をします — 誤字、綴り — 文書全体から本 1 冊まで。ローカルの規則ベースの文法チェッカー Harper が動かしています。提案と、繰り返し使われている言い回しの指摘をまとめた校正レポートも別に作るので、黙って直したものと、判断が要るものとが区別されたままになります。

**Decide** は、あなたの板挟みを、組み込みの 10 人の名簿から選ばれた 3 つの原型的な人格に手渡し、記録に残しながら議論させます。手に入るのは推奨*と*その議事録なので、判定を信じるかわりに、理由のほうを量れます。

**Audit** は、まだ信じると決めていないもの — 誰かが送ってきたスキル、ロール、パラダイム — を読み、それが何であるかを教えます。まず、そのものが実際に何をして、なぜ欲しくなるかの平たい説明。それから安全の確認：プロンプトインジェクションの試み、エージェントの手の届く範囲をこっそり広げる指示、認識論的な赤信号、そして同梱されたコードがあれば、モデルをまったく通さない決定論的な走査も。判定は 3 語のどれか — **pass**、**flag**、**fail** — で、点数ではなく、名指しされた所見に裏打ちされます。読むだけです：audit が、読んでいるものを実行したり、編集したり、インストールしたり、有効にしたりすることはありません。

レポートは `rness/io/output/analyzer/audits/<skill-name>/` に降ります：ほかのファイルと同じように読める日付入りの `.md` と、その隣の小さな `verdict.json`。監査は名指しでいつでも頼めますし（「有効にする前に見ておいて」「このスキルは実際のところ何をするの」）、enough は同梱していないスキルを初めてオンにしたとき、頼まれなくてもこのモードを走らせます。どちらの扉からでも、同じレポートが同じフォルダに書かれます。その話はセクション 16.6 に。

### 16.2 anything-finder

最初のページには出てこないものたちのための、捜索隊です。3 つの顔、1 つのスキル。

**find** が既定で、見つけにくいもの 10 種類それぞれの手引きと、行き詰まった探索のための 11 番目を抱えています。**テキスト** — パブリックドメインの本、詩、歴史的文書。**映像** — 稀少な、失われた、絶版の映画とテレビ。視聴先のリンクと、その合法性の明示つき。表紙や zine に使える、権利の片づいた**画像**。**製品** — 知られていない機材、シンセ、楽器と、実際に買える場所。**論文** — 有料の壁の向こうにある論文を、正規の公開版として見つけます：プレプリント、リポジトリ、アーカイブ。**コード** — 寛容なライセンスのリポジトリ。GitHub に一度も触れていないライブラリも含めて。**書籍** — すでに好きだったものからの、似た読み心地の本。**音** — 楽譜、MIDI、サンプル、機材のマニュアル。**素材** — フォント、テクスチャ、3D モデル、ストック映像。**データ** — データセット、公開 API、政府文書、新聞のアーカイブ。

結果は*find カード*として返ります：リンク、なぜそれが正しい品なのか、そして著作権に敏感なものについては、なぜ使ってよいのか — 公開年か、明示的なライセンスを書き下して。「*The Moonstone* のパブリックドメイン版で、組版に耐えるくらいきれいなものを」「1974 年版はどこで合法的に観られる？」「これをやる MIT ライセンスのライブラリはある？」と聞いてください。正直な答えも取引の一部です：「これは存在しますが、合法的には手に入りません」「候補は 3 つ、2 番目に 70% 賭けます」も、ここでは本物の結果です。そして唯一の経路が海賊版のサイトだけなら、そう言ったうえで、図書館か、貸し出しの仕組みか、販売店を渡してきます。

**patents** は先行技術の顔です。発明をひとつ渡せば、成立特許、公開出願、そして特許以外の文献にわたる構造化された新規性調査を走らせ、何を見つけたか、それが新規性と非自明性にとって何を意味するかを報告します — 法的助言ではない、という断りがどのレポートにも残ります。実際そうだからです。「これはもう特許になっている？」「磁石式の自転車ロックで、こういうものの先行技術は」「私のアイデアは特許になる？」。届かなかったデータベースは*未確認*と明記されて返り、黙って*該当なし*にされることはありません。

**venture** は「これは商売になるか？」の顔で、ほかの 2 つを組み合わせます。すでに存在するものの市場の一掃、先行技術の確認、そして企業、オープンソースの代替、隣接製品、そして挑んで畳んだものたちの墓場にわたる競合の見取り図。手に入るのは公平な読みです — どこが混み合い、どこが隣接し、どこが本当に空いていて、証拠が実際に支える楔はどこか — に続けて、いちばん強い*賛成*の論と、いちばん強い*反対*の論。すべての論点にリンクの錨が打たれ、最後に、あなたにしか答えに行けない短い問いの一覧が付きます。「これを作るべき？」「これは製品として存在する？」「ここの市場の隙間はどこ？」と聞いてください。あなたのアイデアに点数は付けませんし、事業計画も書きませんし、資金を集めろとも言いません。そして、空いている領域を、青信号ではなく問いとして扱います。

出力は `rness/io/output/anything-finder/` へ行きます。取ってくるものはすべて、ほかのウェブアクセスと同じくブローカーを通るので、許可リスト外のドメインは Tor 経由になります — そして、あるソースが答えるのを拒んだときは、レポートがそのホストを名指しし、`allowlists.md` に何を足せばよいかを教えます。結果に黙って穴を残すかわりに。

### 16.3 girraph-merirmaid

enough の 2 つの図の原型（セクション 17 と 18）のための、規律のスキルです。girraph 側は、まっとうな IBIS の描き方を教えます：1 ターンに 1 つの問い、解決へ飛びつかない、止めどきはあなたの確認。merirmaid 側は Mermaid を書くときの決まりを抱えています。たとえば、あとで気持ちよく編集できるくらいノードのラベルを短く保つこと。モードはこのスキルなしでも働きます。あれば、エージェントは本当に規律のある地図描きの相棒になります。

### 16.4 memoir-dialectic

辛抱強い、複数セッションにわたる回想録の相棒です。あなたに聞き取りをして — 一度に 1 つか 2 つの問いで、決してどっと浴びせず — 何もかもを綴じていきます：会話の順に番号を振った計画のドキュメント、素早く再開するための索引、雑多な吐き出しのためのメモファイル、そしていずれは構成の統合と、あなたが望んだときにだけ、下書き。フォルダが記憶です。何週間でも何年でも姿を消して構いません。置いてきたところから続きます。人生まるごとから、たったひとつの節目まで、全域のために作られていて、繊細な話題や踏み込まない領域の扱いも明示され、あなた自身の言い回しを丁寧に保ちます — 声は大事です。下書きが来るなら、なおのこと。

### 16.5 translator

MADLAD-400 による、約 419 言語のオフライン翻訳です — 一度きりの約 3 GB のダウンロードで、CPU でも Apple Silicon でも動き、外へ電話をかけません。短い一節から文書まるごとまで、主要言語から低資源言語や先住民の言語まで。手紙を訳す、README をローカライズする、ある一節の意味を確かめる、意味が保たれるかの試験として第三の言語を経由して往復させる — すべて、ネットワークを抜いたままで。一部の低資源言語には、より高い品質を出す NLLB-200 エンジンを任意で選べます。こちらは非商用のライセンスなので、translation パラダイムからの明示的な選択制になっています。

### 16.6 自分のものを書くこと、他人のものを信じること

上の 5 つは実演です。スキルの*仕組み* — markdown の指示、オンにしたときに読み込まれること、いつ働くかをエージェントに伝える `description:` — こそが、本当の機能です。文体の指針、分野ごとの確認事項、繰り返し使うレポートの書式、データの扱いの手順：ある能力を文章で説明できるなら、それをスキルとしてエージェントに手渡せます。workflow-design（セクション 14.4）で自分のものを作るか、5 つのどれかを分岐させて自分のものにしてください。

その輪のもう一方の端が、よそから届くスキルです。スキルとは、あなたのエージェントが従う指示です。つまり、インターネットから来たスキルは、インターネットから来たほかのどんなファイルとも、まったく同じだけの疑いに値します。そこで enough は、あなたのかわりにそれを読みます：

- **enough が同梱するものは信頼済みで、これまでどおりに見えます。** 上の 5 つは、インストール先の defaults へのリンクとして届きます。押せばすぐ切り替わります。監査は走りません。
- **それ以外はすべて、読まれるまでオフです。** スキルのフォルダを `rness/skills/` に置くと — ダウンロードしたもの、友人が送ってくれたもの、`.skill` から展開したもの — 無効のまま、サイドバーに*未検証*と印を付けて座っています。初めてオンにしたとき、enough は一言もエージェントに届く前に、analyzer の監査モード（セクション 16.1）をそれにかけます。行の中でそれが進むのが見えます：*未検証* → *監査中…* → *監査済み*。
- **要注意は、有効ではないということです。** 監査が何かを見つけると、行は*要注意*（あるいは*不合格*）と言い、スキルはオフのまま、ボタンが 2 つ出ます：**レポートを読む**は全文を読む表示で開き、**それでも有効にする**は確認を求めたうえで、その判断をあなたのものとして記録します — 所見は消されるのではなく、覆されるのであり、行はそれ以降*あなたが信頼済み*と読めます。監査は助言し、あなたが決めます。（ファイルの中で作業したいなら、そのスキルの `verdict.json` を `"verdict": "pass"` に編集しても同じことです。）
- **スキルを編集すれば、読み直されます。** 監査は、それが読んだまさにそのバイト列 — ファイル名も中身も — に結び付いています。何かを変えれば、次にそのスキルをオンにしたとき、また監査されます。前に「それでも有効にする」を選んだものも含めてです：上書きの判断は、ある一組のファイルの、ある一瞬についての記述であって、編集を生き延びはしません。
- **あなたのエージェントがあなたのために書いたスキルも、未信頼です。** それは見落としではなく、意図です。workflow-design が新しい `SKILL.md` を `rness/skills/` に書いたとき、エージェントは初回の有効化で自分の宿題を監査します。見つかるものが何もなければ、ほぼ一瞬で終わります。
- **モデルが動いていないと、監査は終われません** — そのときは、スキルを素通りさせるかわりに「監査の llm の側が走れませんでした」と印を付けます。モデルをオンにしてもう一度切り替えるか、中身がもう分かっているなら*それでも有効にする*を使ってください。

レポートは `rness/io/output/analyzer/audits/<skill-name>/` に暮らします — 会話で監査を頼んだときに analyzer が書くのと同じフォルダです。扉は 2 つ、書類は 1 つ。そしてそれは、開いて、取っておいて、消すこともできる、ふつうの markdown ファイルです。

## 17. girraph モードと `.girraph` 拡張子

読み方は「グラフ」。*ir* は黙字で、*iterative*（反復的）と *recursive*（再帰的）を表しています。動物のほうは 🦒 で、こちらも黙っています。

girraph は、難しい問いの地図です。やることの一覧ではありません：*意見の食い違い*の絵であり、自分自身との実りある食い違いも含みます。ある種の問題（「ホームスクールにすべき？」「この本は結局のところ何についての本？」「その資金を受けるか？」）は、どの答えからも異議が芽を出し、どの異議の下にも新しい問いが生えます。一覧はその争いを埋めてしまいます。girraph はそれを見えるところに置きます：

- ❓ **issue（論点）** — 開かれた問い。いつでも問いのかたちで書きます
- 💡 **position（立場）** — ありうる答え
- ➕ ➖ **argument（論拠）** — ある立場への賛成と反対の理由
- 📄 **note（メモ）** — 背景、制約、ドキュメントへの参照
- 🦒 **入れ子の girraph** — それ自体の地図に値するくらい大きな下位の問い

血筋は IBIS、「厄介な問題」のための 1970 年代の手法です — きれいな答えも、自然な止まりどころも無い類いの問題のための。girraph は、それに対する enough の平文での応答です。

形式は `.girraph` で終わるテキストファイルで、1 行に 1 つの考え。2026 年でも 2056 年でも、どのエディタでも読めます：

```
%girraph 0.1
title: Should enough ship a plugin API?

q1 ? Should enough ship a plugin API?
p1 ! Ship a minimal one < q1
a1 + Ecosystem growth needs stable hooks < p1 by:graham
a2 - API surface = forever maintenance < p1 by:open-skeptic
```

`< q1` は「これは q1 に答えている」という意味で、`by:` は誰の主張かを覚えています。データベースも、隠れているものもありません。ファイルが地図です。

アプリで `.girraph` をクリックすると girraph モードが開きます：折りたためるツリーを、その場で編集できます。ラベルをクリックすれば書き換えられます。行にカーソルを置けば、追加・リンク・削除のボタンが出ます。🦒 のチップをクリックすれば入れ子の地図へ降り — パンくずが連れ戻してくれます — 📄 のチップをクリックすれば、参照されたドキュメントをその場で読めます。チャットでは「girraph にして」「地図にして」と言えば、エージェントがあなたと同じノード単位の操作で同じファイルを編集するので、2 人で同時に地図をいじれます。ノードの削除にはいつでもあなたの確認が要りますし、子が黙って親を失うことはありません。

girraph は **merirmaid のミラー**を生やすこともできます：girraph のツールバーの merirmaid ボタンをひとクリックすれば、地図とリンクした、自動で作り直される Mermaid の図ができます — 論点は六角形、立場はスタジアム、支持と異議はそれぞれの色の線で — girraph が変わるたび、自分を最新に保ちます。girraph で地図を描き、merirmaid で眺める。

girraph を効かせる習慣が 3 つ。論点は問いのかたちで書くこと（「2 年目の資金をどう作るか？」であって、「お金の問題」ではなく）。論拠は論点ではなく立場に付けること — 理由とは、ある*答え*への賛成か反対の理由です。そして枝が広がりきる前に、自分のファイルへ分けること。girraph-merirmaid スキルを有効にすれば、エージェントがこの 3 つをあなたに守らせます。

## 18. merirmaid モードと `.merirmaid` 拡張子

girraph が議論を地図にするのに対し、**merirmaid** は構造を描きます。`.merirmaid` ファイルは [Mermaid](https://mermaid.js.org/) の図 — フローチャート、シーケンス図、状態機械、ER 図、Mermaid が描くものなら何でも — に小さなフロントマターのヘッダーを付けたもので、ブラウザで即座に描かれます。もちろんローカルで。enough のすべてと同じく、CDN はありません。

ヘッダーで宣言する、2 つのありよう：

- **wip** — 作業中のホワイトボード。どのノードの文字もクリックすれば、その場でラベルを編集でき、文字数が生で出ます。構造の変更（箱を足す、矢印をつなぎ替える）は、チャットピルを通してエージェントに頼みます。あなたのパイプライン、筋書き、組織の図を頼めば、エージェントがソースを書き、ブラウザが描き、あなたが言葉を整えます。
- **mirror** — よそに暮らす構造を映した、読み取り専用の反映です：キャッシュボックスの中身（セクション 11.1）か、girraph（セクション 17）。ミラーは、映しているものが変わると作り直されます。絵を変えたければ、そのものを変えてください。

図はリンクします。ノードは別の `.merirmaid` や `.girraph` や markdown ドキュメントを指すことができ、クリックすればそこへ移動し、パンくずが帰り道に印を付けます — こうして図の集まりは、あなたのプロジェクトのたどれる地図帳になります。そして図に構文の誤りがあるとき、merirmaid モードは白紙ではなく、エラーと生のソースを見せます。直すよりどころは、いつでもあります。

girraph-merirmaid スキル（セクション 16.3）が、どちらのファイル形式についても書き方の規律を抱えています。そこにある目安をひとつ、ここで繰り返す値打ちがあります：正直な最初の一手が問いを立てることなら、欲しいのは girraph です。箱と矢印を描くことなら、欲しいのは merirmaid です。

## 19. ここからどこへ

enough をいちばん速くあなたのものにする道：

1. 本物のプロジェクトで立ち上げてください — 実際に大事だと思っているもので。
2. 1 セッション、話すことに使って、プロジェクトプロファイルが溜まり始めるに任せてください。
3. `MOTIVATION.md` を編集して、このプロジェクトが実際のところ何のためのものかを書いてください。
4. 同じ指示を 2 度目に言いそうになったら、止まってください。かわりに `AGENT.md` に書きましょう。
5. あなたの仕事のかたちに既定が合わないと初めて感じたら、「これのためのパラダイムを設計しよう」と言ってください — スキルでも、ロールでも — workflow-design が手を引いてくれます。

その輪 — 引っかかりに気づき、直し方を書き留め、仕事を続ける — が、この遊びのすべてです。組み込みのものは、あなたを出発させます。あなたが最後に手にしているシステムは、誰も出荷していません。あなたが書いたものです。
