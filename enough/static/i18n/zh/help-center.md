# enough 帮助中心

> 你能用 enough 做的一切，都在这里。本文对应 enough **0.3.0**，包括主页（你启动过的每一个项目，列在一起，有进去的路，也有回来的路——第 2 节）、转换那一轮（PDF、Word 文档、电子书、幻灯片和工作簿都以可编辑的 markdown 孪生本打开，带导出、同步和图片查看器——第 6 节）、技能那一轮（analyzer 新增的审查模式、`anything-finder` 技能，以及在放行之前先读一遍任何非 enough 自带技能的首次审查）、2026 年 8 月那一轮（七个本地模型，安装前先做可行性检查，以及 **enough.app**——已签名、已公证的桌面应用）、2026 年 7 月的界面那一轮（模式栈、按文件夹开关的帮助气泡、girraph→merirmaid 镜像），还有 0.3.0 的偏好那一轮（按项目的界面与文字缩放，以及六种语言的界面和帮助——第 9 节）。如果本文和你眼前的应用说的不一样，以应用为准，那是本文的 bug——欢迎到 [enough.support](https://enough.support) 指出来。

enough 是一套跑在你自己机器上的个人语言系统。你把它指向一个文件夹，和它说话，它帮你计划、写作、审阅、研究和翻译。模型默认是本地的。你的文件仍然是你的。而且你看到它做的几乎每一件事，都定义在朴素的 markdown 文件里，你随时可以打开、阅读、修改。

读的时候请记着一件事：**本手册里那些内置功能，只是 enough 能做的事情里的一小部分。** 盒子里的范式、角色和技能是一套入门工具——它们是三种自定义机制的可用范例，而不是这些机制的边界。终局是你自己写，或者让智能体和你一起写：一个照你构思文章的方式来的范式，一个像你最挑剔的读者那样争辩的角色，一个把你行文习惯固定下来的技能。第 3 节讲怎么做。它是本文最重要的一节，而这份手册会一次次把你送回那里。

## 1. 安装、快捷方式，以及这份文档

### 1.1 你需要什么

- 一台 Apple Silicon 的 Mac。（enough 在 macOS 上构建和测试。Linux 支持在计划中；Windows 是可行的。）
- 至少放得下一个模型的磁盘空间——最小的大约 5 GB。
- 不用账号，不用 API 密钥，不用订阅。除非你之后主动启用云模型槽（第 13.2 节），否则一切都在本地跑。

### 1.2 安装

两扇门，同一间屋子。

**应用——短的那条路。** 从发布页下载 `enough` 的 DMG，打开它，把 **enough** 拖进「应用程序」，然后启动。macOS 会提醒你这是从互联网下载的应用——它已签名并经过公证，所以这只是那个友好的蓝色对话框加一个 **打开** 按钮，一次而已，不是要你硬闯的警告。接下来交给首次运行向导：它会搭起自己的 Python 环境，列出模型清单并对*这台*机器给出诚实的判断（第 13.1 节），告诉你哪些可选扩展你已经有了，然后把你交到主页，让你挑一个想干活的文件夹（第 2 节）。等待的时间大多花在下载模型上。不用 Terminal，不用 Homebrew，不用 git。

这个应用自带推理引擎和 Python。那些可选的扩展——语音输入、网页抓取、语法检查、翻译——仍然是独立的程序；向导的「扩展」页会一一列出它们的名字、缺了它会关掉什么、以及怎么装。没有一样是必需的，也没有一样会偷偷装上。有一个扩展根本不是独立程序：**PDF 阅读**随时可以在 enough 内部安装（第 6.8 节）。

**终端——长的那条路，杠杆更多。** 克隆仓库，然后双击克隆目录里的 `install-enough.command`：

```bash
git clone https://github.com/0gsd/enough.git ~/Downloads/enough-seed
open ~/Downloads/enough-seed
```

你第一次双击它时，macOS 的 Gatekeeper 可能会因为「未识别的开发者」而犹豫——那份谨慎针对的是 `.command` 文件，它没有像应用那样签名。右键点这个文件，选一次 **打开**，macOS 从此就记住这份信任了。

启动器会运行 `bootstrap.sh`，一个十步的交互式安装程序，每一步都先问过你、并说明它接下来要做什么。任何时候按 Ctrl-C 都是安全的。重跑也安全——它会先检查状态，从你上次停下的地方接着走。这些步骤大致是：

1. 检查你的平台。
2. 检查 Homebrew，缺了就帮你装上。
3. 装上 enough 倚重的那些辅助程序：`llama.cpp`（本地模型推理）、`whisper-cpp`（语音输入）、`tor`（匿名网页抓取）和 `harper`（本地语法检查，analyzer 技能会用）。文档转换器——pandoc，用来把抓到的网页和 Word 文件变成 markdown，以及 typst，用来写 PDF——已经不在这份清单上了：它们随 enough 自己的 Python 环境一起装，在第 5 步，所有平台都一样。如果你碰巧有自己用 Homebrew 装的 pandoc，enough 会改用你那个。
4. 建立 `~/enough/`，也就是全局安装目录。
5. 准备 Python 环境（通过 `uv`）。
6. 下载模型权重。每一个受支持的模型都会一个一个地问你要不要，附上它的体积，以及针对你机器内存和空闲磁盘的可行性判断——✓ 表示宽裕，~ 表示紧张，✗ 表示还是算了。想要几个就要几个；第 13.1 节把它们都讲了一遍，跳过的那些以后一键就能装。
7. 放好语音输入（whisper）的模型。
8. 放好离线翻译模型，`translator` 技能会用它。
9. 把 `enough` 命令放到你的 PATH 上。
10. 完成，并打印一份接下来该做什么的清单。

以后要更新：从 `~/enough/` 运行 `update-enough.command`，或者在对话框里输入 `/update-enough`。有新的默认内容发布时，enough 会在界面里提一句，并把你指向那个命令，所以你不用自己去盯。`update-weights.command` 单独刷新模型权重。

### 1.3 启动

**从应用启动：** 双击，你就落在**主页**上——你变成过 enough 项目的每一个文件夹，列在一起，还有再添一个的入口。挑一个，它就打开。那是第 2 节的内容，值得先读它再读这一节。

**enough** 菜单里只有一个设置：**Reopen Last Project on Launch**（启动时重开上一个项目），默认关着。打开它，应用就会跳过主页，直接把你送回原处。一个窗口，一次一个项目——而 **File → Close Project**（⌘W）随时把你放回主页，不必退出（第 2.5 节）。

那里仍然有一个朴素的文件夹选择器，但你多半永远碰不到它：它是主页本身起不来时的后备——更新做了一半、安装坏掉——好让糟糕的一天也还留着一条回到工作里的路。

**从终端启动：** enough 按项目文件夹运行。在任意文件夹里打开终端，运行：

```bash
enough
```

然后访问 `http://127.0.0.1:3456`（enough 会替你打开）。不同的文件夹，不同的项目，不同的智能体记忆。唯一不能启动的文件夹是 `~/enough/` 本身——CLI 会拒绝，因为那是安装目录，不是项目。

主页也一样，随处可得：

```bash
enough --home
```

同一个界面，同一份列表，只是在浏览器里而不是应用窗口里。从它打开一个项目，你启动它的那个终端就成了那个项目的终端。

如果你压根不想敲命令，`~/enough/shortcuts/` 里放着两个启动器：

- **`enough-on.command`** —— 把它复制进项目文件夹（`cp ~/enough/shortcuts/enough-on.command ~/some-project/`），然后在 Finder 里双击。一个 Terminal 窗口会在那个文件夹里打开并跑起 enough；⌘W 或 Ctrl-C 停下它。
- **`setup-quick-action.sh`** —— 运行一次（`bash ~/enough/shortcuts/setup-quick-action.sh`），你就得到一个 Finder 快捷操作：右键任意文件夹 → 快捷操作 → **Launch in enough**。如果菜单项没出现，去「系统设置 → 键盘 → 键盘快捷键 → 服务 → 文件和文件夹」里把它打开。

### 1.4 这份文档，以及其余的文档

这个文件是长篇手册。你还有：

- **在界面里的帮助** —— 散布在界面各处的 `(?)` 气泡，每一个都解释它挂着的那样东西：一段 *what*、一段 *how*，还有一列 *ideas*。见第 9.6 节。
- **速查表** —— 键盘快捷键和 markdown 语法，在 UI 窗口里一点就到。见第 9.5 节。
- **[enough.support](https://enough.support)** —— 社区论坛：安装求助、工作流互相展示，还有一群乐意帮你搭起本手册一直在推着你做的那些自定义的人。

而这一切——这份手册、那些气泡、它们周围的界面——都能用六种语言阅读：英语、法语、西班牙语、德语、中文和日语。第 9.4 节有那个下拉框和它的小字说明。

## 2. 主页

在你进入项目之前，你在**主页**上：一整幅画面，列出你曾经变成过 enough 项目的每一个文件夹，外加一块用来再添一个的卡片。它是整个应用里最安静的一屏，这是有意的。没有对话，没有侧栏，没有模型，没有智能体——什么都还没跑起来，也没有什么正在被琢磨。只有你的项目，以及顶栏里那个管主题和这份手册的 ⚙ UI 按钮。

你会见到它：

- 第一次启动、首次运行向导走完的时候；
- 之后每一次启动，除非 **Reopen Last Project on Launch** 开着（第 1.3 节）；
- 每当你关闭一个项目的时候（第 2.5 节）；
- 从终端，任何时候，用 `enough --home`。

唯一*见不到*它的办法就是那个开关。把 **Reopen Last Project on Launch** 打开，enough 就直接回到你上次待的项目，主页不再插进来。把它关掉，每一次启动都从主页开始。这个设置就这么一个开关——没有别的可配的了。

### 2.1 网格、列表，还有 ¶ W C

两种视图，用画面右上角那一对按钮切换，enough 会记住你更喜欢哪一种。

**图标**是浏览的视图：一个文件夹图形、项目的名字，下面一行大白话——*3 天前编辑过*，超过一周就换成实际日期。

**列表**是比较的视图。六列：

| 列 | 它是什么 |
|---|---|
| 名称 | 项目的显示名（你在项目标题栏里设的那个，或者文件夹名） |
| ¶ | 段落数 |
| W | 词数 |
| C | 字符数 |
| 最近更新 | 这些计数所覆盖的文件里，最近的一次改动 |
| 创建于 | 这个文件夹成为 enough 项目的时间 |

中间那三列，和你打开文档时 enough 放在顶栏里的是同样三个读数——¶ 是段落（以空行分隔的块），W 是词，C 是字符（含空格和换行）——只不过在这里是整个项目加起来的。到底*哪些*文件会被算进去，值得用一句话说清，因为正是这句话让这些数字有意义：项目自己的文件树会显示给你的每一个 markdown 文件，**包括转换文档的孪生本**（你在这里改的 `.docx` 就是你的写作），而**不**包括 `rness/` 里的任何东西（智能体的脚手架不是你的书）。所以 W 那一列的数字，差不多就是你写了多少。

点任意列标题按它排序；再点一次同一个就反过来。什么都报不出的项目——从没打开过、从没统计过——不论正序倒序都沉到底部，而不是假装自己最古老。默认顺序是最近编辑的在前。

某个项目的文件夹此刻不在——外接硬盘没插、你在 Finder 里挪走了——它会显示成灰色，工具提示里是它记着的那个路径。它**不会**从列表里消失，而且保留着你最后一次看到时的计数。硬盘躺在抽屉里的项目，不是你弄丢了的项目。

### 2.2 点一个项目：那张地图

单击不会打开一个项目。它会给你画一张它的**地图**：一张只读的 merirmaid 图（第 18 节），画出这个文件夹里看得见的内容，顶上还有一个小小的信息节点，带着路径、文件数、¶ 和 W 的合计，以及项目的创建、上次打开和上次编辑时间。这和 cacheawl 给一个 cachebox 画的是同一种图（第 11.1 节），只是对准了项目。

这张地图是为这样的时刻准备的：你有四个名字都挺像的文件夹，你想知道哪一个里面装着那些章节。看一眼，再决定。

决定好了，工具栏上的 **open project** 按钮就打开它。Esc，或者右上角那条飘带，把你带回网格。而如果你本来就知道要哪一个，**双击**那块卡片或那一行，它就直接打开，不绕这一圈。

不管走哪条路，打开的样子都一样：加载动画出现一两秒，enough 关掉主页并在原地把项目启动起来，然后你就在讨论视图里了（第 4 节），和你直接启动到那个文件夹一模一样。

### 2.3 添加一个文件夹

网格里最后那块卡片——带加号的那块——就是文件夹变成项目的方式。

点它，macOS 会打开它自己的文件夹选择器。挑任何一个装着笔记、草稿或文档的文件夹；enough 会给它加上 `rness/`（第 7 节），把它登记到你的主页上，然后打开它。对话框开着的时候，那块卡片会写着*正在等文件夹选择器…*，所以你想翻多久都行。

有两类文件夹会被拒绝，而 enough 会告诉你是哪一类、为什么，而不是含糊地失败：

- **`~/enough` 本身，或它里面的任何东西。** 那是安装目录，不是项目。（`enough` 命令因为同样的理由拒绝同样的文件夹。）
- **云同步文件夹里的任何东西** —— Google Drive、Dropbox、iCloud Drive。这一条不是挑剔。项目的 `rness/` 是由指回全局默认的符号链接搭起来的，而同步客户端会把符号链接重写或弄坏，这是它们的日常；你会得到一个悄悄不再跟随全局设置的项目，而且偏偏是在你没留意的那台机器上。把项目放在本地磁盘上，同步做完的成果就好。

已经在你主页上的文件夹不算错误——enough 直接把它打开。

如果文件夹选择器根本调不出来（不是 Mac 的机器、拒绝这么做的沙箱），对话框会给出一个朴素的文本框让你把路径敲进去，上面写着原因。之后的一切完全一样。

### 2.4 隐藏一个项目

主页什么都列，一直列，一年的折腾之后就长了。所以：**option-点击任意卡片或行，就把它藏起来。**

隐藏只是 enough 自己列表里的一条记号，仅此而已。它问你的时候就这么说：磁盘上的文件夹没被碰，`rness/` 没被碰，里面一个字也没变。主页上没有「删除这个项目」，这是有意的——删掉一个项目意味着删掉一个装满你写作的文件夹，那是 Finder 的活儿，在那里你看得见自己在做什么。

视图按钮旁边的**隐藏**标签把它们请回来，标签上写着有几个。隐藏的项目显示成灰色，那一行上写着*已隐藏*；option-点击其中一个就取消隐藏（不用确认——它是即时的，也即时可逆）。在应用里，你也可以从 **View → Show Hidden Projects** 拨同一个开关。

### 2.5 关闭一个项目，以及回来

两扇门，同一个房间。

**在应用里：** **File → Close Project**，或者 **⌘W**。项目的后端会体面地关掉，一秒左右之后主页在它的位置上升起来。

**任何地方，应用或浏览器：** ⚙ UI 窗口顶部的 **close project → home** 按钮（第 9 节）。它会先问，因为关闭意味着这次会话结束了——你眼前的这段对话就到此为止，和退出应用是一样的——然后把你送到 ⌘W 会送到的同一个地方。

两者都不会碰你的文件夹。你的文件、你的 `rness/`、你的请求文件和会话日志，都还在你留下它们的地方；结束的只是那段正在运行的对话。

如果你用 enough 有一阵子了，新的 ⌘W 有一个后果值得知道：**⌘W 不再关闭窗口了。** enough 是单窗口应用，关掉那个窗口就等于退出，⌘Q 和红色按钮已经把这件事办了，⌘W 有更好的活儿可干。

还有它和「重开」设置之间的一处互动，否则它一定会让你吃惊一次：**关闭一个项目并不会让 enough 忘掉它。** 如果 **Reopen Last Project on Launch** 开着，你关掉一个项目、在主页上待了一会儿、然后退出——下次启动重开的是那个项目，不是主页。那个开关决定你从哪里开始；Close Project 这个按钮决定你此刻在哪里。如果你想从今往后都从主页开始，把开关关掉。

### 2.6 主页记得什么

三样小事，都是机器全局的——它们跟着你在项目之间来去、也跟着你回到主页，而且不存在任何项目文件夹里：

- **主题和字体**（第 9.1 节）。主页穿着你上次选的那一身，而且你*在主页上*换的主题，就是项目打开时的主题。这一条从前最招人烦：启动的那一屏和干活的那一屏，如今总是一致的。
- **图标还是列表**，来自第 2.1 节。
- **隐藏的项目是否显示着**，来自第 2.4 节。

关于一个项目的其他一切，都住在那个项目的文件夹里，你随时读得到。

## 3. 从内核层面自定义你的工作流

如果你只读一节，就读这一节。

大多数软件递给你功能。enough 递给你机制。智能体的性格、方法和本领，是在每一条消息上、从你磁盘上的 markdown 文件里现场组装出来的：

- **`AGENT.md`** —— 智能体是谁、怎么做事（第 4.1 节）
- **`MOTIVATION.md`** —— 为什么：价值、优先级，「完成」是什么感觉
- **策略** —— 关于它能读什么、写什么、抓什么的硬规矩（第 4.2 节）
- **生效的范式** —— 此刻管着推理的那个框架（第 14 节）
- **启用的技能** —— 它可以去够的能力（第 16 节）
- **启用的角色** —— 你可以召唤的其他人格（第 15 节）
- **项目档案** —— 它关于这个项目学到的东西（第 7.1 节）

改动其中任何一个，在应用里或任何文本编辑器里都行，下一条消息就生效。不用重新构建，不用重启，没有插件 API。只要你会写 markdown 文件，你就能给你的智能体重新编程。

### 3.1 全局 vs. 项目本地

所有可自定义的东西都遵循同一个模式：**默认住在 `~/enough/defaults/`，项目链接到它们，而任何项目都可以断开这条链接。**

改 `~/enough/defaults/` 里的一个文件，所有仍然链着它的项目都会拿到这个改动。在项目里打开一个链接过来的文件，点**自定义**——链接就变成一份项目本地的副本，从此这个项目走它自己的路，而其他项目继续跟着全局默认。文件树一眼就告诉你哪个是哪个：链接过来的文件显示成*斜体、暗一些*，本地副本正常显示。

丢进 `~/enough/defaults/` 的新技能、角色和范式，会在下次启动时出现在每个项目里。技能和角色到达时是关着的，所以不会有什么背着你变了；你按项目、在你想要的时候把它们打开。不是 enough 自带的技能——你下载的、朋友发的、你自己的智能体给你写的——在放行之前会先被读一遍。第 16.6 节讲这件事。

### 3.2 三种部件

| | 范式 | 技能 | 角色 |
|---|---|---|---|
| 它是什么 | 一个推理框架——智能体怎么对待工作 | 一项聚焦的能力——词汇、配方、流程 | 一个你可以召唤的第二人格——有它自己的 AGENT.md + MOTIVATION.md |
| 同时能生效几个 | 任何时候恰好一个 | 想开几个开几个 | 想开几个开几个 |
| 住在哪里 | `rness/paradigms/<name>.md` | `rness/skills/<name>/SKILL.md` | `rness/roles/<name>/` |
| 自带的例子 | default、text-planning、translation、workflow-design | analyzer、anything-finder、girraph-merirmaid、memoir-dialectic、translator | block-breaker、open-skeptic |

### 3.3 造你自己的

这些文件你可以手写——它们就是 markdown，开头带一小段 YAML——但你不必。自带的 **workflow-design 范式**（第 14.4 节）存在的意义，就是让智能体和你一起造它们。说一句「给我造一个技能，它能……」或者「创建一个角色，他……」或者「做一个范式，用来……」，智能体就会切到 workflow-design，问它那些澄清性的问题（范围？名字？触发条件？配套文件？），然后规规矩矩地把这个部件写出来，包括那句告诉未来的对话什么时候该去够它的 `description:` frontmatter。

人们真正会造的东西：

- 为自己工作中每一种明确不同的模式各造一个**范式**——研究、起草、修订——并写清什么时候该切换。
- 一个把某份通讯的声音、某种引用格式、某篇论文的术语固定下来的**技能**。
- 一个当橡皮鸭、只问苏格拉底式问题的**角色**，或者一个多疑的同行评审，或者一个用你自己的知识文件喂出来的领域专家。

手册接下来的部分讲的是那些内置的东西。请把它们每一个都当成一份你有权复制、分叉和改进的范例来读。

## 4. 智能体对话——这一摞东西的底座

打开一个项目，你就落在讨论视图里：和你的智能体的对话，加上显示你项目的侧栏。这是一层。别的模式都叠在它上面，最终也都关回到它。（第 2 节的*主页*完全是另一回事——那是项目打开之前你在的地方；这里是项目打开之后你在的地方。）

这里有什么：

- **对话。** 敲一条消息，按 ⌘Enter（或发送按钮）。回应实时流出来，而且智能体可以边说边做——读写文件、跑 shell 命令、抓网页——每一次工具调用都在记录里当场出现。
- **麦克风按钮。** 点它，然后口述。语音由 whisper.cpp 在本地转写；你的声音不会离开这台机器。录音时按钮会一下一下地跳。再点一次停止。
- **侧栏。** 项目的文件树，加上那些控制区：生效的**范式**、**技能**和**角色**的开关，还有你的**请求**。option-点击任意文件或文件夹会出上下文菜单（新建文件、新建文件夹、复制路径、复制名称）。⌘\ 收起和展开整条侧栏。
- **顶栏。** 模型窗口、broker、UI 窗口、wikisink（🚰）和 cacheawl 的按钮——以及最右边，此刻叠着打开的那些模式的指示器（第 12 节）。

### 4.1 AGENT.md 和 MOTIVATION.md

每个项目都在 `rness/` 里带着自己的这两个文件。它们是智能体身份的根，每一轮都会被载入。

**`AGENT.md`** 是*怎么做*：工作指令。语气、护栏、惯例、长期有效的吩咐。「散文一律小写。」「永远别碰 `archive/` 里的文件。」「跑超过一行的 shell 命令之前先问我。」

**`MOTIVATION.md`** 是*为什么*：眼前任务之外的价值和优先级。这个项目是为了什么、服务谁、哪些取舍要紧（正确优先于速度？简洁优先于周全？），以及「完成」是什么感觉。

在侧栏里点任一个文件就能读；按**自定义**分叉出你项目本地的副本，或者用你喜欢的任何编辑器改它。改动在下一条消息上落地。角色用的是同样的两文件模式（第 15 节）——主智能体并不特殊，只是排在第一个。

### 4.2 策略文件夹与允许列表

`rness/policies/` 装着智能体的硬规矩。不是性格——是法。默认自带四条策略：

- **`allowlists.md`** —— 够得着什么的规矩。三份列表：
  1. *可读文件前缀：* 智能体可以在项目之外读的绝对路径（默认：`~/enough/`）。
  2. *可读写文件前缀：* 它还可以在项目之外写的路径。这份列表出厂时是**空的**：开箱即用时，智能体只在你的项目里写，而且会一直如此，直到你有意加进一个路径。
  3. *互联网域名：* 直接抓取的主机（默认包括 `gutenberg.org`、`en.wikipedia.org`、`en.wikisource.org`、`archive.org`、`standardebooks.org`，以及 Kiwix 的下载主机）。不在列表上的域名并不会被拦掉——那次抓取会改走本地的 Tor 代理，这样一次临时查阅就不会把你的地址留在某台服务器的日志里。broker 上有一个开关可以关掉这个兜底，让不在列表上的抓取直接失败。
- **`context-management.md`** —— 智能体怎么察觉上下文窗口在变满，并且不丢状态地体面重置（第 7.3 节）。
- **`requests.md`** —— 智能体在什么时候、以什么方式把长期工作记成请求文件（第 7.3 节）。
- **`profile-maintenance.md`** —— 什么该进项目档案，什么不该（第 7.1 节）。

策略和别的东西一样是从默认符号链接过来的，所以你可以全局收紧允许列表，也可以为某个需要更松（或更严）的项目单独自定义。实践中，改 `allowlists.md` 是最常见的一项自定义：把你信任的文档站点加进去，把智能体应该能写入的共享文件夹加进去，然后接着过你的日子。

## 5. 阅读/编辑模式

点文件树里的任意文件，它就在统一的阅读/编辑模式里打开：一个模式，两张*面孔*——用来审阅的**阅读面**（眼睛），和用来改文字的**编辑面**（铅笔）。

### 5.1 整幅 vs. 迷你，以及在一切之间来回

阅读/编辑有两种大小。**迷你**是对话旁边的侧边面板：一边聊，一边把参考文档搁在手边。（迷你面板故意不放审阅工具栏——它是用来读和小修的，不是用来标注的。）**整幅**占满整个画面，适合长文档和认真的编辑。

用面板边框上的「迷你↔整幅」按钮换大小。用它旁边的面孔切换按钮换面孔。⌘S 在编辑面上保存。当你看着的是某份转换文档的孪生本时，边框上还会写出原件的名字，并带一个**导出**按钮，把你的改动写回去（第 6.5 节）。而且一切都有脏数据保护：只要你有没保存的改动，enough 就会在任何东西要丢掉它们之前先问你——跳到另一个文件、关掉这个模式、蹦到另一份文档。你不会因为一次手滑，赔掉一小时的活儿。

文档打开着的时候，顶栏会出现三个计数器，跟着你打字一起走：**¶** 段落、**W** 词、**C** 字符。（主页的列表视图给你看的是整个项目的同样三个合计——第 2.1 节。）

和每一个整幅模式一样，阅读/编辑会在右上角的指示区放上它的图标，下面挂着一条小小的红叉飘带用来关闭（第 12 节）。

### 5.2 高亮

在任何 markdown 文档的阅读面上，选中文字，从工具栏或选区上冒出来的浮层里给它涂上四种颜色之一——**黄、绿、蓝、粉**。同一条工具栏还提供轻量的格式：加粗、斜体、下划线（⌘B / ⌘I / ⌘U）。

高亮是耐久的，而且住在正文之外：每份文档有一个隐藏的伴生文件（`.<filename>.highlights.json`），而不是把标记塞进你的文字里，所以文档本身保持干净。页边上一道彩色的带子标出每一行被高亮的位置。高亮跨会话留存，颜色重叠时会叠加。

接下来这一点会改变你的工作方式：智能体看得到它们。它的 `read_highlights` 工具按颜色列出一份文档里的每一处高亮，`navigate_to_highlight` 把视图跳到某一处。这让高亮变成了一条通道。把你想重写的四段涂黄，把你喜欢的两段涂绿，然后说「重写黄的部分；保留绿的那种语气」。你一提颜色，智能体就知道你说的是你的高亮。

### 5.3 支持的文件类型

- **Markdown（`.md`）** 在阅读面上渲染成排好的样子，在编辑面上是源码。markdown 是 enough 的母语——这套系统自己写的几乎所有东西都是 markdown。
- **纯文本**，以及任何像文本的东西，在阅读/编辑里当文本打开。
- **`.girraph`** 文件改在 girraph 模式里打开（第 17 节）。
- **`.merirmaid`** 文件改在 merirmaid 模式里打开（第 18 节）。
- **保存下来的维基百科条目**（`wiki/` 文件夹里的 `article.html`）在 wikisink 阅读器里完整保真地打开（第 10.2 节）。
- **Word 文档、PDF、电子书、幻灯片、工作簿**以可编辑的 markdown **孪生本**打开——树里一行，点一下，边框上一个**导出**按钮把你的改动写回去。那是第 6 节，整个故事都在那儿。
- **图片**（`.png`、`.jpg`、`.gif`、`.webp`、`.bmp`、`.svg`）在一个朴素的查看器里打开（第 6.9 节）。文档*里面*的图片，在阅读面上和 markdown 里的任何图片一样渲染出来。

enough 仍然是一套文本系统，而且会一直是：它渲染 markdown，不做页面排版。它对其他一切做的事情是转换——转得够无损，让你能在里面干活；也转得够诚实，会告诉你什么没能活下来。

## 6. 和 PDF、Word 文档以及其他文件打交道

enough 不渲染 PDF，不给 Word 文档排版，也不画电子表格，而且它不假装自己会。它做的事情更安静，对你在这里做的这类工作也更有用：它把文档转换成你真的能读、能改、能高亮、能交给智能体的 markdown——并且让这份 markdown 一直和原件系着，好让你的改动能回去。

这件事里没有单独的模式，也没有单独的应用。你点那个文件。它就打开了。

### 6.1 孪生本

打开 `memo.docx`，enough 会在旁边写下 `memo.docx.md`。第二个文件就是**孪生本**：文档的一份朴素 markdown 副本，摆在你的项目文件夹里，随你像改别的文件那样改它。造出它，从来不会动到原件。

在文件树里你看到的仍然只有一行——`memo.docx`。孪生本、从文档里抠出来的那一堆图片（`memo.docx.assets/`），以及一个记录着什么是从什么转来的小小隐藏文件，全都折进了那一行，所以你的项目看起来还是它在 Finder 里的样子。点那一行，孪生本就在阅读/编辑模式（第 5 节）里打开，那个模式给你的一切都在：两张面孔、⌘S、脏数据保护——展开到整幅之后，还有高亮。

有两个后果值得知道。命名不会撞车：你自己写的 `memo.md` 和 `memo.docx.md` 是两个不同的文件，enough 从不把它们弄混。而如果你在 Finder 里删掉了 `memo.docx`，什么也不会坏——孪生本安安静静地变成你树里一个普通的 markdown 文件，它本来也一直就是。

你的智能体看到的和你一样。让它读 `report.pdf`，它拿到的是孪生本，没有的话它会先转一份；让它改点什么，它改的也是孪生本，正是你自己的改动落下的地方。

### 6.2 enough 能这样打开什么

这份清单来自应用本身，而不是某个人必须记得更新的一段文字——如果你是在 enough 之外读到这里，请到应用里打开帮助中心（第 9 节）看它填好的样子：

{{convert-formats}}

### 6.3 树里的那个标记

每一份可转换的文档，在它那一行的右边都带着一个小标记，而这个标记只干一件事：告诉你两边是不是还一致。

- **安静** —— 已转换，而且两边一致。没什么要做的。
- **亮着，你的颜色** —— 你改过孪生本。那些改动在 markdown 里，还没进原件；准备好了就导出（第 6.5 节）。
- **亮着，智能体的颜色** —— 转换之后，原件在 enough 之外被改过。有人在 Word 里改了它；一份新副本盖了上去；它从共享盘上下来了。
- **亮着，错误的颜色** —— 上面两种都发生了。这是唯一一种 enough 会来问你的情况，而它确实会问（第 6.7 节）。
- **空心** —— 可以转换，还没转。点它就转。
- **空心，而且点了会解释某个扩展** —— 在还读不了这些的安装上打开 PDF、幻灯片或工作簿（第 6.8 节）。

把鼠标停在标记上，会用一句话说同样的事。点这个标记和点文件名，做的完全是一件事。

### 6.4 第一次打开这样一份文档

每一*类*文档你第一次打开时，会有一个简短的对话框解释接下来会发生什么——孪生本是什么、它去哪儿、原件留在原地。一个「好」按钮。它是每类一次，不是每个文件一次：你的第二份 Word 文档直接就打开了。

办公文档的转换很快，寻常的东西远不到一秒。跑的时候角落里会有一个小提示，慢的那些上面还带一个**取消**按钮。PDF 要久一些，并且会给你一条诚实的进度条（第 6.8 节）。

### 6.5 把你的改动导出回去

打开着的孪生本，边框上带一个**导出**按钮。一个对话框，三个决定：

**导成哪种格式。** 原件自己的格式已经预选好，其余的导出目标也都在——一份 Word 文档可以出成 PDF、EPUB，或者一个自包含的 HTML 页面。这个格式做不到的事情会灰着显示并写明原因，绝不会悄悄不见。

**副本，还是原件。** 默认是在原件旁边写一份**带日期的副本**——`memo-2026-08-19-1042.docx`——而且确切的文件名会在你按下去之前先在对话框里给你看。什么都不冒险：你得到一个新文件，旧的分毫未动。第二个选项就地覆盖原件，而且只有当你要导出的格式就是原件自己的格式时才会提供。选了它，enough 事后会给你一次**撤销**：留下新文件，或者把旧的字节原样放回去，一个字节都不差。

**要不要从此保持同步** —— 见第 6.6 节。

说一句这趟旅程里什么能活下来。覆盖一个 `.docx` 或 `.odt` 时，会拿原件当样式参照，所以页面尺寸、字体，以及任何页眉页脚，都会跟着你的文字一起回来——这些是 markdown 无从表达、否则就会丢掉的东西。而 markdown 确实带不动的东西，就回不来了：修订记录和批注（在进来的路上被接受并丢弃）、文本框、域、精确的图片尺寸。正是这种不对称，让带日期的副本成了默认，也正是它让 enough 从不擅自重写一份原件。

### 6.6 让原件保持同步

在导出对话框里勾上**让原件保持同步**，之后每一次保存孪生本，都会顺手把原件也重写一遍。在 enough 里改，同事来要的时候，你磁盘上的那份 `.docx` 就是最新的。这是按文件的设置，勾上的那一刻就生效，而且每次保存传导过去时都会有一个小小的确认。

它只对写得回去的格式提供——Word、OpenDocument、Rich Text、EPUB；第 6.2 节里的「保持同步」那一列说了算。PDF 加入不了，而这个理由值得直说：enough 能从 markdown *写出* PDF，但它是从头重新排版的。一份同步的 PDF，会在你每次保存时，用它文字的一份朴素重排，换掉你精心排好的原件。那不是同步，那是拆迁，所以它不提供。

### 6.7 当两边都改了

原件可以在你不知情的时候往前走。你在这里改了孪生本；有人在 Word 里改了那份 `.docx`；现在有两个版本的真相。

enough 会注意到。在每一个要紧的时刻——画文件树的时候、你打开文档的时候、你保存的时候、你导出的时候——它都会拿原件和转换时记下的样子比一比，而只是被*碰过*的文件（复制、备份、打开又关上）不算数：这个检查读的是内容，不只是时间戳。

当两边真的都变了，你会得到一个对话框，三个用大白话说的选择：

- **留下我的孪生本。** 什么都不写。标记回到「你改过它」，以后再说。
- **覆盖原件导出。** 你的 markdown 说了算；原件被重写，照例给你一次撤销。
- **从原件重新转换。** 原件说了算；写出一份新的孪生本——而你旧的那份会被存到它旁边当作撤销文件，而不是被删掉。

那个对话框里的任何一个选择，都不会毁掉你拿不回来的东西。这就是整个功能建在其上的设计准则。

### 6.8 读 PDF、幻灯片和工作簿：PDF 扩展

读一份 PDF 比读一份 Word 文件难得多。`.docx` 至少还知道什么是标题；PDF 只知道墨落在哪儿，要把一张表、一个双栏版面或者一份扫描件从里面取出来，得靠真正的文档模型。那些模型很大，所以不在基础安装里——它们改成一点就到：**⚙ UI 窗口 → 扩展 → 安装 PDF 扩展**。

它的代价，老实说：

- 下载约 **250 MB**，装好之后磁盘上约 **1 GB**；
- 另加约 **0.7 GB 的模型权重**，取一次，存在 `~/enough/weights/docling/`；
- 几分钟，大部分是下载。安装程序会把日志流进窗口里让你看着，引擎会当场打开——不用重启。

你得到什么：**PDF**，包括扫描件（文字用 OCR 从像素里读出来）；**PowerPoint 幻灯片**，每一页变成带标题的小节；以及 **Excel 工作簿**，每张表变成 markdown 表格。

速度是量出来的，不是猜的，在 Apple silicon 上：数字版 PDF 每页约 **0.9 秒**，外加每次转换一次性的 **约 10 秒**模型加载。所以一页的 PDF 大约十秒，一百页的书大约一分半，一份幻灯片或工作簿几秒钟。长的转换会显示进度，也可以取消；取消不留下任何东西——没有半份孪生本，没有零散的文件夹。

有两件事能省下你以后疑惑的一刻。第一：**写 PDF 完全不需要这些。** 任何孪生本在任何安装上都能导出成 PDF，有没有扩展都一样，因为干这活儿的排版器随 enough 一起来。这个扩展是用来*读*的。第二：如果「需要一个扩展」的提示出现在一台你确信装过的机器上，请看清你收到的是哪一句——软件包和模型权重是两次独立的下载，中途断掉的连接可能让你只拿到了第一样。再跑一次安装就把活儿干完，而且已经有的东西一样都不会重下。

更新不会拿走这个扩展。`update-enough.command`（以及 `/update-enough`）记得你装过什么，每次同步都会再问一遍，所以一次例行更新不会悄悄把 PDF 阅读收走。

### 6.9 图片，以及看一眼原件

点一张图片，它在一个朴素的查看器里打开：默认适应宽度，点一下换成实际尺寸并四处滚动，透明的地方后面是棋盘格，名字、像素尺寸和文件大小在头部。它是只读的。enough 不是图片编辑器，在那个方向上也没有野心。

文档*里面*的图片是另一回事，它们能过得来：你 Word 文件里的那张照片会被抽到 `memo.docx.assets/`，并在孪生本的阅读面上渲染出来，和别的 markdown 图片一模一样。

而当孪生本不够用时，PDF 的边框上带着 **view original**：它会在面板里打开真正的那份 PDF，好让你拿孪生本和实际的页面对一对。关掉它，你就回到孪生本里，停在你离开的地方。

### 6.10 转换让你付出什么，两句话

有两个限制值得挑明了说，而不是留给你自己撞见。工作簿的各张表会变成一张接一张的表格，**没有表名标题**——读取器不产出它们，而 enough 宁可留个空档，也不愿凭空编一个名字。而从 PDF 里抠出来的图片，alt 文字每次都是「Image」：文件里没有说明文字可以给它更好的一个。

除此之外，是那个不变的承诺：**不问过你，你的原件永远不会被改动。** 转换永远只在旁边写新文件。导出覆盖是唯一一条会碰到原件的路，它需要你有意地点一下，而且事后给你留着撤销。

## 7. 项目文件夹与 `rness/`

一个项目就是一个文件夹。任何文件夹。enough 只往里加一样东西：`rness/`，也就是智能体在这个项目里被外置出来的大脑。智能体在这里所是的、所知的、所记的一切，都以普通文件的形式住在那个文件夹里。你可以全部读它，全部改它，如果你有这个习惯，也可以把它放进 git。

它的结构：

```
your-project/
  rness/
    AGENT.md            who the agent is here          (4.1)
    MOTIVATION.md       why it works                   (4.1)
    active-paradigm     which paradigm is in force     (14)
    paradigms/          available reasoning frameworks (14)
    skills/             available skills               (16)
    roles/              available personas             (15)
    policies/           the hard rules                 (4.2)
    knowledge/          project memory                 (7.1)
    io/                 input/output workspace          (7.2)
    requests/           long-running work tracking      (7.3)
  ...your actual files...
```

符号链接过来的条目（树里的斜体）跟着全局默认走；对其中任何一个点自定义，就分叉出一份本地副本（第 3.1 节）。你以任何方式丢进项目的文件——Finder、别的编辑器、智能体——在下一轮里对所有人都同样可见。

一份转换过的文档（第 6 节）也会往这里添文件，永远在原件旁边，永远以它命名：`memo.docx` 会得到一个在 `memo.docx.md` 的孪生本、放在 `memo.docx.assets/` 里的图片，以及一个隐藏的 `.memo.docx.convert.json`，记着什么是从什么、在什么时候转来的。文件树把这三样折进原件那一行，但它们就是你磁盘上的普通文件——你可以把这一对复制到另一台机器上、放进 git，或者删掉孪生本、再点一次原件拿一份新的。那份隐藏的清单是 enough 的账本；别去动它，它就一直准确。删掉它，enough 就干脆把这份文档当成从没转换过。

### 7.1 knowledge 文件夹

`rness/knowledge/` 是按项目的记忆。

**`project-profile.md`** 是这个文件夹里最有用的文件。它的内容每一轮都会灌进智能体的系统提示词：写在这里的东西就在智能体的工作记忆里，不需要再去查。智能体会随着你们的工作维护它——观察到的偏好、反复出现的文件和人、你们采用的惯例、还开着的线头——你也可以直接改。把一条长期有效的偏好在档案里说一次，好过每次会话都重复一遍。profile-maintenance 策略让这个文件保持克制：要具体的观察而不是含糊的标签，要提炼而不是存档。

**`session-logs/`** 里放着每次会话各轮对话的日期化 markdown 日志，还有 broker 的流水（第 8 节）。只增不改的历史。当你需要重建上周二到底发生了什么时，翻它，或者 grep 它。

除了这两样，这个文件夹是你的。加一个 `glossary/` 子文件夹、一份经验教训文件、一些背景笔记——你放在这里的东西智能体都能查阅。

### 7.2 io 文件夹

`rness/io/` 是那块过路的工作区：

- **`input/`** —— 把文件丢在这里让智能体处理。抓来的网页也会自动落在这里，转成 markdown 并缓存下来，所以抓过一次的页面就永远可以作为依据。
- **`output/`** —— 生成的东西落脚的地方。看一看，留下好的，其余清掉。
- **`cloud-cache/`** —— 如果你用云模型槽，每一次云端往来都记录在这里（第 13.2 节）。就算是云上的活儿，也留下一份本地的、可以 grep 的纸面记录。

### 7.3 请求：长活儿怎么活下来

这一条很少出现在快速上手导览里，但它正是让跨会话工作成为可能的机制，所以值得花两分钟。

当你要的东西不止一两轮能做完时，智能体会在 `rness/requests/` 里开一个**请求文件**：一份 markdown 记录，写着目标、进度检查点，以及一路上做出的决定。这不用你开口。认出一件任务的形状，是智能体的活儿。

请求文件之所以要紧，是因为上下文窗口会满。enough 盯着对话的压力，而按照 context-management 策略，智能体会在溢出之前把状态存进活跃的请求文件。取决于你的编排设置，enough 接着要么自动重置（清空内存里的对话，从检查点重新开始），要么挂起并显示一条横幅，等你准备好了再重置。不论哪一种，真正的记忆是文件系统，不是那段对话：新的会话读一读请求文件里的续接（Continuation）块，就从事情停住的地方接着走。

做完的请求会移到 `rness/requests/done/`——在打开的请求上点**标记完成**，或者跟智能体说一声。这个 done 文件夹对智能体是写保护的，而且它兼职当着一本诚实的日志，记着你们俩到底交付过什么。

## 8. broker 窗口

broker（工具中介）是 enough 的信任锚点。智能体做的每一次工具调用——每一次读文件、写文件、跑 shell 命令、抓网页——都从它这里过。🔀 broker 窗口就是你看着并调整这件事的地方。

十一个开关，分成几组：

| 开关 | 它管什么 |
|---|---|
| trace log | broker 到底写不写它的流水 |
| local models only | 云端槽（OPRO-API）在模型选择器里到底出不出现 |
| read_file / write_file / shell brokered | 每个工具的追踪日志，一个工具一个开关——一共三个（允许列表*始终*照常执行，不受影响） |
| fetch_url enabled | 智能体的网页抓取工具到底能不能用 |
| Tor for off-list fetches | 不在允许列表上的域名：走 Tor（开）还是直接拒绝（关） |
| cache & convert fetches | 把抓到的页面转成 markdown 并缓存在 `rness/io/input/` |
| wikisink tools | 智能体那四个 wiki 工具能不能用（你自己用 🚰 浏览，从不受管） |
| wikisink live updates | 更新运行到底能不能联系维基百科（关 = 只从本地状态出报告） |
| cacheawl tools | 智能体的 cachebox 工具能不能用（你自己的 cacheawl 模式从不受管） |

一切默认都是开着的：默认把项目托付给智能体，同时用一份纸面记录让它保持诚实。那份记录——**追踪流水**——落在 `rness/knowledge/session-logs/<date>-broker.md`：时间戳、工具、决定、参数、结果，每一次经手的调用都在。而当某个开关或允许列表拦下了什么，智能体会收到一条清楚的拒绝消息，说明什么被拦了、为什么，这样它能告诉你，而不是无声地失败。

留意那张表里的设计原则：管着智能体工具的开关，从不管*你*的界面。关掉 cacheawl 工具，并不会把你锁在 cacheawl 模式之外。它的意思是智能体不能自己伸手去那个仓库。

## 9. UI 窗口与帮助文档

⚙ UI 按钮打开显示偏好和参考资料。那个窗口右上角、× 旁边有一个小小的**帮助**按钮：它以只读方式、在应用里打开这份手册，和别的模式一样是一个整幅模式（第 12 节）。

出口如今搭在标题栏上：**close project → home**，就在帮助按钮旁边，它结束这次会话并把你送回主页（第 2.5 节）。它会先问，而且会说明它不做什么——磁盘上的文件夹分毫不动。在应用里你多半更愿意去按 ⌘W；这个按钮是同一件事，而如果你在浏览器里跑 enough，它就是*唯一*的那一个。（主页上没有它，那里没有项目可关。）

它还放着 enough 里唯一一样能从 enough 内部装上的东西：**PDF 阅读**的**扩展**那一行（第 6.8 节）。这一行告诉你现在的状况——未安装、安装中、已安装，或者装了但还没完事——而安装按钮会把整份日志边跑边流进窗口里，所以一次长下载是你可以看着的东西，而不是干等着的东西。装完之后，PDF 就开始能打开了；什么都不用重启。

### 9.1 主题

enough 自带四个：**Enough Default**（深蓝紫的暗色）、**Pastel**（淡色纸张，取自 Terminal「Man Page」配色的精神）、**Wireframe** 和 **Darknest**。切换是即时的，界面里每一个图标都会当场重新取用它的明色或暗色版本。

主题不是写死的。它们住在 `~/enough/config/ui.json` 里，是一块块具名的颜色值，每一个都作为 CSS 自定义属性生效。复制一块现成的，改个名字，换掉颜色，重新加载：你的主题就在下拉框里了。文件顶部的 `_doc` 块解释了每一个键。

### 9.2 字体

同样的路数。自带四套字体栈——SF Mono、系统无衬线、Georgia 衬线、Courier——也欢迎你在同一个 `ui.json` 里添自己的。字号见下面那两个旋钮（第 9.3 节）——而在浏览器标签页里，老老实实的浏览器缩放（⌘+ / ⌘−）依然可以叠在它们之上，用着挺好。

### 9.3 缩放——界面缩放与文字缩放

这件事从前的答案一直是浏览器缩放，直到桌面应用来了，而它外面没有包着浏览器。于是 enough 长出了自己的，并顺手做得更好了一点：不是一个旋钮，而是两个，就在主题那一行下面。

**界面缩放**把*所有东西*都调大调小——图标、标签、侧栏、对话、还有这个窗口本身——每次 0.1×。**文字缩放**只调你眼前的那份文档：阅读/编辑里的页面、一篇 wikisink 条目、文件预览、还有参考模式里的这份手册。它们相乘，而且互不打扰：0.9× 的界面配 1.5× 的文字，是读一份手稿的好办法；反过来，则是把它挪出你这个下午的好办法。点任一个数字，就把那个旋钮弹回 1.0×，另一个不动。

两者都是**按项目文件夹**记住的——你隔着房间读的那份稿子，和你伏案写的那些笔记，各自守着自己的尺寸，谁也不拽着谁。主页保持原始大小，所以那里不出现这两个旋钮。

上下限会随你的屏幕呼吸：在今天的显示器上大致是 0.5× 到 2×，在小窗口里收紧一些，好让界面总还留得下做自己的余地，在非常大、非常密的屏幕上则放宽（2046 年那面 8K 的墙可以到 3×）。当再走一步就要越线时，按钮会抖一下，数字泛红一下，然后什么都不变——这就是全部的错误提示了。

### 9.4 语言

界面会说六种：英语、法语、西班牙语、德语、中文和日语。同一行上的 **ui language** 下拉框会把你眼前的一切换过去——标签、工具提示、`(?)` 气泡、这份手册——实时切换，不用重启。这个选择是机器全局的，和主题一样搭在 `ui.json` 上，所以主页和每个项目在这件事上是一致的。

它有意*不*碰的东西：你的文件、你的对话、你的智能体。用适合你的语言和智能体说话——本地模型这六种都很自在——但 enough 把自己的脚手架（技能、范式、提示词、项目文件）留在英文里，因为那是模型读得最稳的语言。有几样生成出来的东西也留在英文：那些从*你这台*机器上实际装着的东西现取的列表，比如某个气泡里的技能清单，或者文件格式表。而任何一处翻译还没跟上新的英文标签的地方，你看到的会是英文，而不是一片空白：不够好看，但绝不残缺。发现了一处？那是 bug——[enough.support](https://enough.support) 欢迎它。

### 9.5 速查表

两栏参考，就在 UI 窗口里。

**键盘快捷键：**

| 按键 | 动作 |
|---|---|
| esc | 关掉最上面那层打开的模式 |
| ⌘ \ | 显示 / 隐藏侧栏 |
| ⌘ K | 聚焦对话输入框 |
| ⌘ Enter | 发送消息 |
| shift Enter | 换行，而不是发送 |
| ⌘ B / I / U | 把选中的文字加粗 / 斜体 / 下划线（阅读面） |
| ⌘ S | 保存（编辑面） |
| ⌥ 点击 | 文件树上下文菜单 |

（在非 Mac 键盘上：用 Ctrl 代替 ⌘，用 Alt 代替 ⌥。）

这些是界面自己处理的快捷键，所以在应用里和在浏览器标签页里一样管用。应用另外从菜单栏加了两个：**⌘W** 关闭项目并回到主页（第 2.5 节）——它*不再*关闭窗口了——以及 **⌘Q** 退出，一如既往。

**markdown 速查表：** 标题、列表、链接、代码、引用——整份快速参考，给还在把 markdown 练熟的人。这件事值得做，因为 enough 到处都以它为母语。

### 9.6 在界面里的帮助（IHH）

散布在界面各处的 `(?)` 气泡就是内置的帮助系统：一个概念一个气泡——技能、角色、范式选择器、rness、io、knowledge、cacheawl、wikisink、模式系统、转换后的文档等等——每一个都有一段 **what**、一段 **how** 和一列 **ideas**。技能、角色和范式的气泡列出的是*你这个*项目里实际装着的东西，而转换文档那个气泡的文件类型表来自应用自己的格式登记表——全都是现场生成的，所以帮助永远不会和现实脱节。（本手册第 6.2 节里那张表也是同一个来源。）

气泡由 UI 窗口里的「help (?) bubbles」勾选框按项目文件夹控制。新文件夹默认开着，这个设置按文件夹各记各的——所以你那个天天用的老项目可以安静下来，而一个新开的实验还留着它的辅助轮。

连帮助本身也是可以自定义的。内容住在一个 markdown 文件里（`enough/static/help-docs.md`）；改它就是改那些气泡。

## 10. Wikisink

Wikisink（🚰）把一份英文维基百科的离线副本放在你的机器上：可以在应用里浏览、全文搜索，智能体读得到，你可以在上面做批注，还能按需刷新并附上一份变更报告。装好之后，它完全不需要互联网。

### 10.1 设置

第一次点 🚰，向导会问三件事。

1. **体积。** 归档是 Kiwix 的构建，除非特别说明都是纯文字：

   | 口味 | 内容 | 大致体积 |
   |---|---|---|
   | 最热门 100 万条目 *（默认）* | 阅读量最高的一百万条 | ~16 GB |
   | 全部英文维基百科 | 每一个条目 | ~49 GB |
   | 最热门 5 万 | 阅读量最高的五万条 | ~2.1 GB |
   | 最热门 5 万迷你版 | 约 5 万条，只要开头几段 | ~320 MB |
   | 简明英语版 | 完整的简明维基百科 | ~950 MB |

2. **存放。** 默认是 `~/enough/wikisink`；任何文件夹都行，外接硬盘也算。除了归档本身的体积，留出大约 5% 的余量。
3. **确认。** 下载可续传，也扛得住退出——在同一个窗口里暂停、继续或取消，enough 的其余部分照常工作。

归档是一个就地读取的 `.zim` 文件。它从不被解压，也从不弄乱你的文件管理器。你可以登记**多份安装**——比如外接硬盘上放完整归档，内置磁盘上放一份小的——并在 ⚙ 的安装列表里来回切换。硬盘拔了什么也坏不了：那份安装会显示为不可达，直到硬盘回来，而你的评论和保护是独立于任何一份归档存在的。

装好之后，🚰 打开阅读器：后退和前进、搜索框里实时的标题提示（回车就在整个归档上做全文搜索）、一颗 🎲 随机条目骰子，还有一枚来源标记，告诉你你读的是归档快照（`ZIM <date>`）、某次更新带回来的更新副本（`live <date>`），还是一份被保护下来的副本（`preserved`）。内部链接留在应用里；外部链接在你的浏览器里打开。底部那颗对话小药丸，把当前条目——或者你选中的那一段——直接递给智能体。

**更新快照的小药丸。** Kiwix 会周期性重建这些归档，而这件事不该由你去打听。当*你这个*口味有了更新的构建，阅读器工具栏上会冒出一颗小药丸——`newer snapshot: <date> · <size>`。点它，确认体积，升级就地跑起来：同一个存放文件夹，先下载，下完了才换上，旧文件在那之后才删，不会更早。你的评论、保存和 🛡 保护都原封不动地过去，因为它们没有一样住在归档里面。下载时药丸变成进度读数，然后消失。enough 一天最多查一次，从不在阅读器正在渲染时查，你离线时它就安安静静——对一个离线维基百科的功能来说，离线本来就是常态。同一个升级也可以绕远路来做，在 ⚙ 的安装列表里，而且智能体的 wikisink 运行也会报告它（第 10.3 节）——但按下那个按钮的，永远是你。

### 10.2 保存与锁住条目

**保存。** 保存按钮给两个去处：本项目的 `wiki/` 文件夹，或者所有项目共享的、机器全局的 wiki cachebox（`~/enough/cacheawl/wiki/`）。不论哪一个，一次保存都是一个文件夹——`article.html`，归档里那篇条目一个字节不差的样子，加上 `_manifest.md`，带着标题、来源网址、获取日期和 CC BY-SA 的许可行。每一篇保存下来的条目都自带说明，这意味着如果它的文字有一天进了你要发表的东西，你需要的署名就摆在它旁边。在树里点一份保存的 `article.html`，它会在阅读器里完整保真地打开——信息框、表格一应俱全——哪怕一份归档都够不着。想取消保存，在树里悬停那个保存的文件夹，点出现的 🗑。

保存是为*你*的：离线的离线副本、发表时的署名。智能体不需要保存——它的工具随时都能把归档里的任何条目当成干净的文本读出来。

**评论。** 选中文字按 💬，或者用工具栏的 💬 做一条段落级的批注。讨论串住在 🗨 面板里：回复、解决、重开、跳转。评论附着在*条目*上，而不是某个文件上，而且它们靠体面地退让活过条目的更新。文字还在的，保持**锚定**。文字被改掉的，**重新钉**到它所在的段落。整段被删掉的，评论会以**孤儿**的身份留在面板里——标着，但绝不自动删除。

**锁住（删除保护）。** 有时线上维基百科会删掉一篇你正倚重的条目；最经典的情形是某个冷门主题因「关注度不足」而不是质量被砍。🛡 按钮把你的本地副本永远保下来——从此带着 `preserved` 标记提供，不参与以后的刷新，仍然可以被搜到。更新运行的报告确实会给检测到的删除打分（以关注度为由的算可疑，侵犯版权的算无害），好让你知道哪些删除值得看一眼。而这项保护有意只归你：智能体可以建议 🛡，但它永远按不了。

### 10.3 wikisink 更新，以及变更报告

「Wikisink」也是个动词。你保存过或评论过的每一篇条目都被*关注*着，而让智能体「跑一次 wikisink」（或者让它调用自己的 `wikisink` 工具），就是拿关注列表去和线上维基百科对一遍，然后回来报告。一次运行会：

1. 把有变化的关注条目刷新进一层本地覆盖（它们的标记翻成 `live`）；
2. 标出**编辑激增**——那些突然一天被编辑几十次的关注条目，加上全维基范围的激增候选；
3. 拿每日**前 1000 名浏览量排行**和上次跑的结果做差：攀升的、下滑的、新进榜的、掉出榜的，以及你关注条目的浏览趋势；
4. 检查关注过或最近看过的条目有没有被**删除**，并给可疑程度打分（第 10.2 节）；
5. 在有**更新的基础快照**可用时提一句。要不要换掉那个好几个 GB 的基础归档，永远由你决定——按阅读器工具栏里的那颗药丸（第 10.1 节），或者用 ⚙ 的安装列表。没有任何智能体工具能替换它。

报告以 markdown 的形式到达对话里；不设上限的完整版留在 wikisink 的状态文件夹下。这些运行对维基百科是客气的——分批、诚实的 User-Agent——中断了还能接着跑，而 `report-only` 的运行会跳过刷新那一步。这一切由两个 broker 开关管着：一个整个儿地管着智能体的 wiki 工具，另一个可以强制运行完全离线。

## 11. Cacheawl

Cacheawl 是机器全局的文本仓库：放那些你想永远留着、并且要从每个项目都够得到的东西。它住在 `~/enough/cacheawl/`，对每个项目的文件树都隐藏，被你所有的 enough 实例共享。（如果你跑过更早的 enough，你旧的 `infoworld/` 库在 0.1.6 首次启动时已经溶进了 cacheawl——`personal/`、`public/` 和 `wiki/` 成了你最初的三个 cachebox。什么都没丢。）

### 11.1 cachebox 和它们的 merirmaid 图

一个 **cachebox** 是仓库里的一个顶层文件夹，它有两种口味。**普通盒子**装着你自己组织的、要永远留着的文字：一个放参考笔记的 `personal` 盒子、一个放已发表作品的 `press` 盒子，什么结构对你有用就用什么。**缓存副本**则是从某个来源*导入*来的盒子——一个本地文件夹、一个网站，或者一组维基百科条目——它们记得自己从哪儿来。

每个盒子都带一张 **merirmaid 图**：`_cachebox.merirmaid`，一张关于盒子结构的活图，内容一变就重新生成。双击它就能一眼看清一个盒子的形状。这张图是一面*镜子*，按设计是只读的，因为它映照的是现实——想改图，就去改盒子。一遍便宜的对账让镜子保持诚实，哪怕你背着 enough 从 Finder 往里丢了文件。

从顶栏打开 **cacheawl 模式**看双栏视图，一边是项目，一边是仓库。把文件拖过去就是复制。按住 shift 拖是移动。shift-点击出上下文菜单，双击则用任何文件天生的模式打开它——girraph、merirmaid、阅读/编辑，或者 wiki 阅读器——直接从仓库里打开。

### 11.2 cachebox，以及捕捉本地或网上的文档

cacheawl 模式里的**导入栏**（或者随口一句请求）把外面的材料捕进一个盒子：

- **一个本地路径** —— 把一个装着笔记或文档的文件夹复制进仓库。
- **一个网站** —— 按你选的深度爬一个文档站或参考站（上限大约 500 页），把它作为本地 markdown 留下来。网页导入遵守你的抓取开关和允许列表，包括 Tor 路由。
- **维基百科** —— 从你的 wikisink 归档里，把某个主题的条目（上限大约 200 篇）拉成永久的、不依附任何项目的文本。

导入在后台跑。盒子会立刻出现，带着一个你可以看着的「导入中」状态，而失败的导入会明说，不会假装自己完成了。智能体的 cachebox 工具（列出、创建、导入）受 cacheawl 的 broker 开关管着；你自己用 cacheawl 模式从来不受管。

何必费这个劲？因为项目文件夹是工作空间，而 cacheawl 是图书馆空间。把一个框架的文档导入一次，以后每个项目都能离线地拿它当依据。把你常青的参考笔记留在一个盒子里，你以后聊天的每一个智能体都够得着它们。做完一件东西就把它挪进一个盒子，在那里它比它的项目活得更久。

## 12. 多个模式同时叠着

enough 的整幅模式——阅读/编辑、girraph、merirmaid、wikisink、cacheawl——彼此不替换。它们**叠**起来，像一张张纸。打开 cacheawl，从一个盒子里打开一个 girraph，再在上面打开一个笔记文件：三层深，而关掉每一层，下面那层都原样露出来。同样的滚动位置，同样的深入程度，同样没保存的改动。

顶栏上，每个打开着的模式一个方形指示器，最新的在左边。每一个都挂着一条小小的红叉飘带，用来关掉那一个模式，被压在底下的也行。点一个被压住的模式的指示器，就把它提到最上面，别的一概不惊动。Esc 永远关掉最上面的那个。最后一个关掉时，你就回到讨论视图——那个空掉的栈（第 4 节）。

有两处便利值得知道：

- 迷你的阅读/编辑面板浮在整幅模式*之上*，所以你可以在底下的（比如说）girraph 模式里干活，同时把一份文档搁在手边。
- 打开一个已经在栈里某处的模式，不会复制出第二个。它会重新指向并把你原来那个提上来。

## 13. 模型窗口

顶栏上的模型标记打开模型窗口：是哪个脑子在回答你、还有什么可用，以及——如果你愿意——那个云端槽。

### 13.1 本地模型：概览与使用建议

七个受支持的本地模型——而且这个窗口如今也是装它们的地方。每一行你还没有的模型，都会显示它的下载体积，以及一个针对*这台机器*内存和空闲磁盘算出来的可行性判断：✓ 宽裕，~ 紧张，✗ 不建议。下载有实时进度条，扛得住退出（会从停下的地方续上），也可以取消而不丢掉已经下好的部分。装好的模型点一下就切换，除了正在用的那个，任何模型都能从它那一行删掉，把磁盘还给你。

| 昵称 | 模型 | 磁盘 | 最低内存 | 备注 |
|---|---|---|---|---|
| **G40-04** | Gemma 4 4B (E4B) | ~5.4 GB | 8 GB | 最小的那个；哪儿都放得下；默认 |
| **Q35-09** | Qwen3.5-9B | ~5.9 GB | 10 GB | 均衡的中号；带 MTP 投机解码 |
| **G40-12** | Gemma 4 12B (QAT) | ~7.0 GB | 12 GB | 量化感知训练；16 GB 的甜点位 |
| **G40-26** | Gemma 4 26B MoE (4B active) | ~15.6 GB | 20 GB | 大模型的质量，中模型的速度 |
| **Q36-27** | Qwen3.6-27B dense | ~17.1 GB | 22 GB | 老练的重量级；带 MTP；耐得住长跑 |
| **Q38-04** | Qwen3.8 27B (4-bit) | ~19 GB + 1.7 draft | 24 GB | 最新的 Qwen；自己起草自己的投机 |
| **Q38-16** | Qwen3.8 27B (16-bit) | ~54 GB + 3.2 draft | 64 GB | 全精度，给最大的那些 Mac |

有一处命名上的小别扭，说清楚免得你被绊到：两个 Q38 名字里，横杠后面的数字是**量化位宽**，不是参数量——Q38-04 和 Q38-16 是*同一个* 270 亿参数的模型，分别是 4 位和 16 位精度。（G40-04 来自更早的命名习惯，它确实是一个 40 亿参数的模型。）窗口里的标签会把这件事讲明白，好让昵称永远不必自己解释。

一些经验法则。8–16 GB 的机器就住在 G40-04 上，等有了余量再把 G40-12 当作升级——量化感知训练让它在同尺寸里输出干净得不寻常。32 GB 上，G40-12 或 Q35-09 是舒服的日常，硬一点的综合活儿交给 G40-26 或 Q38-04。64 GB 往上，把 Q38-04 或 Q36-27 当默认，然后就别再想这件事了。Q38-16 自成一类：给内存充裕、还能腾出约 57 GB 磁盘的机器准备的全精度重量级——如果你有一台 Mac Studio 并且想要天花板，这就是天花板。上下文窗口会随你的内存自动伸缩——每个模型都带一个按内存档位定的合理默认值，可以在配置里改——而 Qwen 那几个白送多令牌预测（MTP）带来的额外速度：Q35/Q36 是做进模型文件里的，Q38 这一对则靠一个小小的配套「draft」文件，它会自动跟着一起下载。

还有一条针对终端安装的说明：一个模型可以在任何 llama.cpp 上*下载*，却只能在足够新的构建上*运行*。如果你那个对某个较新的模型来说太旧了，窗口会告诉你，并说清怎么修（`brew upgrade llama.cpp`）。用应用安装的人从来见不到这条提示——应用自带推理引擎。

切换模型会重启本地推理服务器，并清空内存里的对话。你的文件、日志和请求状态都还在；一次切换花掉的是对话的回滚记录，不是你的工作。

### 13.2 OpenRouter 支持（OPRO-API 槽）

enough 是本地优先，不是只能本地。第五个模型槽，**OPRO-API**，经由 OpenRouter 通往云端模型。它默认关着，有意做得费点劲才能打开，并且对这笔交易很坦白：你的提示词和输出会离开这台机器，换来的是前沿模型的能力，以及有时候，比一个同级本地模型所需的硬件和电费更低的成本。

打开它的方式：先在 broker 里把 **local models only** 关掉，然后在模型窗口里点 OPRO-API。一个三屏的向导带你走一遍——三个需要你明确勾选的确认框（你有账号、你明白计费、你明白隐私上的交换），然后是你的 API 密钥，然后是一次实时的健康检查。密钥存在 macOS 钥匙串里。它从不被写进任何文件，智能体没有办法读到它，而且 broker 会拒绝那些哪怕只是看起来想去够它的 shell 命令。验证通过之后，OPRO-API 就像别的模型一样可以选，它的设置面板提供重新测试、更新密钥、移除密钥，以及任你指定的 OpenRouter 模型 id。

有两件事让云端的使用可以被追究：

- **一切都在本地留底。** 每一次云端往来都写进 `rness/io/cloud-cache/`，带着 token 计数和一份索引——一份你本地的智能体以后能读的纸面记录。
- **`cloud_pipeline`** 让智能体把大活儿分批走云端槽——最多 200 步，每步都缓存、每步可选做摘要，最后再走一遍汇编——把结果写到磁盘上，而不是把对话淹掉。说一句「用一条 cloud pipeline 把十二章的摘要都起草出来」，重活就在旁路上干完，而且全程有记录。

## 14. 范式

范式是智能体的推理框架——工作怎么进行的交战规则。任何时候恰好有一个生效（显示在侧栏顶部；点 ● 切换），而生效的那个范式，全文都会在每一轮搭上系统提示词。智能体也看得到其他范式的一行目录，所以当你的请求换个地方会被伺候得更好时，它能建议切换——或者直接切。智能体主动切换并没有什么玄妙：它把那个范式的名字写进 `rness/active-paradigm`，然后告诉你它这么做了。

### 14.1 default

自由形式的单智能体对话。大多数工作用的范式，也是那个盯着「什么时候换个范式更合适」的路由器。它还带着那些长期有效的约定——比如知道「黄的部分」指的是你的高亮。

### 14.2 text-planning

为动笔之前那段长长的助跑准备的：把一本小说、一本文集、一本非虚构书或者一篇宣言，从「我想我要写点什么」带到一份能用的计划。智能体会和你一起在项目根目录里搭起一份计划文档——耐心地、一遍遍地、要花多少次会话就花多少次——然后在你要求时，为每一节生成*脚手架*：结构性的指引（节拍、小标题、语气提醒、字数预算），由你自己把它们展开成文字。这个范式的定义性规则是：**它绝不替你写正文。** 脚手架里只有结构。你的声音仍然是你的声音。（它会和 `analyzer` 或 `memoir-dialectic` 技能一起启用；回忆录会被交给 memoir-dialectic，那是专为它们造的。）

### 14.3 translation

把离线翻译宣布为一等能力。它和 `translator` 技能（第 16.5 节）配对：当一个请求涉及在人类语言之间搬运文字时，智能体就切到这里，而如果那个技能关着，它会告诉你你缺了什么——并且一直说到你把它打开为止。技能开着的时候，你就有了一个约 419 种语言的本地翻译器，不用账号、没有速率限制、也不依赖网络。

### 14.4 workflow-design

关于 enough 自身的那个范式，在你是在造或改工作流、而不是在工作流里干活时生效：新技能、新角色、新范式，以及对 AGENT.md 或 MOTIVATION.md 的改动。在这里，智能体表现得像一位深思熟虑的设计伙伴——动手之前先问清楚（范围？名字？触发条件？），在你的第一直觉还能更锋利时给出别的选项，而且每一次搭建都记一个请求文件，因为工作流的改动比产生它们的那些对话活得更久。正是这个范式，让第 3 节成为真的。

## 15. 角色

角色是你可以召唤进对话的第二人格：它有自己的 `AGENT.md` 和 `MOTIVATION.md`，和定义你主智能体的是同样的两文件模式，只是收束成一个互补的——或者有意对立的——性格。在侧栏里按项目开关角色。启用的角色会搭上系统提示词，你按名字招呼它们（「open-skeptic 会怎么说这个计划？」）。

### 15.1 block-breaker

一位写作卡壳的专家，从一位真实作者关于「他们怎么化开卡住」的回答里提炼出来。它先诊断再开方——没主意了、没胆量了、没结构了、没许可了，是四种不同的毛病——然后去够约束、成组的头脑风暴（「先来十个变体，再慢慢削」）、奇怪的重构，以及在你想要时，实实在在的下一句话。它顽固地反对认输。它的核心信念是：对任何自愿写作的人来说，卡壳总是有解的，因为那些规矩本来就是编出来的，解药也可以编出来。

### 15.2 open-skeptic

一个「可被说服的悲观派」：在 AI 强的地方是真心热情，在 AI 被吹过头的地方是职业性怀疑。当你正要搭一套工作流、并希望早早把失败模式都点出来时，就召唤它。它会反驳「让 AI 去复刻人类经验」，反驳没有人类审查、误差不断累积的链条，反驳用流利的自信冒充专业——同时为 AI 作为整理引擎、知识义肢和排练搭档叫好。它会随证据更新：给它看一套确实管用的工作流，它会明明白白地说，管用。

### 15.3 造你自己的

两个例子，一种模式——指令加动机，装在两个 markdown 文件里。角色是补上一种你缺的声音最便宜的办法：一只苏格拉底式的橡皮鸭、一个合规审查员、一个替你的目标读者出场的读者人格、一个用你自己的知识文件喂出来的领域专家。在 workflow-design 范式里张口要一个，智能体会采访你，然后把两个文件都写出来。

## 16. 技能

技能是一个聚焦的能力包：一个文件夹，里面有 `SKILL.md`（外加可选的参考文档和脚本），教会智能体一套流程、一套词汇，或者一种功夫。在侧栏里按项目开关技能。关就是真的关——根本不在提示词里——而且新技能到达时是禁用的，所以不会有什么背着你变了。不是 enough 自带的技能，在能被启用之前会先被读一遍（第 16.6 节）。全部关掉也是正当的：纯粹的对话，没有脚手架，有时反而给模型留下更多让你意外的余地。

### 16.1 analyzer

一个技能里的四种分析模式。

**Summarize（摘要）** 为任何文本产出一页公允的提要：它在说什么、写给谁、作者的动机与偏向、语气、关键引文。

**Proofread（校对）** 做轻量的文字编辑——错别字、拼写——覆盖从整份文档到整本书，由本地的规则式语法检查器 Harper 驱动。它还会另出一份校对报告，列出建议和重复措辞的发现，好让默默修掉的和需要判断的两类保持可分。

**Decide（决断）** 把你的两难交给内置十人名册里的三个原型人格，让他们当着记录辩一场。你拿到的是一条建议*和*那份记录，好让你去掂量推理，而不是相信一个裁决。

**Audit（审查）** 读一件你还没决定要不要信任的东西——别人发给你的技能、一个角色、一个范式——然后告诉你它是什么。先用大白话解释这东西究竟做什么、你为什么会想要它，然后走一遍安全检查：提示词注入的企图、悄悄扩大智能体触及范围的指令、认识论上的危险信号，以及任何随附的代码——那些代码还会另受一遍完全不用模型的确定性扫描。结论是三个词之一——**pass**、**flag**、**fail**——背后是具名的发现，而不是一个分数。它是只读的：审查从不运行、编辑、安装或启用它正在读的那个东西。

报告落在 `rness/io/output/analyzer/audits/<skill-name>/`：一份带日期的 `.md`，你可以像读别的文件那样读它，旁边还有一个小小的 `verdict.json`。你随时可以按名字要一份审查——「我启用它之前先给我把把关」「这个技能到底干什么」——而且当你第一次打开一个不是 enough 自带的技能时，enough 也会不用你开口就替你跑这个模式。两扇门写的是同一份报告，写进同一个文件夹。第 16.6 节讲这个故事。

### 16.2 anything-finder

一支去找那些不会出现在第一页上的东西的搜索队。三张面孔，一个技能。

**find** 是默认的那张，它带着十类难找之物各自的战术手册，外加第十一份，给那些卡住了的任务。**文本**——公版书、诗、历史文献。**影像**——稀有的、失传的、绝版的电影和电视，附上观看链接和它们的合法性说明。**图片**，为封面或独立刊物清好了权的。**产品**——冷门的器材、合成器、乐器，以及到底去哪儿能买到一件。**文章**——卡在付费墙后面的那篇论文，以它合法的公开副本被找到：预印本、机构库、档案馆。**代码**——宽松许可的仓库，包括那些从没碰过 GitHub 的库。**书**——从你已经爱过的书出发的同好推荐。**音频**——乐谱、MIDI、采样、器材手册。**素材**——字体、纹理、3D 模型、素材影像。**数据**——数据集、公共 API、政府文件、报纸档案。

结果以*发现卡片*的形式回来：链接、为什么它是对的那一件，以及——对任何涉及版权的东西——为什么它可以放心使用，附上出版日期或明确写出的许可。你可以问它「给我找一版公版的 *The Moonstone*，干净到能直接排版」「1974 年那版我能在哪儿合法地看」「有没有一个 MIT 许可的库能做这件事」。诚实的答案也是这笔交易的一部分：「这东西存在，但没有合法途径」和「三个候选，我对第二个有七成把握」在这里都是真正的结果；而当唯一的路是盗版站点时，它会明说，并转而把图书馆、借阅系统或者商店递给你。

**patents** 是现有技术那张面孔。给它一项发明，它会在已授权专利、公开申请和非专利文献上跑一遍结构化的新颖性检索，然后报告它找到了什么、这对新颖性和非显而易见性意味着什么——每一份报告里都留着那句「这不是法律意见」的免责声明，因为它本来就不是。「这个被申请过专利吗？」「关于一把磁力自行车锁的现有技术……」「我的点子能申请专利吗？」够不着的数据库会被标为*未检查*，绝不会悄悄当成*没有结果*。

**venture** 是「这算不算一门生意？」那张面孔，它把另外两张组合起来。一遍市场扫描看已经有什么、一次现有技术检查，再加一遍竞争格局的梳理，覆盖公司、开源替代品、相邻产品，以及那片试过之后关门的坟场。你拿到的是一份公允的判读——哪里挤、哪里相邻、哪里真的空着，以及证据实际支持的那个切口——随后是最强的*支持*理由和最强的*反对*理由，每一条都挂着链接，最后是一小串只有你自己能去回答的问题。你可以问它「我该不该做这个」「这个作为产品已经存在了吗」「这里的市场缺口在哪儿」。它不会给你的点子打分，不会替你写商业计划，也不会叫你去融资。而且它把一片空白的领域当成一个问题，不是一盏绿灯。

输出去到 `rness/io/output/anything-finder/`。它抓的一切都和别的网络访问一样从 broker 过，所以不在允许列表上的域名会走 Tor——而当某个来源拒绝回答时，报告会点出那台主机的名字，并告诉你该往 `allowlists.md` 里加什么，而不是在结果里留一个无声的窟窿。

### 16.3 girraph-merirmaid

给 enough 那两种图形原语（第 17 和 18 节）用的功夫技能。girraph 那一半教的是像样的 IBIS 制图：一轮一个问题、不许直接跳到解法、以你的确认作为停下的规则。merirmaid 那一半带着 Mermaid 的写作规矩，比如把节点标签写得短到你能舒服地编辑它。这两个模式不装这个技能也能用；装上之后，智能体才真正成为一个有纪律的制图搭档。

### 16.4 memoir-dialectic

一位耐心的、跨越多次会话的回忆录合作者。它采访你——一次一两个问题，绝不劈头盖脸——并且把一切归档：按对话顺序编号的计划文档、一份便于快速接续的索引、一个放乱糟糟脑内倾倒的笔记文件，最终还有一份提纲综述，以及——只有你想要时——草稿。文件夹就是记忆。你可以消失几周或者几年，它接着你离开的地方往下走。它为从完整人生故事到单独一个里程碑的整个跨度而造，对敏感话题和禁区有明确的处理方式，也小心保存你自己的措辞——声音要紧，尤其当草稿真的要来的时候。

### 16.5 translator

经由 MADLAD-400 实现的约 419 种语言的离线翻译——一次性下载约 3 GB，在 CPU 或 Apple Silicon 上跑，从不往外打电话。从短语到整篇文档，从主要语言到低资源语言和原住民语言。翻一封信、本地化一份 README、看看某一段到底什么意思、把一个短语经第三种语言绕一圈当作意义保真度的测试——全都可以拔了网线做。对某些低资源语言，还有一个可选的 NLLB-200 引擎质量更高；它带着非商业许可，所以要通过 translation 范式主动选用。

### 16.6 写你自己的，以及信任别人的

上面那五个是演示。技能*机制*——markdown 指令，打开时载入，带一句告诉智能体什么时候该出手的 `description:`——才是真正的功能。行文风格指南、领域检查清单、反复出现的报告格式、数据处理流程：只要你能用文字描述一种本事，你就能把它作为技能交给你的智能体。用 workflow-design（第 14.4 节）造你自己的，或者分叉那五个之一，把它变成你的。

这个循环的另一头，是从别处来的技能。技能是你的智能体会照着做的指令，这意味着一个来自互联网的技能，值得和任何来自互联网的文件同等的怀疑。所以 enough 替你读它们：

- **enough 自带的是可信的，而且看起来和一向一样。** 上面那五个是指向安装目录自身默认的链接。它们一点就开。没有什么会去审查它们。
- **其余的一律关着，直到被读过。** 往 `rness/skills/` 丢一个技能文件夹——下载的、朋友发的、从一个 `.skill` 里解压出来的——它会禁用着待在那里，在侧栏里标着*未验证*。你第一次把它打开时，enough 会先对它跑一遍 analyzer 的审查模式（第 16.1 节），一个字都不会先到智能体那里。你能在那一行上看着它发生：*未验证* → *审查中…* → *已审查*。
- **被标记就等于没启用。** 如果审查发现了什么，那一行会写*已标记*（或*未通过*），技能保持关着，同时给你两个按钮：**读报告**在阅读视图里打开完整报告，**仍然启用**请你确认，然后把这个决定记成你的——那条发现不会被抹掉，它是被你否决了，而那一行从此写着*你信任的*。审查提供建议。决定的是你。（如果你更愿意在文件里动手，把那个技能的 `verdict.json` 改成 `"verdict": "pass"` 是同一件事。）
- **改了技能，它就会被重新读一遍。** 审查绑定在它读过的那些确切字节上——文件名和内容都算。改动任何东西，你下次打开这个技能时，它都会被再审一次。这也包括你之前「仍然启用」过的那一个：一次否决描述的是某一刻的某一组文件，它挺不过一次编辑。
- **你的智能体给你写的技能同样算不可信。** 这是有意的，不是疏忽。当 workflow-design 往 `rness/skills/` 里写下一个新的 `SKILL.md`，智能体会在首次启用时审查自己的作业。没什么可发现的时候，这几乎是瞬间的事。
- **没有模型在跑时，审查完不成**——而它会明说，以「审查里 llm 的那一半没能跑起来」标记出来，而不是挥挥手把技能放过去。开一个模型再切一次，或者，如果你本来就知道里面是什么，用*仍然启用*。

报告住在 `rness/io/output/analyzer/audits/<skill-name>/`——和你在对话里要一份审查时 analyzer 写进去的是同一个文件夹。两扇门，一份文档，而且它就是一个普通的 markdown 文件，你可以打开、留着，或者删掉。

## 17. girraph 模式与 `.girraph` 扩展名

它读作「graph」。中间的 *ir* 不发音——它代表 *iterative*（迭代）和 *recursive*（递归）。那只动物是 🦒，而那只动物也不出声。

girraph 是一张关于一个难题的地图。不是待办清单：是一幅关于*分歧*的画，包括你和你自己那些有产出的分歧。有些问题（「我们要不要在家上学？」「这本书到底在讲什么？」「这笔钱我们接不接？」）会从每个答案里长出一个反对，又在每个反对底下长出一个新问题。清单把这场争论埋了。girraph 让它一直看得见：

- ❓ **议题** —— 开放的问题，永远写成问句
- 💡 **立场** —— 可能的答案
- ➕ ➖ **论据** —— 支持或反对某个立场的理由
- 📄 **备注** —— 背景、约束、对文档的引用
- 🦒 **嵌套的 girraph** —— 一个大到该有自己一张图的子问题

它的血统是 IBIS，一种 1970 年代为「棘手问题」发明的方法——那种没有干净答案、也没有天然终点的问题。girraph 是 enough 对它的纯文本演绎。

格式是一个以 `.girraph` 结尾的文本文件，一行一个念头，在 2026 年或 2056 年的任何编辑器里都读得出来：

```
%girraph 0.1
title: Should enough ship a plugin API?

q1 ? Should enough ship a plugin API?
p1 ! Ship a minimal one < q1
a1 + Ecosystem growth needs stable hooks < p1 by:graham
a2 - API surface = forever maintenance < p1 by:open-skeptic
```

`< q1` 的意思是「这个回答 q1」；`by:` 记着这是谁的主张。没有数据库，没有藏起来的东西。文件就是地图。

在应用里，点一个 `.girraph` 会打开 girraph 模式：一棵可折叠的树，你直接在上面编辑。点一个标签就改写它。把鼠标停在一行上，出现添加、连接和删除的按钮。点一个 🦒 小片进入嵌套的地图——面包屑带你回来——点一个 📄 小片就地读被引用的文档。在对话里，说一句「girraph 一下」或者「把这个理一理」，智能体就通过你用的那同一套节点级操作去改同一个文件，所以你们俩可以同时在这张图上干活。删除节点永远需要你的确认，而且子节点绝不会被悄悄丢下。

girraph 还能长出一面 **merirmaid 镜子**：在 girraph 工具栏上点一下 merirmaid 按钮，就会创建一张关联的、自动重生成的 Mermaid 图——议题是六边形，立场是圆角条，支持和反对各按自己的颜色描边——它会随 girraph 的变化一直保持最新。在 girraph 里制图，在 merirmaid 里一眼看清。

有三个习惯让 girraph 真正管用。把议题写成问句（「第二年的钱从哪儿来？」，而不是「钱的问题」）。把论据挂在立场上，而不是议题上——理由是支持或反对某个*答案*的理由。以及，在一个分支蔓延开来之前，把它拆进自己的文件。启用 girraph-merirmaid 技能，智能体会盯着你把这三条都做到。

## 18. merirmaid 模式与 `.merirmaid` 扩展名

girraph 画的是一场论证，**merirmaid** 描的是一个结构。一个 `.merirmaid` 文件就是一张 [Mermaid](https://mermaid.js.org/) 图——流程图、时序图、状态机、ER 图，Mermaid 画得出来的都行——带一小段 frontmatter 头部，在浏览器里实时渲染。当然是本地渲染；和 enough 里的一切一样，不走 CDN。

两种形态，在头部声明：

- **wip** —— 一块干活的白板。点任意节点的文字就地改标签，带实时字数；结构性的改动（加一个框、改一根箭头的走向）通过对话小药丸交给智能体。让它画你的流水线、你的情节、你的组织架构，智能体写源码，浏览器画出来，你来调那些字。
- **mirror** —— 对住在别处的某个结构的只读映照：一个 cachebox 的内容（第 11.1 节），或者一个 girraph（第 17 节）。源头一变，镜子就重新生成。想改这幅画，就去改那个东西。

图之间可以链接。一个节点可以指向另一个 `.merirmaid`、一个 `.girraph`，或者一份 markdown 文档，点它就跳过去，面包屑标着回来的路——于是一组图就成了你项目的一本可以走动的图集。而当一张图有语法错误时，merirmaid 模式会显示错误加上原始源码，而不是一片空白。总还有个东西可以让你着手去修。

girraph-merirmaid 技能（第 16.3 节）带着这两种文件的写作纪律。其中有一条经验值得在这里重复一遍：如果诚实的第一步是问一个问题，那你要的是 girraph；如果是画一个框和一根箭头，那你要的是 merirmaid。

## 19. 接下来往哪儿走

让 enough 变成你的，最快的路：

1. 在一个真实的项目里启动它——一件你真的在乎的事。
2. 花一次会话聊聊天，让项目档案开始攒起来。
3. 改 `MOTIVATION.md`，说清这个项目究竟是为了什么。
4. 你第一次重复一条指令的时候，停下。把它写进 `AGENT.md` 里。
5. 你的工作第一次长出默认设置装不下的形状时，说一句「我们来为这件事设计一个范式吧」——或者一个技能，或者一个角色——让 workflow-design 带你走一遍。

那个循环——察觉摩擦、把解法固定下来、接着干活——就是全部的游戏。内置的东西让你起步。而你最后得到的那套系统，没有人发布过。是你写的。
