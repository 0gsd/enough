# UI languages — how translations work and how to update them

enough's chrome and help content ship in six languages: **English**
(the source) plus **French, Spanish, German, Chinese (simplified), and
Japanese**. This doc is the durable record of how the machinery works
and — the part you'll actually come back for — the exact process for
keeping the five translations in lockstep when the English changes.

The scope is deliberate: **UI labels, tooltips, the `(?)` help bubbles,
and the help-center manual. Nothing else.** Project files, prompts,
skills, paradigms, AGENT.md, file names, and everything the agent reads
or writes stay English — local models work best with English scaffolding,
and your conversation with the agent is yours in whatever language you
two choose. The language setting is global (machine-wide, in
`~/enough/config/ui.json` as `ui_language`), unlike the per-project
display scales next to it in the UI.

## Where everything lives

    enough/static/i18n/
      en/ui.json          ← canonical string catalog (keys + English)
      fr|es|de|zh|ja/
        ui.json           ← translated chrome strings (same key set)
        help-docs.md      ← translated (?) bubbles (same ## id skeleton)
        help-center.md    ← translated manual (same heading skeleton)
        intro.md          ← optional: the chat's brief introduction (0.4.1)

English sources stay where they always were — chrome strings inline in
`enough/static/index.html`, bubbles in `enough/static/help-docs.md`,
the manual in `docs/HELP_CENTER.md`, the brief introduction in
`defaults/intro.md`. The i18n tree holds only the non-English mirrors plus
the `en` catalog, so translations never sit beside the English content
they mirror. `intro.md` is the one optional file: `enough/intro.py` serves
a language's copy when it exists and the English otherwise, and
`i18n_check.py` does not look for it — translate it as a whole short text
(keep its bold lead-ins), not line by line.

**The manual's numbering is load-bearing (0.4.1).** The help center turns
"section 7.3" into a link and gives every heading an id from its number,
the same in all six languages. So when the English manual gains, loses or
renumbers a section, every translated `help-center.md` must make the same
moves — headings *and* every "section N" reference in the prose — not just
translate the new text. `i18n_check.py` catches a changed heading count;
`tests/test_content_integrity.py` checks each file's numbering is
contiguous. **And its shape (0.4.4).** The docs viewer reads each manual as
a DocOES telling whose items take their ids from the English: sections by
number, defined terms by their place in the section. So mirror the English
markdown's shape as well as its words — a term-shaped bullet (`- **word** —
…`) stays term-shaped, a bold label with a period stays a label, a bold
word followed by a comma or a verb stays that — or the term falls back to
English ("told in English"). `python -m enough.docoes lint help-center
--lang <xx>`, run with `ENOUGH_DOCS_ROOT` pointed at a scratch dir, shows it.
A bold label with a stop may run straight into a bold button
(`**Leerlo.** **abrir el fabulac** …`): since 0.7 that paragraph defines
nothing, in any language, as its English doesn't.
**Another document's section (0.7).** Where the English cites a section of
a specification — "Thym's specification, in its section 4" — write the
language's word for *its* right before the section word, and the section
linkers (DocOES's core, the exporter and the docs viewer) leave it as plain
words instead of linking this manual's own section 4: de *ihrem Abschnitt
4* (any form of *ihr* or *sein*, or *dessen*, *deren*), fr *sa section 4*,
*ses sections* (or *leur*, *leurs*), es *su sección 4*, *sus secciones*,
ja *その* or *仕様書の* / *仕様の* before *セクション 4*, zh *它的*, *其*
or *规范* / *规范的* before *第 4 节*. Every other "section 4" links. The
list is `OTHER_DOC_WORDS` in `enough/docoes.py`.
In the docs viewer *fabula* is also the name of a density, with *short*
and *atem*: the three button words stay as written in every language.

## How it works at runtime (index.html, "i18n round" comments)

- Markup carries `data-i18n` (textContent), `data-i18n-title`,
  `data-i18n-placeholder`, `data-i18n-aria` attributes with dot-keys
  (`prefs.uiLanguage`, `topbar.files.title`, …). The inline English is
  the permanent fallback: `en` needs no catalog, and a missing key in
  any language silently shows English.
- Strings built in JS go through `t('key', 'english fallback')`.
- `applyI18n()` walks the four attributes, memoizing each element's
  English original into `data-i18n-src*` so switching languages
  round-trips without a reload. It also sets `<html lang>`.
- The boot language rides `BOOT_UI_STATE` (server-templated) and the
  catalog is prefetched from `<head>`; the bubbles loader and
  `GET /api/help-center?lang=` pick the translated files with automatic
  English fallback. The server whitelists codes (`UI_LANGUAGES` in
  `server.py`) — an unknown code is dropped, never used as a path.

## The update process (run this whenever English changes)

1. **Change the English source** — inline string in index.html (update
   `static/i18n/en/ui.json` to match, byte-identical), or
   `static/help-docs.md`, or `docs/HELP_CENTER.md`. New markup strings
   get a `data-i18n*` key; new JS strings get `t()`.
2. **Run the checker:**

       uv run python scripts/i18n_check.py

   It diffs every language against the English structure and prints
   exactly what's missing or stale, per language, per file — that
   output is the whole to-do list. (`tests/test_i18n.py` runs the same
   check, so CI fails until the list is empty.)
3. **Regenerate what it lists.** Two supported routes:
   - **An agent (the way the originals were made).** Give a capable
     model the English file (or just the changed sections), the
     corresponding translated file, and the translation contract below.
     Ask for minimal edits to the translated file that bring it back in
     lockstep — not a wholesale re-translation.
   - **MADLAD-400, offline** (the translator skill's engine,
     `~/.local/share/translator/madlad400-3b-ct2/`). Fine for short
     catalog strings; for markdown files translate paragraph-by-
     paragraph and reassemble around the untouched structure — MADLAD
     translates meaning, not markdown, so never feed it headings,
     tokens, code fences, or inline HTML.
4. **Re-run the checker** until it exits 0, then run the suite.
5. **Before every commit**, run `uv run python scripts/precommit.py
   --quick`. It includes `i18n_check.py`, but it also runs
   `tests/test_content_integrity.py`, which enforces the parts this
   document asserts and the checker cannot see: that every `en/ui.json`
   value is byte-identical to the inline English in index.html, that a
   key reused at several sites carries the same English at all of them,
   that `{placeholders}` and inline HTML survive into all five
   translations, and that a translated value byte-equal to its English is
   deliberate. See "Pre-commit suite" in docs/AGENT_GUIDE.md.

## The translation contract (give this to whoever translates)

- Preserve ALL structure byte-for-byte: heading lines' `#` depth and
  count, `## <id>` section ids in help-docs.md (ids are keys, never
  translated), `name:`/`path:` line keys (translate the `name:` VALUE,
  never the `path:` value), `{{tokens}}` (e.g. `{{skills-list}}`,
  `{{convert-formats}}` — leave exactly as written, they expand at
  runtime), fenced code blocks (content untranslated), inline HTML
  tags and `<kbd>` key names, markdown links' URL halves.
- ui.json: translate values only; keys are identical to `en/ui.json`;
  `_meta.language` matches the folder.
- Keep the voice (internally nicknamed "Rosa"): warm, plain, unhurried,
  wry; lowercase headings stay lowercase where English lowercases.
  Translate the register, not just the words. The manual's opening
  paragraph is Graham's own and says so — keep that first-person frame
  intact in translation.
- Keyboard keys (⌘, esc, shift), product names (enough, wikisink,
  canon — cacheawl before 0.4.3 — merirmaid, girraph, cosm, MacroCOSM, Thym, Ascribe,
  fabula, atem, FEED, MADLAD, OpenRouter), skill/role/paradigm names, and
  file paths stay as-is. Modes keep their English proper names with a
  translated gloss on first mention where the English manual glosses
  them. The ordinary words around them are translated, and the 0.4.3
  catalogs have settled these, so keep them consistent: *volume* (de
  Band, fr volume, es volumen, ja 巻, zh 卷), *twin* (de Zwilling, fr
  jumeau, es gemelo, ja 双子, zh 孪生), *decompile* (de dekompilieren,
  fr décompiler, es descompilar, ja 逆コンパイル, zh 反编译). Japanese
  keeps two words on purpose: ツイン for a converted document's markdown
  twin (the convert strings and manual §7 always used it) and 双子 for a
  text's fabula twin, so "twins, plural" (§7.1) reads as two kinds.
  **short** (0.4.3, SHORT) is a product word, like fabula and atem: keep it
  as *short* in every language — lowercase in running copy (German
  capitalises it, as it does every noun), SHORT for the acronym, whose
  expansion (*syuzhetic-hermeneutic open readable text*) is never
  translated; the Canon/tree tag stays *short* everywhere — and give it
  the gender the language would: de *der Short* (pl. *die Shorts*), fr
  *le short* (yes, also the garment; the manual winks at it once), es
  *el short*; ja and zh write *short* in Latin letters, as they do atem. Its two orders are translated: *as the
  author told it* / *by weight* (de wie der Autor es erzählt hat / nach
  Gewicht, fr comme l'auteur l'a raconté / par poids, es como lo contó el
  autor / por peso, ja 作者が語った順に / 重みの順に, zh 按作者讲述的顺序 /
  按分量). **entailment** (0.7, the owner's ruling of 2026-11-12) is the
  step that expands meaning by reducing data, and what it makes: the whole
  entails what is made from it (MacroCOSM OES 18.1) — a text its fabula, a
  fabula a short, a short its atem, a fabulac a cshort or a catem. It
  replaced *telling* as the word for a short or a reading; *telling* now
  means only the one language a document is written in (DocOES's
  `telling`), and the order *as the author told it* keeps its verb, since it
  names the author's own act. It is translated in the logic sense, where the
  whole entails the part, by a word a reader who is not a logician reads
  naturally: de *die Folgerung*, with *folgen aus* for the verb ("aus der
  Fabula folgt ein Short": the logicians' own word, and in everyday German a
  conclusion drawn from something; not *Ableitung*, too near to deriving, nor
  *Implikation*, which reads as a side effect); fr *l'implication*, verb
  *impliquer* ("la fabula implique un short": everyday French for *entail*
  and the logicians' word; *conséquence* leans toward cause and effect); es
  *la implicación*, verb *implicar* (the same reasons; *entrañar* is the
  closest verb, but has no noun in use); ja 含意, verb 含意する (the
  logicians' term, which anyone reads as "meaning held within", 含む plus 意:
  the whole holds the part; not 帰結, an outcome, nor 導出, which says
  derive); zh 蕴含 (everyday "to hold within, to imply", the logicians' 蕴涵
  in its everyday characters; not 推导, which says derive, nor 推论, a
  reasoner's inference). The words the translations had used for a telling
  (de Erzählung, fr récit, es relato, ja 語り, zh 讲述) are retired in this
  sense; a reading *said again* through a morph takes each language's plain
  words for saying again (de neu fassen, fr redire, es decir de nuevo, ja
  言い直す, zh 重新说一遍), and a cshort's source is *rebuilt* (de neu gebaut,
  fr reconstruite, es reconstruido, ja 組み立て直した, zh 重新搭建). *One
  fabula, many entailments*: de *Eine Fabula, viele Folgerungen*, fr *Une
  fabula, de nombreuses implications*, es *Una fabula, muchas
  implicaciones*, ja ひとつの fabula に、たくさんの含意, zh 一个 fabula，多种蕴含.
  The Thym move is `entail`, code, in every language; `tell`, its earlier
  spelling, is mentioned only as that.
  **fabula** (0.6, the fabula round, pins P0) is the word for
  what a decompile makes; it replaced *EMF*, which the UI strings and the
  bubbles no longer say (the old spelling `emf/1` lives on only as data).
  It stays *fabula* in every language — de *die Fabula*, fr and es *la
  fabula*, ja and zh in Latin letters — and a text's fabula file is still
  its *twin* (de *Zwilling*, fr *jumeau*, es *gemelo*, ja 双子, zh 孪生文件).
  Its flavours are product words written as-is (*fabulan*, *fabulap*,
  *fabulac*), shown beside the translated plain words *prose* / *verse*;
  *cshort* and *catem* (a fabulac's short and its atem at a depth) are
  product words like short and atem, lowercase everywhere; the depth names
  `line`, `overview`, `manual` are data and stay English. The manual may
  still gloss *fabula* as the Formalists' own term (§12.4 and §13.3), ja
  with ファーブラ in brackets. *Syuzhet* takes each language's narratology term
  with the Russian one in brackets (de *Sujet*, fr *sujet*, es *siuzhet*,
  ja シュジェート, zh 情节). Three densities of one meaning, said in that
  order wherever they are listed: fabula · short (SHORT) · atem.
  **The dialectic** (0.6, U1b) is ordinary words, translated and kept
  consistent: a *question* (de Frage, fr question, es pregunta, ja 質問, zh
  问题); a *session*, the answers a person sends together (de Sitzung, fr
  session, es sesión, ja セッション, zh 会话; "sitting" until 0.7, renamed so
  the screen says what the record's `D:session` says); to *settle* the answers
  into the volume
  (de einarbeiten, fr intégrer, es incorporar, ja 反映する, zh 并入); the
  *holder* of a holograph (de Inhaber, fr titulaire, es titular, ja 持ち主, zh
  持有者). **holograph** and **isograph** are Ascribe's product words, kept as
  they are, lowercase, in every language (ja and zh in Latin letters); the
  answer kinds' values (`stated`, a state word the server sends such as
  `answered`) are data. Name people "by what they are to you", never "by
  role": `role` is the retired word for a readvisor (tests/test_vocabulary.py).
  **The allograph and its registry** (0.7, P4; Ascribe 14.6 to 14.13):
  **allograph**, **faceplace** and **dangler** are Ascribe's words, kept as
  they are, lowercase, in every language like holograph (ja and zh in Latin
  letters); **Allograph+** and the **Allograph Registry** are names, and so
  is **Connect** (Comprise Connect), all as written. The ordinary words
  around them, translated and kept consistent: a *listing* and to *list* (de
  Eintrag / eintragen, fr inscription / inscrire, es inscripción /
  inscribir, ja 掲載 / 掲載する, zh 登记); a *tag* (de Tag, fr étiquette, es
  etiqueta, ja タグ, zh 标签); to *withdraw* (de zurückziehen, fr retirer, es
  retirar, ja 取り下げる, zh 撤回); a *claim* (de Angabe, fr affirmation, es
  afirmación, ja 申告, zh 声明); *stated* and *attested*, the two levels (de
  angegeben / bezeugt, fr déclaré / attesté, es declarado / atestiguado, ja
  自己申告 / 証言あり, zh 自述 / 有人作证); to *attest* and an *attestation* (de
  bezeugen / Bezeugung, fr attester / attestation, es atestiguar /
  atestación, ja 証言する / 証言, zh 作证 / 证言 — zh keeps 证明 for a
  faceplace *proof*, so the two never read alike); a *proof* and the *proof
  string* (de Nachweis / Nachweistext, fr preuve / texte de preuve, es
  prueba / texto de prueba, ja 証明 / 証明の文字列, zh 证明 / 证明字符串); a
  *handle* (de Handle, fr identifiant, es usuario, ja ハンドル, zh 用户名); to
  *answer for* an agent, a bond (de für ihn einstehen, fr en répondre, es
  responder por él, ja 責任を持つ, zh 为它负责); an *owner* (de Eigentümer, fr
  propriétaire, es propietario, ja オーナー, zh 所有者); a *character* (de
  Figur, fr personnage, es personaje, ja キャラクター, zh 人物 — not 角色, the retired word for a readvisor); to *sign in*
  and a *passkey* (de anmelden / Passkey, fr se connecter / clé d'accès, es
  iniciar sesión / llave de acceso, ja サインイン / パスキー, zh 登录 / 通行密钥).
  The values a registry entry sends (`person`, `agent`, `client`, a strength
  band, a decade) are data.
  **Writing and running Thym** (0.6, U1c): the language's own words are code
  and stay as written in every language — `thym 0`, `thym 1`, `for each`,
  `keeps`, `depth`, `as`, `with`, `to`, a move's or a check's name, a
  program's name such as `settle-the-answers`, and the keys `F8` /
  `shift+F8`. The ordinary words around them follow the 0.5.0 catalogs: a
  *move* (de Handgriff, fr mouvement, es movimiento, ja ムーブ, zh 动作), a
  *run* (de Lauf, fr exécution, es ejecución, ja 実行, zh 运行), a *trace* (de
  Spur, fr trace, es traza, ja トレース, zh 轨迹). What the compiler, a plan or
  a run says (a refusal's words, a move's `says` line, a signature) is the
  server's and English, shown as it comes.
  **Holotype** is a brand word (Comprise's rule: it stays on screen as
  is) — never translate it; the manual may gloss it once in a section
  (es *holotipo*, zh 正模, de Holotypus) where a reader needs the idea.
- Lists generated from installed items (`{{skills-list}}` output,
  convert-formats table content) render in English by design — the
  data comes from English frontmatter on the user's machine.

## Adding a whole new language

1. Add the code to `UI_LANGUAGES` in `enough/server.py` AND to the
   `UI_LANGUAGES` map in index.html (native-name label) AND to `LANGS`
   in `scripts/i18n_check.py`.
2. Create `enough/static/i18n/<code>/` with the three files (start
   from the English sources + the contract above).
3. `uv run python scripts/i18n_check.py` → fix until clean.
4. Mention it in `docs/HELP_CENTER.md` §10.4 and in
   `defaults/ui-config.json`'s `_doc`.

## What deliberately does NOT translate

Chat content, readvisor replies, project files, skills/readvisors/paradigms
(names and bodies), AGENT.md/MOTIVATION.md, policies, the broker's
journal entries, log lines, error strings from the backend, dynamic
data (model names, file names, dates), and the generated portions of
help content noted above. Two 0.4.3 additions: the MacroCOSM
specification (`docs/MACROCOSM_OES.md`) is English only for now — the
docs viewer says so in the other five languages, and
`GET /api/macrocosm-spec?lang=` already whitelists `lang`, so a
`static/i18n/<lang>/MACROCOSM_OES.md` would be served first if one ever
ships; a short's footer line (*a short of notes.md, told as the author
told it, …*) and its "Also in the fabula" heading are written by the
engine in English, like everything a compile writes; and what a `.cosm` file says is data — stance words, salience
values, field names, lens names and check ids appear in the cosm viewer
as the file spells them, while the labels and tooltips around them are
translated. Thym (0.5.0) adds its own: a trace's title line (*ran publish-story on notes.md in 189 s …*), a
reading's footer (*a reading of notes.md through plain-letter, made here on …; the text stands unchanged*) and
its `read_through:` front matter, the one-line cost a plan prints, and the ten scales' word lists, which read
English (docs/THYM.md 13.3) and are the reference's, not the page's; the Thym specification (`docs/THYM.md`,
`GET /api/thym-spec`) is English only like the MacroCOSM one, and so are Ascribe's (`docs/ASCRIBE.md`) and, since
0.5.4, Comprise OES's (`docs/COMPRISE_OES.md`); all four open in the docs viewer, which says so in the other five
languages. The four are the canonical editions published at cosmoes.org, synced byte for byte: never translated, never
edited here. If you're tempted to translate any of these,
re-read the second paragraph of this file first.
