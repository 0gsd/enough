# cacheawl — backend plan & API contract (v1)

> Companion to [merirmaid-plan.md](merirmaid-plan.md) and
> [AGENT_GUIDE.md](AGENT_GUIDE.md). This file was the **contract the UI wave
> built against**. As of 0.1.6 both halves have shipped: the backend
> (`enough/cacheawl.py`, the `/api/cacheawl/*` endpoints, the three agent
> tools, the infoworld migration) *and* the split-view cachebox mode in
> `static/index.html`. It remains the reference for what the backend gives
> the UI and the interaction semantics the mode implements.

## Concepts

- **The store** is `~/enough/cacheawl/` (overridable via
  `ENOUGH_CACHEAWL_ROOT` for tests). It is machine-global, not per-project,
  and is **hidden from every project's file tree** the same way wikisink
  dirs are.
- A **cachebox** is a ROOT-LEVEL folder in the store. Only direct children
  of `cacheawl/` are cacheboxes; folders nested deeper are plain folders.
- Each cachebox carries two backend-owned sidecars:
  - `.cachebox.json` — hidden metadata (origin, status, timestamps, a cheap
    tree fingerprint). Never shown in listings/trees.
  - `_cachebox.merirmaid` — an auto-generated `modality: mirror` diagram of
    the box (see the "cachebox mirror contract" in merirmaid-plan.md).
    Regenerated by the backend on every mutation. **Read-only**: both the
    agent's `write_file` and `POST /api/file` refuse to modify it (403 /
    tool error) with a message telling the caller to change the cachebox
    contents instead.
- Some cacheboxes are plain folders; others are **cached replicas** ingested
  from a source (`path` / `url` / `wikisink`) recorded in `origin`.

## Data shapes

### Cachebox summary (listing row)

```jsonc
{
  "name": "rust-book",
  "origin": { "type": "url", "value": "https://doc.rust-lang.org/book/", "depth": 2 },
  "status": "complete",              // complete | ingesting | failed
  "created_at": "2026-07-13T21:40:00Z",
  "updated_at": "2026-07-13T21:44:10Z",
  "item_count": 42,                   // content files (excludes sidecars)
  "dir_count": 6,
  "total_size": 356123,
  "total_size_human": "347.8 KB",
  "ingest": {                          // null for a plain box; progress otherwise
    "phase": "complete",              // queued|starting|copying|crawling|expanding|capped|complete|failed
    "files_written": 42,
    "started_at": "…", "finished_at": "…",
    "error": null
  }
}
```

`origin.type` is one of `folder` (plain/empty box), `path`, `url`,
`wikisink`, or `infoworld-migration`. `origin.depth` is an int `1`–`3`, the
string `"all"`, or `null`.

### Tree node (icon grid)

`cachebox_tree` / the `/api/cacheawl/tree` payload nests these. **Folders are
listed before files, each group alphabetical** — render that order.

```jsonc
{ "name": "chapter1.md", "path": "book/chapter1.md", "is_dir": false,
  "size": 8123, "is_mirror": false }
```

- `path` is relative to the cachebox root. Use it as the stable id / the
  `path` you send back in transfer requests.
- `is_mirror: true` marks the `_cachebox.merirmaid` file — the UI should
  route a click on it to the **merirmaid viewer** (read-only mirror), not
  the text editor.
- Directory nodes carry `children: [...]` instead of `size`.

## Endpoints

All under `/api/cacheawl`. Bodies are JSON (except `POST /api/file`, which
stays form-encoded as today). Errors return the usual FastAPI
`{"detail": "..."}` with the status codes noted.

### `GET /api/cacheawl/tree`

The split-view payload: the project tree **and** every cachebox tree in one
call. Triggers a cheap **reconcile** on every box first (fingerprint check —
regenerates a stale mirror so manual file drops the backend didn't perform
are reflected).

```jsonc
{
  "root": "/Users/you/enough/cacheawl",
  "project": [ /* project file-tree nodes: name, path, is_dir, is_symlink, children */ ],
  "cacheboxes": [ { ...summary..., "tree": [ /* tree nodes */ ] }, ... ]
}
```

### `POST /api/cacheawl/create`  → summary
Body `{ "name": "..." }`. Names: letters/digits/spaces/hyphens/underscores,
must not start with a symbol, ≤64 chars. `400` on a bad or duplicate name.

### `POST /api/cacheawl/rename`  → summary
Body `{ "name": "...", "new_name": "..." }`. `400` if the target exists.

### `POST /api/cacheawl/delete`  → `{ "deleted": "name" }`
Body `{ "name": "...", "confirm": true }`. **`confirm` must be `true`** — an
unconfirmed delete returns `400` with a message to confirm; deletion is
permanent (whole folder). `404` if the box doesn't exist. The UI should
gate this behind an explicit confirm dialog.

### `POST /api/cacheawl/transfer`  → result
Copy or move a file/folder between the project dir and a cachebox (either
direction) or within/between cacheboxes.

```jsonc
{
  "op": "copy",                        // "copy" | "move"
  "src": { "root": "project", "path": "notes/a.md" },
  "dst": { "root": "cachebox", "box": "research", "path": "a.md" },
  "overwrite": false                    // optional; default false = never clobber
}
```

- Each endpoint side is `{ "root": "project" | "cachebox", "box": <name if
  cachebox>, "path": <relative path> }`.
- If `dst.path` names an existing **directory**, the source is placed inside
  it under its own name.
- Path-traversal is rejected on both sides (`..`, or a resolved path that
  escapes its root → `400`). The backend-owned sidecars (`.cachebox.json`,
  `_cachebox.merirmaid`) cannot be a transfer source or destination.
- Refuses to clobber unless `overwrite: true`.
- Mirrors are regenerated for every cachebox the op touched;
  `result.boxes_updated` lists them. Re-fetch `tree` after.

### `POST /api/cacheawl/ingest`  → `{ box, status:"ingesting", origin }`
Body `{ "box", "type", "value", "depth"?, "all"? }`.

- `type`: `"path"` | `"url"` | `"wikisink"`; `value`: the source string.
- `depth`: int `1`–`3` (default `1`); or `"all": true`. **`all` is invalid
  for `wikisink`** (`400`).
- The box is **registered synchronously** with `status: "ingesting"` before
  the response returns (so `ingest-status` is immediately pollable); the
  actual work runs in the background. Malformed requests / an
  already-populated box → `400` up front.
- Ingest into a **fresh box name** (or a previously-failed/empty box). A box
  that is already `complete` and populated is rejected.

Ingest semantics (also enforced by the agent tool):
- `path` — copies text files (binaries skipped by extension + null-byte
  sniff) mirroring the source tree to `depth` folder levels (`depth 1` =
  top-level files only; `all` = unlimited). Never follows symlinks out of
  the source root.
- `url` — same-origin crawl to `depth` link layers (`all` =
  starting-subdirectory-scoped, hard cap ~500 pages), each page converted to
  markdown via the shared fetch_url plumbing (allowlist/Tor gating applies;
  robots.txt disallow respected). Files mirror the URL path.
- `wikisink` — fuzzy-matches an article, saves it as a wikisink folder in the
  box, then expands crosslinks `depth` layers (cap ~200 articles). Requires
  an installed archive.

### `GET /api/cacheawl/ingest-status?box=NAME`  → status
```jsonc
{ "name": "rust-book", "status": "ingesting", "origin": {...},
  "ingest": { "phase": "crawling", "files_written": 12, "pages_seen": 15 },
  "updated_at": "…" }
```
Poll while `status == "ingesting"`. `404` if the box doesn't exist. On
failure the box ends `status: "failed"` with `ingest.error` set (a clean,
resumable-or-failed state — never a phantom "complete" box).

## Interaction semantics the UI is expected to implement

The backend deals in files; the split-view UI drives it. The intended
mouse/keyboard model for the icon grid (both panes — project tree and
cachebox contents):

- **Single click = select.** Highlights the item; no side effect. Selection
  is what a subsequent transfer/delete acts on. Multi-select (cmd/shift) is
  optional for v1 but the transfer API is single-item, so batch = N calls.
- **Double click = open.** A folder opens (descend); a file opens in its
  natural viewer — text files in the read/edit mode, a `.girraph` in
  girraph mode, a `_cachebox.merirmaid` (or any `.merirmaid`) in the
  merirmaid viewer, a saved wiki `article.html` in the wikisink reader.
  Launching a store file into any of these modes goes through the
  **`cacheawl:<box>/<rel>` virtual path scheme** (see below), since store
  files live outside the project root and the existing file endpoints are
  project-relative.
- **Shift click = context menu.** The per-item action menu:
  transfer (copy/move to the other pane or another box), rename-not-offered
  for files (transfer covers it), delete. Box-level actions (rename box,
  delete box, start ingest) live on the box header, not per-file.
- **Drag between panes** (optional, nice-to-have) maps to `transfer` with
  `op` = move (or copy with a modifier).

Fields the UI needs from the backend, by view:
- **Box list / headers:** `name`, `status`, `origin`, `item_count`,
  `total_size_human`, `updated_at`. Show a spinner/progress when
  `status == "ingesting"` (poll `ingest-status`); show a retry affordance
  when `status == "failed"` (`ingest.error`).
- **Icon grid:** the `tree` nodes — `name`, `path`, `is_dir`, `size`,
  `is_mirror`, `children`. Route `is_mirror`/`.merirmaid` → merirmaid
  viewer; a folder named entry containing a saved wiki article
  (`article.html` + `.meta.json`) → wikisink reader.
- **Transfer targets:** the `{root, box, path}` triple for each side.

## Launching store files into the modes: the `cacheawl:` path scheme

Cacheboxes live under `~/enough/cacheawl/` — outside any project root — but
the read/edit, girraph, and merirmaid modes all address content through the
project-relative file endpoints (`GET /api/file{,/raw}`, `POST /api/file`).
Rather than add global-path variants of each endpoint, `server.py`'s
`_resolve_project_path` accepts a **virtual path prefix**:

```
cacheawl:<box>/<relative-path-inside-the-box>
```

When a path starts with `cacheawl:`, the helper resolves the remainder
against `cacheawl.root()` instead of the project directory. That single
addition is what lets cacheawl mode open a store file in every mode without
new endpoints — the UI sends `cacheawl:rust-book/chapter1.md` (or a
`.girraph` / `.merirmaid` under a box) and the ordinary read/edit, girraph,
and merirmaid plumbing just works.

Contract:

- **Traversal is rejected.** The remainder is refused if it is absolute,
  contains a `..` component, or is empty → `400`. It never escapes the store
  root (same `/var` vs `/private/var` resolve discipline as the rest of the
  store).
- **Sidecar write-guards still apply.** The resolved target flows into the
  same downstream checks: `POST /api/file` (and the agent's `write_file`)
  refuse a `modality: mirror` file → `403`, and refuse `.cachebox.json` →
  `403`. The scheme grants launch access, not a bypass of the backend-owned
  sidecars.
- **In-tree paths never reach the store.** The prefix is the *only* way a
  project-relative request addresses cacheawl; a plain relative path can't
  traverse into `~/enough/cacheawl/`.

There is no separate "global-path read endpoint" and no read-only fallback
card — the scheme is the whole contract for cross-mode launching.

## What v1 deliberately left to the UI wave (now shipped)

- The split-view cachebox pane itself (HTML/CSS/JS in `static/index.html`)
  and its icon grid, drag/drop, context menus, and the box-header controls.
- The merirmaid **viewer** (rendering `_cachebox.merirmaid` to SVG) — the
  backend only produces the plain-text mirror per the pinned merirmaid
  format; rendering is the frontend's job (vendored `mermaid.min.js`).
- Any progress SSE stream for ingests — v1 uses **poll**
  `GET /api/cacheawl/ingest-status`; a future `wiki_sink`-style SSE event
  could layer on without changing the status shape.
- Multi-select batch transfer UX (backend transfer is single-item).
